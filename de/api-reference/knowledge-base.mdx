## Wissensdatenbank-Endpunkte

Verwalten Sie Wissensdatenbank-Dateien in zwei Ebenen: als zentrale Bibliothek auf Kontoebene unter ` /api/kb/* ` und als Zuordnungen pro Assistent unter ` /api/assistants/{assistantId}/knowledge-base `.

<Callout kind="info">

Alle Wissensdatenbank-Endpunkte akzeptieren entweder eine authentifizierte Browser-Sitzung oder einen API-Schlüssel.

API-Schlüssel benötigen für Lesezugriffe auf `GET`-Endpunkte den Scope `kb:read` und für schreibende Anfragen auf `POST`- oder `DELETE`-Endpunkte den Scope `kb:write`.

</Callout>

<Callout kind="alert">

Uploads verwenden `multipart/form-data`. Neu hochgeladene Dateien werden asynchron verarbeitet und können zunächst den Status `pending` oder `processing` zurückgeben, bevor sie für Suche und Retrieval bereit sind.

</Callout>

## Endpunktübersicht

| Methode | Pfad | Zweck | Auth |
| --- | --- | --- | --- |
| `GET` | `/api/kb/files` | Konten-KB-Dateien auflisten | Sitzung oder API-Key `kb:read` |
| `POST` | `/api/kb/files` | Neue KB-Datei hochladen | Sitzung oder API-Key `kb:write` |
| `GET` | `/api/kb/files/{fileId}` | Metadaten einer Datei abrufen | Sitzung oder API-Key `kb:read` |
| `DELETE` | `/api/kb/files/{fileId}` | KB-Datei dauerhaft löschen | Sitzung oder API-Key `kb:write` |
| `GET` | `/api/kb/files/{fileId}/download` | Signierte Download-URL abrufen | Sitzung oder API-Key `kb:read` |
| `POST` | `/api/kb/files/{fileId}/reprocess` | Neu-Chunking und Neu-Embedding erzwingen | Sitzung oder API-Key `kb:write` |
| `POST` | `/api/kb/search` | Semantische Suche über zugeordnete Dateien | Sitzung oder API-Key `kb:read` |
| `GET` | `/api/assistants/{assistantId}/knowledge-base` | Zugeordnete Dateien auflisten | Sitzung oder API-Key `kb:read` |
| `POST` | `/api/assistants/{assistantId}/knowledge-base` | Bestehende KB-Datei zuordnen | Sitzung oder API-Key `kb:write` |
| `DELETE` | `/api/assistants/{assistantId}/knowledge-base/{fileId}` | Datei von Assistent entfernen | Sitzung oder API-Key `kb:write` |

## Konten-KB-Datei hochladen

Laden Sie eine neue Datei in die Wissensdatenbank-Bibliothek Ihres Kontos hoch.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/files" \
  --header "Authorization: Bearer tk_example_kb_write_4rf8m2qa" \
  --form "file=@./docs/acme-support-playbook.pdf"
```

```javascript
const formData = new FormData();
formData.append("file", kbFile);

const response = await fetch("https://app.talkturo.com/api/kb/files", {
  method: "POST",
  headers: {
    Authorization: "Bearer tk_example_kb_write_4rf8m2qa",
  },
  body: formData,
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200 normal,200 dedupliziert,402">
```json
{
  "success": true,
  "credits_charged": 0,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "filename": "acme-support-playbook.pdf",
    "mime_type": "application/pdf",
    "size_bytes": 248193,
    "status": "pending"
  }
}
```

```json
{
  "success": true,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "status": "ready"
  },
  "deduplicated": true,
```

Die ersten 50 MB Speicher sind frei. Für jede weiteren 50 MB werden 1 Credit berechnet.

<Callout kind="info">

Der Upload akzeptiert PDF-, DOCX-, DOC-, TXT- und Markdown-Dateien mit bis zu 1 GB Größe.

</Callout>

<ParamField body="file" param-type="file" required="true">
Datei für den Upload als `multipart/form-data`. Die maximale Größe beträgt 1 GB.

Eindeutige Dateikennung.

<ResponseField name="file.mime_type" field-type="string" required="false">
Erkannter MIME-Typ. Dieses Feld fehlt in der deduplizierten Kurzantwort.
</ResponseField>

<ResponseField name="file.size_bytes" field-type="number" required="false">
Dateigröße in Bytes. Dieses Feld fehlt in der deduplizierten Kurzantwort.
</ResponseField>

<ResponseField name="file.status" field-type="string" required="true">
Aktueller Verarbeitungsstatus der Datei.
</ResponseField>

<ResponseField name="deduplicated" field-type="boolean" required="false">

</ResponseField>

<ResponseField name="message" field-type="string" required="false">
Menschenlesbare Beschreibung der Deduplizierung.
</ResponseField>

<ResponseField name="error" field-type="string" required="false">
Fehlermeldung bei nicht erfolgreicher Anfrage, zum Beispiel bei unzureichendem Credit-Guthaben.
</ResponseField>

Maschinenlesbarer Fehlergrund. Bei fehlenden Credits ist der Wert `insufficient_credits`.
</ResponseField>

<ResponseField name="required_credits" field-type="number" required="false">
Zusätzliche Credits, die für den Upload erforderlich wären.
</ResponseField>

<ResponseField name="balance" field-type="number" required="false">
Aktuelles Credit-Guthaben des Kontos.
</ResponseField>

### Fehlercodes

| Status | Bedeutung |
| --- | --- |
| `400` | Ungültige oder fehlende Upload-Daten |
| `402` | Nicht genügend Credits für zusätzlichen Speicher |
| `413` | Datei überschreitet die maximale Größe |
| `415` | Dateityp wird nicht unterstützt |

## Semantische Suche

```bash
  --header "Authorization: Bearer tk_example_kb_read_9xmk7q2r" \
  --header "Content-Type: application/json" \
  --data '{
    "assistant_id": "9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2",
    "query": "Wie funktioniert die Rückerstattungsfrist für Enterprise-Kunden?",
```

## Bestehende KB-Datei einem Assistenten zuordnen

Ordnen Sie eine bereits in der Kontobibliothek vorhandene Datei einem Assistenten zu.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/assistants/9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2/knowledge-base" \
  --header "Authorization: Bearer tk_example_kb_write_4rf8m2qa" \
  --header "Content-Type: application/json" \
  --data '{
    "file_id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714"
  }'
```

```javascript
const response = await fetch(
  "https://app.talkturo.com/api/assistants/9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2/knowledge-base",
  {
    method: "POST",
    headers: {
      Authorization: "Bearer tk_example_kb_write_4rf8m2qa",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      file_id: "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    }),
  }
);

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true
}
```
</Response>

Die Zuordnung ist idempotent. Wenn die Datei bereits dem Assistenten zugeordnet ist, bleibt die Anfrage erfolgreich und erzeugt kein Duplikat.

### Pfadparameter

<ParamField path="assistantId" param-type="uuid" required="true">
Kennung des Assistenten, dem die Datei zugeordnet werden soll.
</ParamField>

### Body-Parameter

<ParamField body="file_id" param-type="uuid" required="true">
Kennung einer bestehenden Datei aus der Konten-Wissensdatenbank.
</ParamField>

### Antwortfelder

<ResponseField name="success" field-type="boolean" required="true">
Gibt `true` zurück, wenn die Datei zugeordnet ist oder bereits zugeordnet war.
</ResponseField>

## Typischer Workflow

Verwenden Sie die Wissensdatenbank-Endpunkte in dieser Reihenfolge, wenn Sie Dokumente für Retrieval bereitstellen möchten:

<Steps>
<Step title="Datei in die Kontobibliothek hochladen" icon="upload">

Senden Sie die Datei an `POST /api/kb/files`.

Erfolg sieht aus wie eine Antwort mit `success: true` und einem `file`-Objekt mit Status `pending`, oder mit `deduplicated: true`, wenn dieselbe Datei bereits vorhanden ist.

</Step>
<Step title="Verarbeitung abwarten" icon="check-circle">

Rufen Sie `GET /api/kb/files` oder `GET /api/kb/files/{fileId}` auf und prüfen Sie das Feld `status`.

Ihr Workflow kann fortfahren, sobald die Datei den Status `ready` erreicht hat. Bei `failed` prüfen Sie `status_error`.

</Step>
<Step title="Datei einem Assistenten zuordnen" icon="users">

Ordnen Sie die verarbeitete Datei mit `POST /api/assistants/{assistantId}/knowledge-base` einem Assistenten zu.

Erfolg sieht aus wie eine Antwort mit `success: true`.

</Step>
<Step title="Semantische Suche ausführen" icon="search">

Senden Sie Ihre Suchanfrage an `POST /api/kb/search`, um Treffer aus den dem Assistenten zugeordneten Dateien abzurufen.

Erfolg sieht aus wie eine Antwort mit `success: true` und einem `hits`-Array.

</Step>
</Steps>
