## Kontoweite Wissensdatenbank-Dateien

Verwalten Sie Wissensdatenbank-Dateien auf Kontoebene mit dualer Authentifizierung. Diese Endpunkte akzeptieren einen API-Key oder ein Session-Cookie und ermöglichen das Hochladen, Auflisten, Abrufen, Herunterladen und Löschen von Dateien, ohne sie einem bestimmten Assistenten zuzuordnen.

<Callout kind="info">

Kontoweite KB-Datei-Endpunkte verwenden duale Authentifizierung über `withApiAuth`. Authentifizieren Sie sich mit einem API-Key wie `Authorization: Bearer tk_live_example_9xmk7q2r` oder mit einem angemeldeten Session-Cookie. API-Key-Scopes gelten ebenfalls: `kb:read` für `GET`-Endpunkte sowie `kb:write` für `POST`- und `DELETE`-Endpunkte.

</Callout>

### Kontoweite KB-Endpunktübersicht

| Methode | Pfad | Auth | Zweck |
| --- | --- | --- | --- |
| `GET` | `/api/kb/files` | API-Key oder Session | KB-Dateien für das Konto auflisten |
| `POST` | `/api/kb/files` | API-Key oder Session | KB-Datei hochladen |
| `GET` | `/api/kb/files/{fileId}` | API-Key oder Session | Einzelne KB-Datei abrufen |
| `DELETE` | `/api/kb/files/{fileId}` | API-Key oder Session | KB-Datei löschen |
| `GET` | `/api/kb/files/{fileId}/download` | API-Key oder Session | Signierte Download-URL abrufen |

### KB-Datei hochladen

Laden Sie eine Datei mit `multipart/form-data` hoch. Akzeptierte Formate sind `PDF`, `DOCX`, `TXT` und `MD`. Die maximale Dateigröße beträgt 1 GB.

<Callout kind="alert">

Die Dateiverarbeitung erfolgt nach dem Upload, sodass eine neu hochgeladene Datei mit einem noch nicht bereiten Status erscheinen kann, bevor sie für Retrieval verfügbar wird.

</Callout>

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/files" \
  --header "Authorization: Bearer tk_live_example_9xmk7q2r" \
  --form "file=@./docs/acme-support-playbook.pdf"
```

```javascript
const formData = new FormData();
formData.append("file", fileInput.files[0]);

const response = await fetch("https://app.talkturo.com/api/kb/files", {
  method: "POST",
  headers: {
    Authorization: "Bearer tk_live_example_9xmk7q2r",
  },
  body: formData,
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json

  "success": true,
```

## Wissensdatenbank-Endpunkte

Verwalten Sie assistentenspezifische Wissensdatenbank-Dateien mit sitzungsauthentifizierten Endpunkten unter `/api/assistants/{assistantId}/knowledge-base`. Hochgeladene Dateien werden pro Assistent gespeichert und für Retrieval während Anrufen verarbeitet.

<Callout kind="info">

Diese Endpunkte erfordern eine authentifizierte Browser-Sitzung. Sie verwenden keine API-Schlüssel-Authentifizierung.

</Callout>

<Callout kind="alert">

Upload-Anfragen verwenden `multipart/form-data` und müssen ein Dateifeld enthalten. Die Dateiverarbeitung erfolgt nach dem Upload; eine neu hochgeladene Datei kann daher mit einem noch nicht bereiten `status` erscheinen, bevor sie für Retrieval verfügbar wird.

</Callout>

## Endpunktübersicht

| Methode | Pfad | Zweck | Auth |
| --- | --- | --- | --- |
| `GET` | `/api/assistants/{assistantId}/knowledge-base` | Wissensdatenbank-Dateien eines Assistenten auflisten | Sitzungs-Cookie |
| `POST` | `/api/assistants/{assistantId}/knowledge-base` | Wissensdatenbank-Datei hochladen | Sitzungs-Cookie |
| `DELETE` | `/api/assistants/{assistantId}/knowledge-base/{fileId}` | Wissensdatenbank-Datei löschen | Sitzungs-Cookie |
| `GET` | `/api/assistants/{assistantId}/billing/estimate` | Kostenschätzung für die Wissensdatenbank-Verarbeitung abrufen | Sitzungs-Cookie |
| `GET` | `/api/kb` | Eigenständiger Wissensdatenbank-Abfrage-Endpunkt, sofern in Ihrer Deployment aktiviert | Prüfen Sie Ihre Deployment |

## Eigenständiger Wissensdatenbank-Endpunkt

Einige Deployments stellen möglicherweise einen separaten Endpunkt `GET /api/kb` für eigenständige Wissensdatenbank-Abfragen bereit.

<Callout kind="info">

Der Repository-Kontext für diese Seite bestätigt die assistentenspezifischen Endpunkte zur Verwaltung der Wissensdatenbank. Er liefert kein verifiziertes Anfrage- oder Antwortschema für `GET /api/kb`. Prüfen Sie Ihre deployte API oder interne Routendefinitionen, bevor Sie diesen Endpunkt in der Produktion verwenden.

</Callout>

Falls `GET /api/kb` in Ihrer Umgebung existiert, behandeln Sie ihn getrennt von der Dateiverwaltung für Assistenten. Er ersetzt nicht die oben dokumentierten Upload-, Listen- oder Lösch-Endpunkte.

## Typischer Workflow

Verwenden Sie die Wissensdatenbank-Endpunkte in dieser Reihenfolge, wenn Sie die Dokumentenverwaltung automatisieren:

<Steps>
<Step title="Datei hochladen" icon="upload">

Senden Sie eine `POST`-Anfrage mit `multipart/form-data` an den Wissensdatenbank-Endpunkt des Assistenten.

Erfolg sieht aus wie eine Antwort mit `success: true` und einem `file`-Objekt.

</Step>
<Step title="Verarbeitungsstatus abfragen" icon="check-circle">

Rufen Sie `GET /api/assistants/{assistantId}/knowledge-base` auf und prüfen Sie den `status` jeder Datei.

Ihr Workflow kann fortfahren, sobald die hochgeladene Datei in der Liste erscheint und der Status anzeigt, dass die Verarbeitung abgeschlossen ist.

</Step>
<Step title="Verarbeitungskosten bei Bedarf schätzen" icon="bar-chart">

Rufen Sie `GET /api/assistants/{assistantId}/billing/estimate` vor oder nach dem Upload auf, wenn Sie Abrechnungstransparenz für die Wissensdatenbank-Nutzung des Assistenten benötigen.

Erfolg sieht aus wie eine Antwort mit `success: true` und einem `estimate`-Objekt.

</Step>
<Step title="Veraltete Dateien entfernen" icon="trash">

Löschen Sie Dateien, die der Assistent nicht mehr verwenden soll, mit `DELETE /api/assistants/{assistantId}/knowledge-base/{fileId}`.

Eine erfolgreiche Löschung gibt `success: true` und eine Bestätigungsnachricht zurück.

</Step>
</Steps>
