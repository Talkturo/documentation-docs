## Was ein Check ist

Ein Check (auch Szenario genannt) ist ein gespeichertes Testgespräch für einen Assistenten. Er enthält eine Bezeichnung, die Anweisungen, denen der simulierte Anrufer folgt, und die Erwartungen, an denen das Verhalten des Assistenten gemessen wird. Legen Sie pro Assistent eine Sammlung von Checks an und führen Sie diese nach Änderungen am Prompt oder an den Tools aus, um zu bestätigen, dass sich der Assistent weiterhin so verhält, wie Sie es erwarten.

Eine Ausführung führt einen oder mehrere Checks aus und meldet pro Check ein Urteil. Ausführungen werden vor dem Start in Credits bepreist; die aktuellen Preise und Ihr Guthaben erhalten Sie zusammen mit dem Ausführungsverlauf.

## Anfragen authentifizieren

Die Check-Routen akzeptieren entweder einen Workspace-API-Schlüssel oder ein Session-Cookie aus der Web-App.

- **API-Schlüssel**: Senden Sie `Authorization: Bearer tk_live_...` oder `tk_test_...` für einen Test-Workspace.
- **Session**: Verwenden Sie das Cookie, das die Web-App beim Anmelden eines Benutzers setzt.

Der Workspace wird immer aus dem Credential abgeleitet. Eine Workspace- oder Account-ID im Body oder in der Query-Zeichenkette ändert das Ziel nicht, sodass ein Schlüssel, der für einen Workspace ausgestellt wurde, niemals die Checks eines anderen Workspaces lesen kann.

<Callout kind="info">

Diese Routen akzeptieren beide Credential-Typen, weil das Dashboard-Frontend sie aufruft. Die versionierte Oberfläche [API v1](/de/api-reference/v1-overview) akzeptiert nur API-Schlüssel. Informationen zum Erstellen und Rotieren von Schlüsseln finden Sie unter [Authentifizierung](/de/api-reference/api-keys).

</Callout>

## Endpunkt-Referenz

Jeder Pfad ist relativ zu `https://app.talkturo.com` und gilt für genau einen Assistenten.

| Methode | Pfad | Zweck |
|---|---|---|
| GET | `/api/assistants/{assistantId}/checks` | Listet die Checks des Assistenten auf |
| POST | `/api/assistants/{assistantId}/checks` | Erstellt einen Check |
| PATCH | `/api/assistants/{assistantId}/checks/{checkId}` | Bearbeitet einen Check oder schaltet ihn ab |
| DELETE | `/api/assistants/{assistantId}/checks/{checkId}` | Löscht einen Check |
| GET | `/api/assistants/{assistantId}/checks/runs` | Liest die letzten 20 Ausführungen mit aktuellen Preisen |
| POST | `/api/assistants/{assistantId}/checks/runs` | Startet eine Ausführung |
| GET | `/api/assistants/{assistantId}/checks/runs/{runId}` | Liest eine Ausführung und ihre Ergebnisse |
| PATCH | `/api/assistants/{assistantId}/checks/runs/{runId}` | Bricht eine Ausführung ab |

## Das Check-Objekt

Jede Check-Antwort liefert denselben Satz von Feldern in snake_case.

<ParamField body="id" param-type="string" show-location="false">

</ParamField>

<ParamField body="label" param-type="string" show-location="false">

</ParamField>

<ParamField body="instructions" param-type="string" show-location="false">

Was der simulierte Anrufer tut und sagt. Maximal 20000 Zeichen.

</ParamField>

</ParamField>

<ParamField body="source" param-type="string" show-location="false">

<ParamField body="created_at" param-type="string" show-location="false">

</ParamField>

<ParamField body="updated_at" param-type="string" show-location="false">

ISO-8601-Zeitstempel der letzten Änderung des Checks.

</ParamField>

### Check erstellen

Fügt dem Assistenten einen Check hinzu. Ein erstellter Check wird nicht ausgeführt; starten Sie eine Ausführung, um ein Urteil zu erhalten.

<ParamField path="assistantId" param-type="string" required="true">

ID des Assistenten, dem der Check zugeordnet wird.

</ParamField>

<ParamField body="label" param-type="string" required="true">

Kurzer Name des Szenarios. Zwischen 1 und 200 Zeichen.

</ParamField>

<ParamField body="instructions" param-type="string" required="true">

Was der simulierte Anrufer tut und sagt. Zwischen 1 und 20000 Zeichen. Formulieren Sie es als Briefing: die Situation, die Details, die der Anrufer kennt, und den Ton, den er anschlägt.

</ParamField>

<ParamField body="agentExpectations" param-type="string" required="true">

Was der Assistent erwartungsgemäß tun soll. Zwischen 1 und 5000 Zeichen. Dieses Request-Feld ist camelCase; gespeichert und zurückgegeben wird es als `agent_expectations`.

</ParamField>

<ParamField body="tags" param-type="string[]">

Optionales Array aus Strings zum Gruppieren von Checks.

</ParamField>

<ParamField body="userdata" param-type="object">

Optionales Objekt mit Werten, das während des simulierten Gesprächs den Datensatz des Anrufers ersetzt.

</ParamField>

<ParamField body="enabled" param-type="boolean">

Ob der Check an Ausführungen teilnimmt, die ohne explizite Check-Liste gestartet werden. Standardwert ist `true`.

</ParamField>

<ParamField body="source" param-type="string" enum="manual,generated">

Herkunft des Checks. Standardwert ist `manual`; verwenden Sie `generated` für einen aus einem vergangenen Anruf abgeleiteten Check und geben Sie dazu eine `source_call_id` an.

</ParamField>

### Ausführung starten

Startet die Ausführung von Checks. Lassen Sie `checkIds` weg, um alle aktivierten Checks des Assistenten auszuführen, oder senden Sie eine explizite Liste, um bestimmte Checks anzusprechen.

<ParamField path="assistantId" param-type="string" required="true">

ID des zu testenden Assistenten.

</ParamField>

<ParamField body="mode" param-type="string" enum="text,audio">

Wie das simulierte Gespräch geführt wird. Standardwert ist `text`.

</ParamField>

<ParamField body="checkIds" param-type="string[]">

Explizite Liste der auszuführenden Check-IDs, maximal 25 pro Ausführung. Wird das Feld weggelassen, laufen alle aktivierten Checks des Assistenten.

</ParamField>

<ParamField body="promptVersionId" param-type="string">

Führt die Checks gegen eine bestimmte gespeicherte Prompt-Version statt gegen den aktuellen Prompt des Assistenten aus.

</ParamField>

<ParamField body="options" param-type="object">

Optionales Objekt, das an den Runner durchgereicht wird.

</ParamField>

Die Ausführung wird vor dem Start bepreist, die Schätzung kommt als `credits_estimated` zurück, und Ihr Guthaben muss sie decken. Wenn die Ergebnisse vorliegen, werden Credits nur für die Checks berechnet, die tatsächlich gelaufen sind. Bei einer abgebrochenen Ausführung werden nur die Checks berechnet, die ein echtes Urteil erzeugt haben.

Pro Assistent läuft immer nur eine Ausführung. Eine Startanfrage reiht entweder die gesamte Ausführung ein oder schlägt vollständig fehl.

<Callout kind="alert">

Eine Startanfrage ist alles oder nichts. Es gibt keine Teilläufe: Schlägt die Anfrage fehl, wird kein Check eingereiht und nichts berechnet.

</Callout>

#### Fehler beim Start einer Ausführung

| Status | Fehlercode | Bedeutung |
|---|---|---|
| `400` | `no_checks` | Der Assistent hat keine aktivierten Checks zum Ausführen. Die Meldung lautet „There is nothing to run: add a check first." |
| `400` | | Es wurden mehr als 25 Check-IDs gesendet. |
| `400` | `bad_prompt_version` | Die Prompt-Version gehört nicht zu diesem Assistenten. |
| `402` | `insufficient_credits` | Das Guthaben deckt die Schätzung nicht. Der Body enthält zusätzlich `required_credits` und `balance`. |
| `409` | | Für diesen Assistenten läuft bereits eine Ausführung. Warten Sie, bis sie abgeschlossen ist. |
| `503` | | Die Ausführung konnte derzeit nicht bepreist werden. Versuchen Sie es später erneut. |
| `500` | | Das Starten der Ausführung ist fehlgeschlagen. Wurde sie vom Runner abgelehnt, wird die Ausführung als fehlgeschlagen geschlossen und ihre ID zurückgegeben. |

### Ausführung lesen

### Statuswerte einer Ausführung

Eine Ausführung hat einen von vier Statuswerten.

| Status | Bedeutung |
|---|---|
| `queued` | Angenommen und wartet darauf, dass der Runner sie aufnimmt |
| `running` | Checks werden ausgeführt |
| `cancelled` | Durch eine Abbruchanfrage gestoppt |
| `failed` | Die Ausführung wurde nicht abgeschlossen |

Eine regulär abgeschlossene Ausführung meldet ihre Zähler `passed` und `failed` sowie einen `finished_at`-Zeitstempel. Die Urteile pro Check sind vom Status der Ausführung getrennt, daher kann eine Ausführung abschließen, während einzelne Ergebnisse als `fail` oder `error` markiert sind.

### Ausführung abbrechen

Stoppt eine Ausführung, die noch nicht abgeschlossen ist. Checks, die bereits ein Ergebnis geliefert haben, behalten es und werden berechnet; die übrigen Checks werden nicht ausgeführt.

<ParamField path="assistantId" param-type="string" required="true">

ID des Assistenten, dem die Ausführung gehört.

</ParamField>

<ParamField path="runId" param-type="string" required="true">

ID der abzubrechenden Ausführung.

</ParamField>

<ParamField body="action" param-type="string" required="true" enum="cancel">

Die auszuführende Aktion. `cancel` ist der einzige akzeptierte Wert; alles andere liefert `400`.

</ParamField>

<Request tabs="cURL">

```bash
curl -X PATCH https://app.talkturo.com/api/assistants/ast_9c4b7e21/checks/runs/run_8c14bd3a \
  -H "Authorization: Bearer tk_live_9xmk7q2r4tz" \
  -H "Content-Type: application/json" \
  -d '{ "action": "cancel" }'
```

</Request>

<Response tabs="200">

```json
{
  "success": true,
  "status": "cancelled",
  "completed": false
}
```

</Response>

<ResponseField name="status" field-type="string">

Der Status der Ausführung nach der Anfrage.

</ResponseField>

<ResponseField name="completed" field-type="boolean">

Ob die Ausführung ihren finalen Zustand erreicht hat.

</ResponseField>

Ist die Ausführung bereits abgeschlossen, wird nichts abgebrochen; die Antwort enthält stattdessen `alreadyFinished: true` mit dem aktuellen Status der Ausführung.
