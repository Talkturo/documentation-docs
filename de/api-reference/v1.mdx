## Was Sie mit der v1 API erstellen können

Die v1 API ist eine JSON-REST-Schnittstelle für Server-zu-Server-Integrationen. Von Ihrem eigenen Backend aus können Sie einen ausgehenden Anruf zu einem einzelnen Kontakt platzieren, eine WhatsApp-Nachricht senden, nachlesen, was in einem Anruf passiert ist (Status, Zusammenfassung, Transkript, Aufnahme, Analyse), nachfassen, wenn etwas verfügbar wird, worauf ein Kontakt gewartet hat, und die für Ihren Workspace genehmigten Nachrichtenvorlagen auflisten.

<Callout kind="info">

Jede Anfrage geht an `https://app.talkturo.com/api/v1`. Senden Sie `Content-Type: application/json` bei Anfragen mit Body, und erwarten Sie bei jeder Antwort einen JSON-Body zurück.

</Callout>

## Mit einem Workspace-API-Schlüssel authentifizieren

Senden Sie einen Workspace-API-Schlüssel als Bearer-Token im `authorization`-Header. Session-Cookies, Dashboard-Logins und Browser-Token werden abgelehnt.

```bash
curl "https://app.talkturo.com/api/v1/calls/c4a8e21f-6b03-4d97-8e5a-2f17b9c4d803" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4w"
```

Schlüssel beginnen mit `tk_live_` für einen Produktions-Workspace oder `tk_test_` für einen Test-Workspace. Talkturo speichert nur einen Hash des Schlüssels, der vollständige Wert wird also nur einmal angezeigt, wenn Sie ihn erstellen. Wenn Sie ihn verlieren, erstellen Sie einen neuen Schlüssel und löschen den alten.

Ein Schlüssel gehört zu genau einem Workspace, und diese Bindung steht fest, sobald der Schlüssel sich authentifiziert. Kein Anfrageparameter, Header oder Body-Feld kann den Schlüssel auf einen anderen Workspace zeigen lassen, ein Schlüssel kann also keine Daten außerhalb des Workspace lesen oder schreiben, der ihn ausgestellt hat.

Ein fehlender Header antwortet mit `401` und der Meldung `Send a workspace API key: Authorization: Bearer tk_live_…`. Ein Schlüssel, der nicht mehr funktioniert (gelöscht, abgelaufen oder deaktiviert), antwortet mit `401` und `The API key is invalid, expired or switched off.`

Um einen Schlüssel zu erstellen, seine Scopes zu wählen und den vollständigen Lebenszyklus zu sehen, lesen Sie [Authentifizierung](/de/api-reference/authentication) und [API-Schlüssel](/de/api-reference/api-keys).

## Scopes

Jeder Endpunkt erfordert einen benannten Scope, und der Schlüssel muss ihn tragen. Die Scope-Prüfung läuft in drei Schritten: `*` gewährt alles, ein Präfix-Wildcard wie `calls:*` gewährt jeden Scope in diesem Namespace, und ansonsten muss der Scope exakt passen.

| Scope | Gewährt Zugriff auf |
| --- | --- |
| `calls:create` | Ausgehende Anrufe platzieren |
| `calls:read` | Anrufe auflisten und lesen, Aufnahmen herunterladen |
| `messages:send` | WhatsApp-Nachrichten senden |
| `messages:read` | Eine Nachricht und ihren Zustellstatus lesen |
| `plans:read` | Follow-up-Pläne auflisten |
| `plans:write` | Einen Plan als bereit markieren |
| `templates:read` | Genehmigte WhatsApp-Vorlagen auflisten |

Ein Schlüssel ohne den erforderlichen Scope antwortet mit `403`, dem Code `missing_scope` und einer Meldung, die den benötigten Scope nennt, zum Beispiel `This API key does not have the messages:send scope.`

## Ratenlimits und Header

Jede Anfrage zählt gegen das stündliche Kontingent des Schlüssels. Der Standard sind 1000 Anfragen pro Stunde, und jeder Schlüssel kann mit einem eigenen Limit bis 100000 konfiguriert werden.

Drei Header kommen bei jeder Antwort zurück, ob erfolgreich oder nicht, damit Sie Ihren Client takten können, bevor Sie an die Grenze stoßen:

| Header | Bedeutung |
| --- | --- |
| `X-RateLimit-Limit` | Anfragen, die der Schlüssel in der aktuellen Stunde machen darf |
| `X-RateLimit-Remaining` | Verbleibende Anfragen im Fenster, nie unter null |
| `X-RateLimit-Reset` | Wann das aktuelle Fenster zurückgesetzt wird |

Über dem Limit antwortet die Anfrage mit `429`, dem Code `rate_limited` und einem `Retry-After`-Header, der die Sekunden bis zum Zurücksetzen des Fensters enthält.

```json
{
  "error": {
    "code": "rate_limited",
    "message": "This API key has used its 1000 requests for this hour."
  }
}
```

## Fehlerantworten

Jeder Fehler nutzt dasselbe Format: ein `error`-Objekt mit einem kurzen, maschinenlesbaren `code` und einer `message`, die Menschen lesen können. Verzweigen Sie auf `code`, und loggen Sie `message` für die Person, die die Logs liest.

```json
{
  "error": {
    "code": "call_not_found",
    "message": "No call with this id in this workspace."
  }
}
```

| Status | Code | Wann es dazu kommt |
| --- | --- | --- |
| 400 | `invalid_request` | Der Body oder der Query-String ist fehlerhaft, ein Feld fehlt oder ein Wert hat den falschen Typ |
| 400 | `idempotency_key_required` | Die POST-Anfrage hat keinen brauchbaren `Idempotency-Key`-Header |
| 400 | `invalid_status` | `status` in der Plan-Liste ist keiner der erlaubten Werte |
| 400 | `invalid_contact_id` | `contact_id` in der Plan-Liste ist keine UUID |
| 400 | `invalid_body` | Der Ready-Body enthält ein anderes Feld als `note`, oder eine Notiz ist länger als 300 Zeichen |
| 401 | `unauthorized` | Der `Authorization`-Header fehlt, oder der Schlüssel ist ungültig, abgelaufen oder deaktiviert |
| 403 | `missing_scope` | Der Schlüssel trägt nicht den Scope, den der Endpunkt erfordert |
| 404 | `call_not_found` | Kein Anruf mit dieser ID in diesem Workspace |
| 404 | `message_not_found` | Keine Nachricht mit dieser ID in diesem Workspace |
| 404 | `plan_not_found` | Kein Plan mit dieser ID in diesem Workspace |
| 404 | `recording_not_found` | Der Anruf existiert, hat aber keine Aufnahme |
| 404 | `contact_not_found` | Der Kontakt existiert nicht in diesem Workspace |
| 409 | `idempotency_key_reused` | Derselbe Schlüssel wurde zuvor mit einem anderen Body verwendet |
| 409 | `not_waiting` | Der Plan wartet auf nichts |
| 422 | `contact_has_no_phone` | Der Kontakt hat keine Telefonnummer, die angerufen werden kann |
| 422 | `no_whatsapp_number` | Der Workspace hat keine WhatsApp-Nummer, von der gesendet werden kann |
| 422 | `assistant_required` | Der Workspace sendet von mehr als einer WhatsApp-Nummer, daher muss `assistant_id` mitgesendet werden |
| 429 | `rate_limited` | Der Schlüssel hat sein stündliches Kontingent verbraucht |
| 500 | `internal_error` | Auf der Talkturo-Seite ist etwas fehlgeschlagen. Wiederholen Sie die Anfrage |
| 502 | `failed` | WhatsApp hat die Nachricht nicht angenommen. Der Body enthält ein `failure`-Objekt |
| 503 | `recording_unavailable` | Der Aufnahme-Link konnte gerade nicht signiert werden. Versuchen Sie es später erneut |

<Callout kind="alert">

Wiederholen Sie Antworten mit `401`, `403`, `404`, `409` oder `422` nicht unverändert. Jede davon bedeutet, dass die Anfrage selbst weiter scheitern wird, bis Sie den Schlüssel, den Body oder die Ressource ändern.

</Callout>

## Idempotenz

`POST /api/v1/calls` und `POST /api/v1/messages` erfordern beide einen `Idempotency-Key`-Header. Der Wert muss 1 bis 100 Zeichen aus Buchstaben, Ziffern oder `:`, `_`, `.` und `-` enthalten. Alles andere oder ein fehlender Header antwortet mit `400` und dem Code `idempotency_key_required`.

Senden Sie denselben Schlüssel erneut mit demselben Body, gibt Talkturo zurück, was die erste Anfrage zurückgegeben hat, ohne die Aktion zu wiederholen: Es wird kein zweiter Anruf platziert und keine zweite Nachricht gesendet. Senden Sie denselben Schlüssel mit einem anderen Body, erhalten Sie `409` mit dem Code `idempotency_key_reused`, was Sie vor einer Wiederholungsschleife schützt, die die Anfrage still verändert.

Wählen Sie Schlüssel, die für die logische Operation eindeutig sind statt für den HTTP-Versuch, damit eine Wiederholung nach einem Timeout den ursprünglichen Schlüssel wiederverwendet:

```text
acme-sales:call:deal_7781:1
acme-sales:msg:deal_7781:order_ready
```

`POST /api/v1/plans/{id}/ready` nimmt keinen `Idempotency-Key` entgegen. Ein erfolgreiches Ready bewegt den Plan aus `waiting` heraus, eine Wiederholung antwortet daher mit `409` und dem Code `not_waiting`, statt ein zweites Mal an den Kontakt zu schreiben.

## Das Call-Objekt

Die Calls-Endpunkte geben alle dieselbe Ressource zurück. Hier ist jedes Feld, das sie trägt.

<ResponseField name="id" field-type="string">
Der Bezeichner des Anrufs, eine UUID. Verwenden Sie ihn mit den Retrieve- und Recording-Endpunkten und um einen Anruf dem `call.analyzed` Webhook zuzuordnen.
</ResponseField>

<ResponseField name="status" field-type="string">
Wo der Anruf in seinem Lebenszyklus steht: `queued` (angenommen, noch nicht gewählt), `ringing`, `in_progress`, `completed` oder `failed`.
</ResponseField>

<ResponseField name="assistant_id" field-type="string">
Der Assistent, dessen Stimme und Prompt-Konfiguration den Anruf geführt hat.
</ResponseField>

<ResponseField name="contact_id" field-type="string | null">
Der Kontakt, den der Anruf erreichen sollte, oder `null`, wenn die Anfrage stattdessen eine reine `to_number` genannt hat.
</ResponseField>

<ResponseField name="campaign_id" field-type="string | null">
Die Kampagne, aus der der Anruf stammt. `null` für Anrufe, die über diese API platziert wurden.
</ResponseField>

<ResponseField name="direction" field-type="string">
`outbound` für Anrufe, die Sie platzieren, `inbound` für Anrufe, die der Workspace empfangen hat.
</ResponseField>

<ResponseField name="from_number" field-type="string | null">
Die Nummer, von der der Anruf platziert wurde, im E.164-Format.
</ResponseField>

<ResponseField name="to_number" field-type="string | null">
Die gewählte Nummer im E.164-Format.
</ResponseField>

<ResponseField name="created_at" field-type="string">
Wann die Anfrage angenommen wurde, als ISO 8601-Zeitstempel.
</ResponseField>

<ResponseField name="started_at" field-type="string | null">
Wann es am anderen Ende zu klingeln begann. `null`, bis der Anruf verbunden ist.
</ResponseField>

<ResponseField name="ended_at" field-type="string | null">
Wann der Anruf beendet wurde. `null`, solange er noch läuft.
</ResponseField>

<ResponseField name="duration_seconds" field-type="integer | null">
Länge des verbundenen Anrufs in gerundeten Sekunden. `0`, wenn der Anruf endete, ohne je zu starten, und `null`, bevor er startet.
</ResponseField>

<ResponseField name="answered_by" field-type="string | null">
Wer abgenommen hat: `human`, `voicemail` oder `unknown`. `null`, bevor der Anruf beantwortet wird.
</ResponseField>

<ResponseField name="ended_reason" field-type="string | null">
Warum der Anruf endete. Immer `null`, außer der Anruf hat gestartet.
</ResponseField>

<ResponseField name="failure_reason" field-type="string | null">
Warum ein Anruf nie verbunden wurde: `busy`, `no_answer` oder `call_not_started`, wenn eine eingereihte Anfrage nie zu einem Anruf wurde.
</ResponseField>

<ResponseField name="outcome" field-type="string | null">
Was erreicht wurde: `answered`, `unreachable` (der Anruf endete, ohne zu starten), `voicemail`, `do_not_call` oder das Ergebnis, das der Assistent nach dem Anruf festgehalten hat.
</ResponseField>

<ResponseField name="summary" field-type="string | null">
Eine kurze schriftliche Zusammenfassung des Gesprächs, erstellt nachdem der Anruf endet.
</ResponseField>

<ResponseField name="transcript" field-type="string | null">
Das Gesprächstranskript als Text. Wird nur gesendet, wenn Sie `include=transcript` anfordern, und nur für Anrufe, die gestartet sind.
</ResponseField>

<ResponseField name="recording_url" field-type="string | null">
Die stabile Adresse der Aufnahme in dieser API, `https://app.talkturo.com/api/v1/calls/{id}/recording`. `null`, wenn der Anruf keine Aufnahme hat.
</ResponseField>

<ResponseField name="analysis" field-type="object | null">
Die strukturierte Auswertung des Anrufs, oder `null`, wenn keine Analyse existiert. Enthält `sentiment` und `success` (beide nur gefüllt, wenn das Anrufergebnis bewertet wurde), dazu die Listen `key_points`, `objections`, `questions_asked` und `action_items`.
</ResponseField>

<ResponseField name="callback" field-type="object">
Was der Kontakt erbeten hat. Enthält `requested` (boolean), `scheduled_call_id`, `run_at`, `timezone`, `when_words` (die Formulierung des Kontakts, etwa „Donnerstag nachmittag“) und `reason`.
</ResponseField>

<ResponseField name="metadata" field-type="object">
Die `metadata`, die Sie beim Platzieren des Anrufs gesendet haben, unverändert zurückgegeben. Die Variablen, die nur zum Aufbau des Prompts dienten, sind entfernt.
</ResponseField>

<Callout kind="alert">

Eine Anfrage, aus der nie ein Anruf wurde, wird als `failed` mit `failure_reason` `call_not_started` gemeldet, sobald seit ihrer Erstellung zehn Minuten vergangen sind. Ein `queued`-Status, der älter als zehn Minuten ist, ist daher nie endgültig, und wiederholtes Abfragen löst ihn nicht auf.

</Callout>

## Einen Anruf platzieren

Platziert einen ausgehenden Anruf zu einem Kontakt oder einer reinen Telefonnummer und gibt sofort das Call-Objekt zurück. Die Antwort sagt Ihnen, dass die Anfrage angenommen wurde, nicht wie der Anruf gelaufen ist: Hören Sie auf den `call.analyzed` Webhook oder fragen Sie den Retrieve-Endpunkt nach dem Ergebnis ab. Erfordert den Scope `calls:create`.

Der Workspace muss für ausgehende Anrufe verifiziert sein, bevor Anrufe angenommen werden. Ist er es nicht, wird die Anfrage mit einem `until`-Feld im Fehler-Body abgelehnt, das Ihnen sagt, wann ausgehende Anrufe wieder möglich sind.

### Endpunkt

`POST /api/v1/calls`

### Header

<ParamField header="Idempotency-Key" param-type="string" required="true">
Eindeutig für diesen Anruf. 1 bis 100 Zeichen aus Buchstaben, Ziffern oder `:` `_` `.` `-`.
</ParamField>

### Body-Parameter

<ParamField body="assistant_id" param-type="string" required="true">
UUID des Assistenten, der den Anruf führt. Seine Stimme, sein Prompt, seine Sprache und seine Tools entscheiden, was passiert.
</ParamField>

<ParamField body="to_number" param-type="string">
Die zu wählende Nummer, 4 bis 32 Zeichen, im E.164-Format. Geben Sie dies oder `contact_id` an, oder beides.
</ParamField>

<ParamField body="contact_id" param-type="string">
UUID des Kontakts, der angerufen werden soll. Verwenden Sie sie statt `to_number`, wenn der Anruf an der Historie des Kontakts hängen soll. Geben Sie dies oder `to_number` an, oder beides.
</ParamField>

<ParamField body="from_number" param-type="string">
Die Nummer, von der der Anruf platziert wird, 4 bis 32 Zeichen. Lassen Sie sie weg, um die Standardnummer des Assistenten zu verwenden.
</ParamField>

<ParamField body="variables" param-type="object">
Werte für den Prompt des Assistenten, gerendert als `{{call.key}}`. Jeder Wert ist ein String mit bis zu 2000 Zeichen, eine Zahl oder ein Boolean. Schlüssel sind Strings.
</ParamField>

<ParamField body="metadata" param-type="object">
Ihre eigenen Daten, die am Anruf hängen. Sie kommen bei jedem Webhook für diesen Anruf und im Call-Objekt zurück.
</ParamField>

Der Body ist strikt: Senden Sie ein Feld, das oben nicht aufgeführt ist, antwortet die Anfrage mit `400`. `metadata` und `variables` dürfen zusammen höchstens 8 KB JSON umfassen.

### Beispielanfrage


## Anrufe auflisten

Listet die Anrufe in Ihrem Workspace auf, die neuesten zuerst, mit Filtern für Assistent, Kontakt und Zeitfenster. Verwenden Sie den Endpunkt, um Ihr eigenes Anrufprotokoll aufzubauen oder Ergebnisse abzugleichen, nachdem Sie eine Webhook-Zustellung verpasst haben. Erfordert den Scope `calls:read`.

### Endpunkt

`GET /api/v1/calls`

### Query-Parameter

<ParamField query="assistant_id" param-type="string">
Nur Anrufe dieses Assistenten zurückgeben. Eine UUID.
</ParamField>

<ParamField query="contact_id" param-type="string">
Nur Anrufe an diesen Kontakt zurückgeben. Eine UUID.
</ParamField>

<ParamField query="from" param-type="string">
Beginn des Zeitfensters, inklusive, als ISO 8601-Zeitstempel mit Offset. Wird mit `created_at` verglichen.
</ParamField>

<ParamField query="to" param-type="string">
Ende des Zeitfensters, exklusiv, als ISO 8601-Zeitstempel mit Offset. Wird mit `created_at` verglichen.
</ParamField>

<ParamField query="cursor" param-type="string">
Der `next_cursor`-Wert der vorherigen Seite. Lassen Sie ihn für die erste Seite weg.
</ParamField>

<ParamField query="limit" param-type="integer">
Seitengröße von 1 bis 100. Standard ist 25.
</ParamField>

<ParamField query="include" param-type="string">
Übergeben Sie `transcript`, um das Feld `transcript` bei jedem Anruf der Seite zu füllen.
</ParamField>

### Beispielanfrage

<Request tabs="cURL,JavaScript" default-tab="1">

```bash
curl "https://app.talkturo.com/api/v1/calls?assistant_id=6d2f9a44-1c83-4b0e-9f57-a1c8e3b6d204&from=2025-03-01T00:00:00Z&limit=1" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4w"
```

```javascript
const params = new URLSearchParams({
  assistant_id: "6d2f9a44-1c83-4b0e-9f57-a1c8e3b6d204",
  from: "2025-03-01T00:00:00Z",
  limit: "1",
});

const response = await fetch(`https://app.talkturo.com/api/v1/calls?${params}`, {
  headers: { Authorization: "Bearer tk_live_example_9xmk7q2r4w" },
});

const page = await response.json();
console.log(page.data.length, page.next_cursor);
```

</Request>

Die Seite antwortet mit einer Hülle, die die Anrufe und einen Cursor enthält. Jeder Eintrag ist ein Call-Objekt wie unter [Das Call-Objekt](#the-call-object) beschrieben.

<ResponseField name="data" field-type="array" required="true">
Die Anrufe auf dieser Seite, sortiert nach `created_at` absteigend.
</ResponseField>

<ResponseField name="next_cursor" field-type="string | null" required="true">
Übergeben Sie diesen Wert als `cursor`, um die nächste Seite zu holen. `null` bedeutet, Sie haben die letzte Seite erreicht.

## Eine Aufnahme herunterladen

Gibt ein `302` auf einen signierten Link zur Aufnahme des Anrufs zurück. Der signierte Link gilt eine Stunde. Die API-Adresse in `recording_url` läuft nie ab und verrät nie, wo Aufnahmen gespeichert sind; speichern Sie also diese Adresse und holen Sie sich bei Bedarf einen frischen Redirect. Erfordert den Scope `calls:read`.

### Endpunkt

`GET /api/v1/calls/{id}/recording`

### Pfadparameter

<ParamField path="id" param-type="string" required="true">
UUID eines Anrufs, der eine Aufnahme hat.
</ParamField>

### Beispielanfrage

<Request tabs="cURL,JavaScript" default-tab="1">

```bash
curl -L "https://app.talkturo.com/api/v1/calls/c4a8e21f-6b03-4d97-8e5a-2f17b9c4d803/recording" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4w" \
  -o call-c4a8e21f.mp3
```

```javascript
const recordingUrl =
  "https://app.talkturo.com/api/v1/calls/c4a8e21f-6b03-4d97-8e5a-2f17b9c4d803/recording";

const response = await fetch(recordingUrl, {
  headers: { Authorization: "Bearer tk_live_example_9xmk7q2r4w" },
  redirect: "follow",
});

if (!response.ok) throw new Error("Recording not available");

const audio = await response.arrayBuffer();
```

</Request>

### Antwort

Der Redirect hat keinen Body. Lassen Sie Ihren HTTP-Client Weiterleitungen folgen, sonst erhalten Sie das `302` und müssen den `Location`-Header selbst lesen.

## Eine WhatsApp-Nachricht senden

Sendet eine WhatsApp-Nachricht an einen Kontakt, entweder Freitext innerhalb des 24-Stunden-Fensters des Kontakts oder eine genehmigte Utility-Vorlage außerhalb davon. Erfordert den Scope `messages:send`.

Senden Sie genau eines von `text` oder `template`. Alles andere, auch beides, antwortet mit `400`.

### Endpunkt

`POST /api/v1/messages`

### Header

<ParamField header="Idempotency-Key" param-type="string" required="true">
Eindeutig pro Nachricht. 1 bis 100 Zeichen aus Buchstaben, Ziffern oder `:` `_` `.` `-`.
</ParamField>

### Body-Parameter

<ParamField body="contact_id" param-type="string" required="true">
UUID des Kontakts, der die Nachricht erhalten soll.
</ParamField>

<ParamField body="assistant_id" param-type="string">
UUID des Assistenten, dessen WhatsApp-Nummer die Nachricht sendet, oder `null`. Senden Sie sie, wenn der Workspace mehr als eine WhatsApp-Nummer hat, sonst antwortet die Anfrage mit `422` und dem Code `assistant_required`.
</ParamField>

<ParamField body="text" param-type="string">
Freitext, 1 bis 4096 Zeichen. Wird nur innerhalb des 24-Stunden-Fensters des Kontakts angenommen. Geben Sie dies oder `template` an.
</ParamField>

<ParamField body="template" param-type="object">
Die genehmigte Vorlage, die gesendet werden soll. Geben Sie dies oder `text` an.
</ParamField>

<ParamField body="template.name" param-type="string" required="true">
Vorlagenname, 1 bis 512 Zeichen, wie vom Templates-Endpunkt zurückgegeben.
</ParamField>

<ParamField body="template.language" param-type="string" required="true">
Sprache der Vorlage, 2 bis 16 Zeichen. `en` und `de` sind die Sprachen, die der Templates-Endpunkt anbietet.
</ParamField>

<ParamField body="template.variables" param-type="object">
Werte für die Variablen der Vorlage: Schlüssel sind Strings, Werte sind Strings mit bis zu 1024 Zeichen. Standard ist ein leeres Objekt.
</ParamField>

<ParamField body="consent" param-type="object">
Optionaler Nachweis, warum Sie diesen Kontakt anschreiben dürfen.
</ParamField>

<ParamField body="consent.evidence" param-type="string">
Wo und wann der Kontakt zugestimmt hat, 1 bis 500 Zeichen.
</ParamField>

```bash
      "evidence": "Opted in at checkout on 2025-02-27"
    }
  }'
```
