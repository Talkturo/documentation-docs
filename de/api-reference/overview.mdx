## Entwickeln Sie auf der Talkturo API

Erstellen Sie Integrationen und Automatisierungen auf Basis der Voice-AI-Plattform von Talkturo mit einer REST-API für Assistenten, Telefonie, Telefonnummern, Guthaben, CRM-Daten, Workflows und Kontoverwaltung. Auf dieser Seite lernen Sie die grundlegenden API-Konventionen kennen und finden die Endpunktgruppe, die Sie benötigen.

<Callout kind="info">

Senden Sie alle API-Anfragen an `https://api.talkturo.com/api`.

</Callout>

## Authentifizieren Sie Anfragen

Talkturo unterstützt drei Authentifizierungsmethoden. Die meisten externen Integrationen sollten API-Schlüssel verwenden, während Browser- und Desktop-Clients plattformspezifische Authentifizierungsabläufe nutzen.

<Tabs>
  <Tab title="API-Schlüssel" icon="key">

Verwenden Sie ein Bearer-Token, das mit `tk_live_` oder `tk_test_` beginnt, um Server-zu-Server-Anfragen zu authentifizieren. API-Schlüssel unterstützen Scopes und haben standardmäßig ein Ratenlimit von 1000 Anfragen pro Stunde.

Unter [Authentifizierung](/de/api-reference/authentication) finden Sie das Header-Format, das Verhalten von Scopes und Sicherheitshinweise.

  </Tab>
  <Tab title="Sitzungs-Cookies" icon="lock">

Die Talkturo-Web-App verwendet authentifizierte Sitzungs-Cookies für browserbasierte Anfragen. Diese Methode ist für Web-Sitzungen der eigenen Anwendung vorgesehen, nicht für externe Backend-Integrationen.

Unter [Authentifizierung](/de/api-reference/authentication) erfahren Sie, wann sitzungsbasierte Authentifizierung zum Einsatz kommt.

  </Tab>
  <Tab title="JWT-Bearer-Token" icon="monitor">

Die Desktop-App verwendet Bearer-JWT-Token für authentifizierten API-Zugriff. Dieser Ablauf ist speziell für Desktop-Clients gedacht, die sich über Talkturo-Benutzersitzungen authentifizieren.

Weitere Informationen finden Sie unter [Authentifizierung](/de/api-reference/authentication) und [Desktop-Authentifizierung](/de/api-reference/desktop).

  </Tab>
</Tabs>

## Antwortformat verstehen

Die meisten Endpunkte geben JSON in einem einheitlichen Format zurück, sodass Sie Erfolg und Misserfolg vorhersehbar behandeln können. Erfolgreiche Antworten geben ein `success`-Flag und Antwortdaten zurück, während fehlgeschlagene Antworten ein `success`-Flag und Fehlerdetails zurückgeben.

### HTTP-Statuscodes

| Status | Bedeutung |
| --- | --- |
| `200` | Anfrage erfolgreich |
| `201` | Ressource erstellt |
| `400` | Ungültige Anfrage |
| `401` | Nicht autorisiert |
| `402` | Ungenügendes Guthaben |
| `403` | Verboten |
| `404` | Nicht gefunden |
| `500` | Serverfehler |

## Ratenlimits

API-Schlüssel sind standardmäßig auf 1000 Anfragen pro Stunde begrenzt. Wenn Sie Hintergrundjobs, Wiederholungen oder Massensynchronisierungen entwickeln, fügen Sie Backoff- und Wiederholungsbehandlung hinzu.
