## Close AI-Endpunkte

Greifen Sie über die Close AI-API auf Dashboard-Analytics, Sitzungsdaten, Prompt-Vorlagen, Verkaufsskripte, Benutzereinstellungen und Desktop-Status zu. Alle Close AI-Endpunkte verwenden Session-Cookie-Authentifizierung. API-Schlüssel werden nicht unterstützt.

<Callout kind="info">

Authentifizieren Sie Anfragen an Close AI-Endpunkte mit einer gültigen Web-Session. Wenn Sie serverseitige Integrationen oder Desktop-Flows erstellen, verwenden Sie stattdessen die entsprechenden Desktop-Endpunkte.

</Callout>

## Endpunktübersicht

| Methode | Pfad | Beschreibung |
| --- | --- | --- |
| `GET` | `/api/close-ai/dashboard` | Dashboard-Analytics abrufen |
| `POST` | `/api/close-ai/dashboard/narrative` | Dashboard-Narrative generieren |
| `GET` | `/api/close-ai/sessions` | Sitzungen auflisten |
| `GET` `PATCH` `DELETE` | `/api/close-ai/sessions/:sessionId` | Sitzung abrufen, umbenennen oder löschen |
| `GET` `POST` | `/api/close-ai/prompts` | Prompt-Vorlagen auflisten oder erstellen |
| `GET` `POST` `PUT` `DELETE` | `/api/close-ai/scripts` | Verkaufsskripte auflisten, erstellen, aktualisieren oder löschen |
| `GET` `PUT` | `/api/close-ai/settings` | Benutzereinstellungen lesen oder aktualisieren |
| `GET` | `/api/close-ai/desktop-status` | Desktop-Status abrufen |

## Dashboard-Narrative generieren

## Sitzungen auflisten

Listen Sie Close AI-Sitzungen des aktuellen Benutzers mit Pagination, Volltextsuche auf dem Titel und optionaler Workspace-Einschränkung auf.

<Request>
```bash
curl -X GET "https://app.talkturo.com/api/close-ai/sessions?limit=50&offset=0&q=acme&account=my-workspace" \
  -H "Cookie: sb-access-token=..."
```
</Request>

<Response>
```json
{
  "sessions": [{
    "id": "uuid",
    "user_id": "uuid",
    "account_id": "uuid | null",
    "title": "Call with Acme Corp",
    "session_type": "listen | ask",
    "started_at": "2026-08-20T10:00:00Z",
    "ended_at": "2026-08-20T10:32:00Z",
    "status": "completed",
    "duration_seconds": 1920,
    "updated_at": "2026-08-20T10:32:05Z"
  }],
  "count": 84
}
```
</Response>

### Abfrageparameter

<ParamField query="limit" param-type="integer" required="false">
Maximale Anzahl zurückgegebener Sitzungen. Standard ist `50`. Der Wert wird auf den Bereich `1` bis `100` begrenzt.
</ParamField>

<ParamField query="offset" param-type="integer" required="false">
Versatz für paginierte Ergebnisse. Standard ist `0`.
</ParamField>

<ParamField query="q" param-type="string" required="false">
Suche nach Sitzungen über einen `ILIKE`-Vergleich auf dem Feld `title`.
</ParamField>

<ParamField query="account" param-type="string" required="false">
Workspace-Slug zur Einschränkung der Ergebnisse. Wenn gesetzt, filtert der Endpunkt nach `account_id = ? OR account_id IS NULL`, damit ältere Sitzungen ohne Workspace-Zuordnung weiterhin sichtbar bleiben.
</ParamField>

### Antwortfelder

<ResponseField name="sessions" field-type="array" required="true">
Paginierte Liste von Sitzungen, die dem authentifizierten Benutzer unterliegen.
</ResponseField>

<ResponseField name="count" field-type="integer" required="true">
Gesamtanzahl der Sitzungen für die aktuelle Abfrage.
</ResponseField>

### Fehlermuster

| Status | Antwort |
| --- | --- |
| `400` | `{ "error": "<supabase message>" }` |

</Response>

## Prompt-Vorlagen auflisten oder erstellen

Verwalten Sie gespeicherte Prompt-Vorlagen für Close AI. Sie können Benutzervorlagen abrufen, nur Templates filtern und neue Standardvorlagen anlegen.

### Vorlagen auflisten

Rufen Sie die Vorlagen des aktuellen Benutzers ab. Mit `templates=true` erhalten Sie nur Template-Presets.

<Request>
```bash
curl -X GET "https://app.talkturo.com/api/close-ai/prompts?templates=true" \
  -H "Cookie: sb-access-token=..."
```
</Request>

<Response>
```json
{
  "presets": [{
    "id": "uuid",
    "user_id": "uuid",
    "title": "Discovery Call",
    "prompt": "You are a...",
    "is_default": true,
    "is_template": false,
    "created_at": "...",
    "updated_at": "..."
  }]
}
```
</Response>

### Abfrageparameter

<ParamField query="templates" param-type="boolean" required="false">
Wenn `true`, gibt der Endpunkt nur Template-Presets mit `is_template = true` zurück. Wenn weggelassen, gibt der Endpunkt alle Presets des Benutzers zurück.
</ParamField>

### Vorlagen erstellen

Erstellen Sie ein neues Prompt-Preset. Wenn Sie `is_default` auf `true` setzen, entfernt der Endpunkt atomar jede andere Standardvorlage des Benutzers.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/close-ai/prompts" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=..." \
  -d '{
    "title": "Discovery Call",
    "prompt": "You are a...",
    "is_default": true,
    "is_template": false
  }'
```
</Request>

<Response>
```json
{
  "preset": {
    "id": "uuid",
    "title": "Discovery Call",
    "prompt": "You are a...",
    "is_default": true,
    "is_template": false
  }
}
```
</Response>

### Body-Parameter

<ParamField body="title" param-type="string" required="true">
Titel der Vorlage. Länge `1` bis `200` Zeichen.
</ParamField>

<ParamField body="prompt" param-type="string" required="true">
Prompt-Inhalt. Länge `1` bis `20000` Zeichen.
</ParamField>

<ParamField body="is_default" param-type="boolean" required="false">
Markiert die Vorlage als Standardvorlage des Benutzers. Wenn `true`, wird jede vorhandene Standardvorlage zuerst entfernt.
</ParamField>

<ParamField body="is_template" param-type="boolean" required="false">
Markiert die Vorlage als Template-Preset.
</ParamField>

### Antwortfelder

<ResponseField name="presets" field-type="array" required="true">
Liste gespeicherter Prompt-Presets.
</ResponseField>

<ResponseField name="preset" field-type="object" required="false">
Neu erstelltes Prompt-Preset in der `POST`-Antwort.
</ResponseField>

### Fehlermuster

| Status | Antwort |
| --- | --- |
| `401` | `{ "error": "unauthorized" }` |
| `400` | `{ "error": "invalid_body", "detail": {} }` |

## Verkaufsskripte auflisten, erstellen, aktualisieren oder löschen

Verwalten Sie Workspace-Verkaufsskripte, die einen Verzweigungs-Node-Graphen in `content` speichern und genau ein aktives Skript pro Workspace unterstützen.

### Skripte auflisten

Rufen Sie alle Skripte eines Workspace ab, sortiert nach zuletzt aktualisiert.

<Request>
```bash
curl -X GET "https://app.talkturo.com/api/close-ai/scripts?account=my-workspace" \
  -H "Cookie: sb-access-token=..."
```
</Request>

<Response>
```json
{
  "scripts": [{
    "id": "uuid",
    "name": "Discovery Script",
    "content": {
      "sections": [],
      "prompts": []
    },
    "is_active": true,
    "updated_at": "..."
  }]
}
```
</Response>

### Abfrageparameter

<ParamField query="account" param-type="string" required="true">
Workspace-Slug. Dieser Parameter ist für `GET` und `POST` erforderlich.
</ParamField>

<ParamField query="id" param-type="string" required="false">
Skript-ID für `DELETE`. Wenn sie fehlt, antwortet der Endpunkt mit `id_required`.
</ParamField>

### Skript erstellen

Erstellen Sie ein neues leeres Skript. Wenn Sie keinen Namen senden, verwendet der Endpunkt `Untitled script`.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/close-ai/scripts?account=my-workspace" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=..." \
  -d '{ "name": "My Script" }'
```
</Request>

<Response>
```json
{
  "script": {
    "id": "uuid",
    "name": "My Script",
    "content": {
      "sections": [],
      "prompts": []
    },
    "is_active": false,
    "updated_at": "..."
  }
}
```
</Response>

### Body-Parameter für `POST`

<ParamField body="name" param-type="string" required="false">
Skriptname. Standard ist `Untitled script`.
</ParamField>

### Skript aktualisieren

Aktualisieren Sie den Namen, den Inhalt und den Aktiv-Status eines vorhandenen Skripts. Wenn Sie `is_active` auf `true` setzen, deaktiviert der Endpunkt zuerst alle anderen Skripte im Workspace.

<Request>
```bash
curl -X PUT "https://app.talkturo.com/api/close-ai/scripts" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=..." \
  -d '{
    "id": "2d7b8c90-4d34-4d55-a1e9-8f4d0c54a4d1",
    "name": "Updated Name",
    "content": {
      "sections": [{
        "id": "s1",
        "name": "Intro",
        "type": "script",
        "content": "Good morning, I am calling from...",
        "position": { "x": 120, "y": 0 },
        "next": [{ "id": "n1", "condition": "Interested", "targetId": "s2" }]
      }],
      "prompts": [{
        "id": "p1",
        "trigger": "price",
        "text": "Handle pricing objection",
        "enabled": true
      }]
    },
    "is_active": true
  }'
```
</Request>

<Response>
```json
{
```

## Benutzereinstellungen lesen oder aktualisieren

Lesen oder speichern Sie benutzerspezifische Analytics-System-Prompts für Close AI.

### Einstellungen lesen

Rufen Sie die aktuellen Einstellungen des Benutzers ab. Wenn noch nichts gespeichert wurde, sind die Felder `null`.

<Request>
```bash
curl -X GET "https://app.talkturo.com/api/close-ai/settings" \
  -H "Cookie: sb-access-token=..."
```
</Request>

<Response>
```json
{
  "analytics_system_prompt": "You are a sales coach...",
  "updated_at": "2026-08-15T09:30:00Z"
}
```
</Response>

### Antwortfelder

<ResponseField name="analytics_system_prompt" field-type="string" required="false">
Aktueller Analytics-System-Prompt des Benutzers. Der Wert ist `null`, wenn keiner gesetzt wurde.
</ResponseField>

<ResponseField name="updated_at" field-type="string" required="false">
Zeitstempel der letzten Aktualisierung. Der Wert ist `null`, wenn noch nie gespeichert wurde.
</ResponseField>

### Einstellungen aktualisieren

Speichern oder leeren Sie den Analytics-System-Prompt des Benutzers. Der Endpunkt verwendet ein Upsert und kann wiederholt sicher aufgerufen werden.

<Request>

```bash
curl -X PUT "https://app.talkturo.com/api/close-ai/settings" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=..." \
  -d '{
    "analytics_system_prompt": "You are a sales coach..."
  }'
```
</Request>

<Response>
```json
{
  "analytics_system_prompt": "You are a sales coach...",
  "updated_at": "2026-08-23T10:15:00Z"
}
```
</Response>

## Authentifizierungsfehler

Close AI-Endpunkte antworten bei fehlender oder abgelaufener Session in der Regel mit `401`. Die genaue Antwortform hängt vom Endpunkt ab.

<ExpandableGroup>
  <Expandable title="Typische 401-Antworten">

  - Dashboard, Narrative, Prompts, Skripte und Einstellungen verwenden meist `{ "error": "unauthorized" }`.
  - Desktop-Status verwendet `{ "ok": false, "reason": "unauthenticated" }`.

  </Expandable>
</ExpandableGroup>

## Workspace-Zugriffsfehler

Workspace-bezogene Endpunkte prüfen zusätzlich zur Session, ob Sie auf den angeforderten Workspace zugreifen dürfen.

<ExpandableGroup>
  <Expandable title="Typische Workspace-Fehler">

  - Fehlender Workspace-Slug führt zu `{ "error": "account_required" }` bei Endpunkten, die einen Workspace benötigen.
  - Nicht vorhandene Workspaces führen zu `{ "error": "workspace_not_found" }`.
  - Fehlende Mitgliedschaft führt zu `{ "error": "workspace_access_denied" }` oder zu einer datenbankspezifischen `403`-Antwort unter RLS.

  </Expandable>
</ExpandableGroup>

## Validierungsfehler

Zod-validierte Endpunkte antworten mit `400`, wenn Body-Daten die erwartete Form nicht erfüllen.

<ExpandableGroup>
  <Expandable title="Typische 400-Antworten">

  - Narrative, Prompts, Skripte und Einstellungen verwenden `{ "error": "invalid_body" }`.
  - Einige Endpunkte ergänzen ein `detail`-Objekt mit Validierungsinformationen.
  - Skript- und andere Endpunkte können zusätzliche spezifische Fehler wie `id_required` zurückgeben.

  </Expandable>
</ExpandableGroup>

## Fehler bei fehlenden Ressourcen

Einzelne Ressourcenendpunkte verwenden `404`, wenn die angeforderte Sitzung, das Skript oder der Workspace nicht existiert.

<ExpandableGroup>
  <Expandable title="Typische 404-Antworten">

  - Sitzungsendpunkte verwenden `{ "error": "not_found" }` für unbekannte Sitzungs-IDs.
  - Workspace-bezogene Endpunkte verwenden `{ "error": "workspace_not_found" }`.
  - Andere Ressourcenendpunkte können eigene kennzeichnungsspezifische `404`-Fehler verwenden.

  </Expandable>
</ExpandableGroup>
