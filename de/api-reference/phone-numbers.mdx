## Telefonnummern mit der Talkturo-Telefonie verwalten

Mit den aktuellen Telefonnummern-Endpunkten suchen Sie verfügbare Rufnummern, kaufen Nummern, listen gekaufte Nummern auf und geben nicht mehr benötigte Nummern frei. Die Endpunkte unterstützen je nach Route die Authentifizierung per API-Schlüssel oder Sitzung.

<Callout kind="info">

Verwenden Sie diese Endpunkte für die Verwaltung von Telefonnummern in Ihrem Account. Wenn Sie Telefonnummern einem Assistant zuweisen oder allgemeine Telephony-Einstellungen verwalten möchten, siehe [Telephony](/de/api-reference/telephony).

</Callout>

## Authentifizierung

Die Such-, Kauf- und Listen-Endpunkte akzeptieren einen gemeinsamen API-Schlüssel oder eine authentifizierte Sitzung:

- `POST /api/phone-numbers/search`
- `POST /api/phone-numbers/purchase`
- `GET /api/phone-numbers/purchase`

Die Freigabe ist ausschließlich sitzungsbasiert und steht nur dem Owner des Accounts zur Verfügung:

- `DELETE /api/phone-numbers/{id}?account={workspaceSlug}`

Der stillgelegte Telnyx-Endpunkt akzeptiert weiterhin Anfragen, führt aber keine Signaturprüfung oder KYC-Verarbeitung mehr aus:

- `POST /api/phone-numbers/telnyx-webhook`

## Endpunktübersicht

| Methode | Pfad | Authentifizierung | Zweck |
| --- | --- | --- | --- |
| `POST` | `/api/phone-numbers/search` | API-Schlüssel oder Sitzung | Verfügbare Telefonnummern anhand von Filtern suchen |
| `POST` | `/api/phone-numbers/purchase` | API-Schlüssel oder Sitzung | Eine verfügbare Telefonnummer kaufen |
| `GET` | `/api/phone-numbers/purchase` | API-Schlüssel oder Sitzung | Gekaufte Telefonnummern auflisten |
| `DELETE` | `/api/phone-numbers/{id}?account={workspaceSlug}` | Sitzung, nur Owner | Eine Telefonnummer unwiderruflich an den Carrier freigeben |
| `POST` | `/api/phone-numbers/telnyx-webhook` | Keine Verarbeitung mehr | Stillgelegten Telnyx-Webhook bestätigen |

## Verfügbare Telefonnummern suchen

Rufen Sie `POST /api/phone-numbers/search` mit einem JSON-Body auf, um verfügbare Telefonnummern nach Land, Nummerntyp, Region, Präfix oder Muster zu suchen. `filters.countryCode` ist erforderlich.

<Request tabs="cURL" default-tab="1">
```bash
curl -X POST "https://deployment-host/api/phone-numbers/search" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_test_example_9xmk7q2r" \
  -d '{
    "filters": {
      "countryCode": "US",
      "numberType": "local",
      "areaCode": "415",
      "locality": "San Francisco",
      "contains": "5018"
    },
    "carrier": "telnyx",
    "provider": "telnyx"
  }'
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "success": true,
  "numbers": [
    "+14155550188",
    "+14155550199"
  ],
  "carrier": "telnyx",
  "provider": "telnyx",
  "verifiedLocalities": [
    "San Francisco"
  ],
  "pricing": {
    "currency": "USD",
    "monthly": 2.0
  },
  "billing": {
    "interval": "monthly"
  },
  "count": 2
}
```
</Response>

## Telefonnummer kaufen

Rufen Sie `POST /api/phone-numbers/purchase` auf, um eine verfügbare Telefonnummer zu kaufen. Der Request-Body muss `phoneNumber` enthalten.

<Request tabs="cURL" default-tab="1">
```bash
curl -X POST "https://deployment-host/api/phone-numbers/purchase" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_test_example_9xmk7q2r" \
  -d '{
    "phoneNumber": "+14155550188",
    "connectionId": "conn_4f8a21c7",
    "provider": "telnyx",
    "carrier": "telnyx",
    "numberType": "local"
  }'
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "phoneNumber": {
    "id": "pn_2f6c9a41",
    "phone_number": "+14155550188",
    "status": "active",
    "is_trial": false,
    "trial_expires_at": null,
    "message": "Phone number purchased successfully"
  },
  "eligibility": {
    "currentCount": 3,
    "maxAllowed": 25,
    "hasSubscription": true,
    "planName": "Growth"
  }
}
```
</Response>

<Callout kind="info">

Wenn Sie eine Sitzung verwenden, ist `teamId` erforderlich. Bei einer API-Schlüssel-Anfrage verwendet der Workspace des API-Schlüssels den zugehörigen Kontext. Sie können diesen Workspace nicht mit `teamId` überschreiben.

</Callout>

### Request-Body

<ParamField body="phoneNumber" param-type="string" required="true">
Die zu kaufende Telefonnummer im internationalen Format.
</ParamField>

<ParamField body="teamId" param-type="string" required="false">
Das Team, dem die Telefonnummer im Sitzungskontext zugeordnet wird. Bei einer Sitzung ist dieses Feld erforderlich. Bei API-Schlüssel-Authentifizierung kann der Workspace des API-Schlüssels nicht überschrieben werden.
</ParamField>

<ParamField body="connectionId" param-type="string" required="false">
Die Verbindung, über die die Telefonnummer bereitgestellt werden soll.
</ParamField>

<ParamField body="provider" param-type="string" required="false">
Der Provider, der für den Kauf verwendet werden soll.
</ParamField>

<ParamField body="carrier" param-type="string" required="false">
Der Carrier, der für den Kauf verwendet werden soll.
</ParamField>

<ParamField body="numberType" param-type="string" required="false">
Der Typ der zu kaufenden Telefonnummer.
</ParamField>

### Antwortfelder

<ResponseField name="phoneNumber" field-type="object" required="true">
Die gekaufte Telefonnummer mit ihrer Kennung, ihrem Status und den Testzeitraumdaten.
</ResponseField>

<ResponseField name="eligibility" field-type="object" required="true">
Die aktuellen Berechtigungs- und Kontingentdaten für den Kauf.
</ResponseField>

#### Felder von `phoneNumber`

<ResponseField name="id" field-type="string" required="true">
Die eindeutige Kennung der Telefonnummer.
</ResponseField>

<ResponseField name="phone_number" field-type="string" required="true">
Die gekaufte Telefonnummer im internationalen Format.
</ResponseField>

<ResponseField name="status" field-type="string" required="true">
Der aktuelle Status der Telefonnummer.
</ResponseField>

<ResponseField name="is_trial" field-type="boolean" required="true">

</ResponseField>

<ResponseField name="trial_expires_at" field-type="string or null" required="true">
Der Zeitpunkt, zu dem ein Testzeitraum endet, oder `null`, wenn kein Testzeitraum gilt.
</ResponseField>

<ResponseField name="message" field-type="string" required="true">
Eine Nachricht zum Ergebnis des Kaufs.
</ResponseField>

#### Felder von `eligibility`

<ResponseField name="currentCount" field-type="integer" required="true">
Anzahl der bereits gekauften Telefonnummern.
</ResponseField>

<ResponseField name="maxAllowed" field-type="integer" required="true">
Maximal zulässige Anzahl gekaufter Telefonnummern.
</ResponseField>

<ResponseField name="hasSubscription" field-type="boolean" required="true">
Gibt an, ob für den Account ein aktives Abonnement vorhanden ist.
</ResponseField>

<ResponseField name="planName" field-type="string" required="true">
Name des für die Berechtigung verwendeten Plans.
</ResponseField>

## Gekaufte Telefonnummern auflisten

Rufen Sie `GET /api/phone-numbers/purchase` auf, um die gekauften Telefonnummern des authentifizierten API-Schlüssels oder der authentifizierten Sitzung aufzulisten.

<Request tabs="cURL" default-tab="1">
```bash
curl -X GET "https://deployment-host/api/phone-numbers/purchase" \
  -H "Authorization: Bearer tk_test_example_9xmk7q2r"
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "success": true,
  "phoneNumbers": [
    {
      "id": "pn_2f6c9a41",
      "phone_number": "+14155550188",
      "status": "active"
    }
  ]
}
```
</Response>

## Telefonnummer freigeben

Rufen Sie `DELETE /api/phone-numbers/{id}?account={workspaceSlug}` auf, um eine Telefonnummer aus dem angegebenen Workspace freizugeben. Die Route akzeptiert ausschließlich eine Sitzung und steht nur dem Owner zur Verfügung.

<Callout kind="danger">

Die Freigabe ist unwiderruflich. Die Telefonnummer wird an den Carrier zurückgegeben und kann anschließend erneut vergeben werden.

</Callout>

<Request tabs="cURL" default-tab="1">
```bash
curl -X DELETE "https://deployment-host/api/phone-numbers/pn_2f6c9a41?account=acme-support" \
  -H "Cookie: sb-session=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example"
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "success": true,
  "phoneNumber": "+14155550188"
}
```
</Response>

### Pfad- und Query-Parameter

<ParamField path="id" param-type="string" required="true">
Die eindeutige Kennung der freizugebenden Telefonnummer.
</ParamField>

<ParamField query="account" param-type="string" required="true">
Der Workspace-Slug, aus dem die Telefonnummer freigegeben wird.
</ParamField>

### Antwortfelder

<ResponseField name="success" field-type="boolean" required="true">
Gibt an, ob die Telefonnummer erfolgreich freigegeben wurde.
</ResponseField>

<ResponseField name="phoneNumber" field-type="string" required="true">
Die freigegebene Telefonnummer.
</ResponseField>

### Fehlerstatus

| Status | Bedeutung |
| --- | --- |
| `400` | Die Anfrage enthält ungültige Parameter. |
| `401` | Die Sitzung fehlt oder ist ungültig. |
| `403` | Die Sitzung gehört nicht dem Owner des Accounts. |
| `404` | Telefonnummer oder Workspace wurde nicht gefunden. |
| `502` | Der Carrier konnte die Freigabe nicht bestätigen. |

## Stillgelegter Telnyx-Webhook

`POST /api/phone-numbers/telnyx-webhook` ist stillgelegt. Die Route führt keine ED25519-Signaturprüfung und keine KYC- oder Compliance-Verarbeitung mehr aus.

<Request tabs="HTTP" default-tab="1">
```bash
curl -X POST "https://deployment-host/api/phone-numbers/telnyx-webhook" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "payload": {
        "event_type": "phone_number.updated"
      }
    }
  }'
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "received": true,
  "retired": true
}
```
</Response>
