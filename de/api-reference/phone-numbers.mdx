## Telefonnummern mit der Talkturo-Telefonie verwalten

Mit den Endpunkten für Telefonnummern suchen Sie verfügbare Rufnummern, kaufen neue Nummern, rufen vorhandene Nummern ab, geben nicht mehr benötigte Nummern frei und verarbeiten Carrier-Webhooks für KYC- und Compliance-Statusänderungen. Diese Endpunkte decken den vollständigen Lebenszyklus einer Telefonnummer innerhalb der Talkturo-Telefonie ab.

Für die Endpunkte zum Suchen, Kaufen und Abrufen können Sie entweder einen API-Schlüssel oder eine authentifizierte Sitzung verwenden. Der Freigabe-Endpunkt erfordert eine authentifizierte Sitzung des Workspace-Eigentümers. Die beiden Webhook-Endpunkte bilden die Ausnahme, da sie von externen Carriern aufgerufen werden.

<Callout kind="info">

Verwenden Sie diese Endpunkte für die Verwaltung von Telefonnummern in Ihrem Account. Wenn Sie Telefonnummern einem Assistant zuweisen oder allgemeine Telephony-Einstellungen verwalten möchten, siehe [Telephony](/de/api-reference/telephony).

</Callout>

## Authentifizierung

Die Endpunkte für Suche, Kauf und Abruf unterstützen duale Authentifizierung. Verwenden Sie entweder einen API-Schlüssel im Header `Authorization: Bearer tk_live_...` oder ein authentifiziertes Session-Cookie. Der Freigabe-Endpunkt erfordert ein Session-Cookie, authentifiziert durch den Workspace-Eigentümer. Die beiden Webhook-Endpunkte bilden die Ausnahme, da sie von Carriern aufgerufen werden.

## Endpunktübersicht

| Methode | Pfad | Authentifizierung | Zweck |
| --- | --- | --- | --- |
| `POST` | `/api/phone-numbers/search` | API-Schlüssel oder Session | Verfügbare Telefonnummern beim Carrier suchen |
| `POST` | `/api/phone-numbers/purchase` | API-Schlüssel oder Session | Eine Telefonnummer kaufen und bereitstellen |
| `GET` | `/api/phone-numbers/{id}` | API-Schlüssel oder Session | Eine bestimmte Telefonnummer abrufen |
| `DELETE` | `/api/phone-numbers/{id}` | Session (nur Eigentümer) | Eine Telefonnummer freigeben |
| `POST` | `/api/phone-numbers/telnyx-webhook` | ED25519-Signatur | KYC- und Compliance-Status von Telnyx verarbeiten |
| `POST` | `/api/phone-numbers/twilio-webhook` | Keine direkte Signaturprüfung | Bundle-Status von Twilio verarbeiten |

## Verfügbare Telefonnummern suchen

Rufen Sie `POST /api/phone-numbers/search` auf, um freie Telefonnummern anhand von Land, Nummerntyp und carrier-spezifischen Filtern zu finden.

<Request tabs="cURL" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/search" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r5s8d4m1n6p3v7y2z" \
  -d '{
    "filters": {
      "countryCode": "US",
      "numberType": "local",
      "areaCode": "415",
      "features": ["sms", "voice"],
      "limit": 2
    },
    "teamId": "team_7c9a2b11",
    "carrier": "talkturo"
  }'
```
</Request>

### Request-Body

<ParamField body="filters" param-type="object" required="true">
Enthält die Suchfilter für verfügbare Telefonnummern. Das Objekt muss mindestens `filters.countryCode` enthalten.
</ParamField>

<ParamField body="filters.countryCode" param-type="string" required="true">
ISO-3166-1-Alpha-2-Ländercode, nach dem verfügbare Nummern gesucht werden.
</ParamField>

<ParamField body="filters.numberType" param-type="string" required="false" enum="local,mobile,toll-free">
Typ der Telefonnummer. Standard ist `local`.
</ParamField>

<ParamField body="filters.areaCode" param-type="string" required="false">
Carrier-spezifischer Filter für die Vorwahl.
</ParamField>

<ParamField body="filters.features" param-type="array" required="false">
Carrier-spezifischer Filter für gewünschte Funktionen wie `sms` oder `voice`.
</ParamField>

<ParamField body="filters.limit" param-type="integer" required="false">
Carrier-spezifischer Filter, der die Anzahl der zurückgegebenen Ergebnisse begrenzt.
</ParamField>

<ParamField body="teamId" param-type="string" required="false">
Team-Kennung für KYC-Länder-Prüfung und Abrechnung.
</ParamField>

<ParamField body="carrier" param-type="string" required="false">
Auswahl des Carriers, zum Beispiel `talkturo`.
</ParamField>

<ParamField body="provider" param-type="string" required="false">
Legacy-Alias für `carrier`. Unterstützt zum Beispiel `talkturo` oder `twilio`.
</ParamField>

### Antwortfelder

<ResponseField name="success" field-type="boolean" required="true">
Gibt an, ob die Suche erfolgreich war.
</ResponseField>

<ResponseField name="count" field-type="integer" required="true">
Anzahl der gefundenen Telefonnummern im Ergebnis.
</ResponseField>

<ResponseField name="carrier" field-type="string" required="false">
Carrier, der für die Suche verwendet wurde.
</ResponseField>

<ResponseField name="provider" field-type="string" required="false">
Aufgelöster Provider-Name. Dieses Feld bleibt aus Kompatibilitätsgründen erhalten.
</ResponseField>

<ResponseField name="billing" field-type="string" required="false">
Abrechnungsmodus für die gefundenen Nummern. Mögliche Werte sind `credits`, `exempt` oder `byoa`.
</ResponseField>

<ResponseField name="verifiedLocalities" field-type="array" required="false">
Liste der verifizierten Orte, die für lokale Compliance- oder KYC-Prüfungen relevant sind.
</ResponseField>

<ResponseField name="pricing" field-type="object" required="false">
Preisangaben für Kauf und laufende Nutzung der gefundenen Nummern.
</ResponseField>

<ResponseField name="numbers" field-type="array" required="true">
Liste der verfügbaren Telefonnummern, die den angegebenen Filtern entsprechen.
</ResponseField>

### Fehlerantworten

| Status | Bedeutung |
| --- | --- |
| `400` | `filters.countryCode` fehlt im Request-Body. |
| `403` | Das angegebene Land erfordert eine abgeschlossene KYC-Verifizierung. |
| `409` | Der angeforderte Twilio-Carrier ist nicht eingerichtet. |
| `502` | Die Carrier-API hat einen Fehler zurückgegeben oder war nicht erreichbar. |

## Telefonnummer kaufen

Rufen Sie `POST /api/phone-numbers/purchase` auf, um eine verfügbare Telefonnummer einem Account zuzuordnen und zu provisionieren.

<Request tabs="cURL" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/purchase" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r5s8d4m1n6p3v7y2z" \
  -d '{
    "phoneNumber": "+14155550188",
    "teamId": "team_7c9a2b11",
    "connectionId": "fqdn_conn_4a8d2c9e",
    "carrier": "talkturo",
    "numberType": "local",
```

### Fehlerantworten

| Status | Bedeutung |
| --- | --- |
| `400` | Der Request-Body ist ungültig oder unvollständig. |
| `402` | Das verfügbare Guthaben reicht für den Kauf nicht aus. |

## Telefonnummer freigeben

Rufen Sie `DELETE /api/phone-numbers/{id}` auf, um eine Telefonnummer aus Ihrem Account freizugeben. Übergeben Sie den Workspace-Slug als Query-Parameter `account`.

<Callout kind="alert">

Dieser Endpunkt akzeptiert nur Session-Cookie-Authentifizierung und erfordert eine Sitzung des Workspace-Eigentümers.

</Callout>

<Request tabs="cURL" default-tab="1">
```bash
curl -X DELETE "https://api.talkturo.com/api/phone-numbers/pn_2f6c9a41?account=acme-support" \
  -H "Cookie: sb-session=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example"
```
</Request>

<Response tabs="200,400,403,404,502" default-tab="1">
```json
{
  "success": true,
  "phoneNumber": "+14155550182"
}
```

```json

  "success": false,
  "error": "account is required"
}
```

```json
{
  "success": false,
  "error": "Only workspace owners can release phone numbers"
}
```

```json
{
  "success": false,
  "error": "Phone number not found"
}
```

```json
{
  "success": false,
  "error": "Carrier release failed"
}
```
</Response>

### Pfadparameter

<ParamField path="id" param-type="string" required="true">
Die eindeutige Kennung der freizugebenden Telefonnummer.
</ParamField>

### Query-Parameter

<ParamField query="account" param-type="string" required="true">
Workspace-Slug, aus dem die Telefonnummer freigegeben wird.
</ParamField>

### Antwortfelder

<ResponseField name="success" field-type="boolean" required="true">
Gibt an, ob die Telefonnummer erfolgreich freigegeben wurde.
</ResponseField>

<ResponseField name="phoneNumber" field-type="string" required="true">
Die freigegebene Telefonnummer im E.164-Format.

### Fehlerantworten

| Status | Bedeutung |
| --- | --- |

## Telnyx-Webhook für KYC-Status

`POST /api/phone-numbers/telnyx-webhook` verarbeitet Statusaktualisierungen von Telnyx für KYC- und Compliance-Prüfungen.

<Callout kind="alert">

Dieser Endpunkt prüft eine ED25519-Signatur gegen den konfigurierten öffentlichen Schlüssel aus `TELNYX_PUBLIC_KEY`. Wenn der Schlüssel nicht konfiguriert ist, antwortet der Endpunkt mit `503`. Bei ungültiger Signatur antwortet der Endpunkt mit `400`. Nach erfolgreicher Prüfung verarbeitet der Endpunkt das rohe Event-JSON, synchronisiert den Status der `requirement_group_id` und gibt anschließend immer `200` zurück, damit Telnyx keine Wiederholungsversuche startet.

</Callout>

<Request tabs="HTTP" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/telnyx-webhook" \
  -H "Content-Type: application/json" \
  -H "Telnyx-Signature-Ed25519: 4f8f7f4f2fb1d5e8a03ef9b4df2ac7f1a0d75c2d6d1f2e8c9a3e7b5f4d2c1a9e" \
  -H "Telnyx-Timestamp: 1731002201" \
  -d '{
    "data": {
      "payload": {
        "requirement_group_id": "rg_7c9a2b11"
      }
    }
  }'
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "received": true,
  "status": "approved",
  "updated": true,
  "matchedRequest": true
}
```
</Response>

## Twilio-Webhook für Bundle-Status

`POST /api/phone-numbers/twilio-webhook` verarbeitet Statusaktualisierungen von Twilio für Compliance-Bundles.

<Callout kind="info">

Dieser Endpunkt vertraut dem eingehenden Statusfeld nicht direkt. Stattdessen liest er `BundleSID`, `BundleSid` oder `bundle_sid` aus dem Formular und ruft den tatsächlichen Status erneut über die Twilio-API ab. Der Endpunkt gibt danach immer `200` zurück, damit Twilio keine unnötigen Wiederholungsversuche sendet.

</Callout>

<Request tabs="HTTP" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/twilio-webhook" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "BundleSID=BU7f3b0d9c5a1e44e6a8c2f11d9a7b3c4"
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "received": true,
  "status": "in_review",
  "matchedRequest": true
}
```
</Response>
