## Telefonnummern mit der Talkturo-Telefonie verwalten

Mit den Endpunkten für Telefonnummern suchen Sie verfügbare Rufnummern, kaufen neue Nummern, rufen vorhandene Nummern ab, geben nicht mehr benötigte Nummern frei und verarbeiten Carrier-Webhooks für KYC- und Compliance-Statusänderungen. Diese Endpunkte decken den vollständigen Lebenszyklus einer Telefonnummer innerhalb der Talkturo-Telefonie ab.

Die Such- und Kauf-Endpunkte akzeptieren eine authentifizierte Sitzung oder einen API-Key. `GET /api/phone-numbers/{id}` und `DELETE /api/phone-numbers/{id}` erfordern weiterhin eine authentifizierte Sitzung per Session-Cookie. Die beiden Webhook-Endpunkte bilden die Ausnahme, da sie von externen Carriern aufgerufen werden. `GET /api/phone-numbers/purchase` verwendet kein `withApiAuth` und erwartet nur die angegebene Workspace-ID.

<Callout kind="info">

Verwenden Sie diese Endpunkte für die Verwaltung von Telefonnummern in Ihrem Account. Wenn Sie Telefonnummern einem Assistant zuweisen oder allgemeine Telephony-Einstellungen verwalten möchten, siehe [Telephony](/de/api-reference/telephony).

</Callout>

## Authentifizierung

Die folgenden Endpunkte akzeptieren Session-Cookie oder API-Key:

- `POST /api/phone-numbers/search`
- `POST /api/phone-numbers/purchase`

Die folgenden Endpunkte erfordern Session-Cookie-Authentifizierung:

- `GET /api/phone-numbers/{id}`
- `DELETE /api/phone-numbers/{id}`

Der folgende Endpunkt verwendet kein `withApiAuth`:

- `GET /api/phone-numbers/purchase`

Die folgenden Webhook-Endpunkte akzeptieren Anfragen von Carriern und verwenden kein Session-Cookie:

- `POST /api/phone-numbers/telnyx-webhook`
- `POST /api/phone-numbers/twilio-webhook`

## Endpunktübersicht

| Methode | Pfad | Authentifizierung | Zweck |
| --- | --- | --- | --- |
| `POST` | `/api/phone-numbers/search` | Session-Cookie oder API-Key | Verfügbare Telefonnummern beim Carrier suchen |
| `POST` | `/api/phone-numbers/purchase` | Session-Cookie oder API-Key | Eine Telefonnummer kaufen und bereitstellen |
| `GET` | `/api/phone-numbers/purchase` | Keine | Gekaufte Telefonnummern für ein Workspace abrufen |
| `GET` | `/api/phone-numbers/{id}` | Session-Cookie | Eine bestimmte Telefonnummer abrufen |
| `DELETE` | `/api/phone-numbers/{id}` | Session-Cookie | Eine Telefonnummer freigeben |
| `POST` | `/api/phone-numbers/telnyx-webhook` | ED25519-Signatur | KYC- und Compliance-Status von Telnyx verarbeiten |
| `POST` | `/api/phone-numbers/twilio-webhook` | Keine direkte Signaturprüfung | Bundle-Status von Twilio verarbeiten |

## Verfügbare Telefonnummern suchen

Rufen Sie `POST /api/phone-numbers/search` auf, um freie Telefonnummern anhand von Land, Nummerntyp, Vorwahl und Carrier-Kontext zu finden. Die Anfrage verwendet einen JSON-Body statt Query-Parametern.

<Request tabs="cURL" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/search" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tturo_example_9xmk7q2r" \
  -d '{
    "filters": {
      "countryCode": "US",
      "numberType": "local",
      "areaCode": "415"
    },
    "teamId": "7c6c6d18-8d5c-4d9d-95a7-44f0e4f72b31",

  }'
```

### Request-Body

<ParamField body="filters" param-type="object" required="true">
Enthält die Suchkriterien für verfügbare Telefonnummern.
</ParamField>

</ParamField>

<ParamField body="provider" param-type="string" required="false">
Legacy-Alias für `carrier`.
</ParamField>

### Fehlercodes

| Status | Bedeutung |
| --- | --- |
| `400` | `filters.countryCode` fehlt oder die Anfrage ist syntaktisch ungültig |
| `403` | KYC oder andere Berechtigungsvoraussetzungen verhindern die Suche |
| `409` | Der angeforderte Carrier ist nicht verfügbar |
| `502` | Der Upstream-Carrier hat die Suche nicht erfolgreich verarbeitet |

## Telefonnummer kaufen

Rufen Sie `POST /api/phone-numbers/purchase` auf, um eine verfügbare Telefonnummer einem Workspace zuzuordnen und zu provisionieren. Bei Session-Authentifizierung ist `teamId` erforderlich. Bei API-Key-Authentifizierung kann der Endpunkt auf `auth.accountId` zurückfallen.

<Request tabs="cURL" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/purchase" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tturo_example_9xmk7q2r" \
  -d '{
    "phoneNumber": "+14155550188",
    "teamId": "7c6c6d18-8d5c-4d9d-95a7-44f0e4f72b31",
    "carrier": "talkturo_1",
    "numberType": "local",
    "region": {
      "state": "CA",
      "locality": "San Francisco",
      "rateCenter": "SNFC CZN01"
    }
  }'
```
</Request>

| Status | Bedeutung |
| --- | --- |
| `400` | Erforderliche Parameter fehlen oder das Request-Format ist ungültig |

## Telnyx-Webhook für KYC-Status

`POST /api/phone-numbers/telnyx-webhook` verarbeitet Statusaktualisierungen von Telnyx für KYC- und Compliance-Prüfungen.

<Callout kind="alert">

Dieser Endpunkt prüft eine ED25519-Signatur gegen den konfigurierten öffentlichen Schlüssel aus `TELNYX_PUBLIC_KEY`. Wenn der Schlüssel nicht konfiguriert ist, antwortet der Endpunkt mit `503`. Bei ungültiger Signatur antwortet der Endpunkt mit `400`. Nach erfolgreicher Prüfung verarbeitet der Endpunkt das rohe Event-JSON, synchronisiert den Status der `requirement_group_id` und gibt anschließend immer `200` zurück, damit Telnyx keine Wiederholungsversuche startet.

</Callout>

<Request tabs="HTTP" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/telnyx-webhook" \
  -H "Content-Type: application/json" \
  -H "Telnyx-Signature-Ed25519: 4f8f7f4f2fb1d5e8a03ef9b4df2ac7f1a0d75c2d6d1f2e8c9a3e7b5f4d2c1a9e" \
  -H "Telnyx-Timestamp: 1731002201" \
  -d '{
    "data": {
      "payload": {
        "requirement_group_id": "rg_7c9a2b11"
      }
    }
  }'
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "received": true,
  "status": "approved",
  "updated": true,
  "matchedRequest": true
}
```
</Response>

## Twilio-Webhook für Bundle-Status

`POST /api/phone-numbers/twilio-webhook` verarbeitet Statusaktualisierungen von Twilio für Compliance-Bundles.

<Callout kind="info">

Dieser Endpunkt vertraut dem eingehenden Statusfeld nicht direkt. Stattdessen liest er `BundleSID`, `BundleSid` oder `bundle_sid` aus dem Formular und ruft den tatsächlichen Status erneut über die Twilio-API ab. Der Endpunkt gibt danach immer `200` zurück, damit Twilio keine unnötigen Wiederholungsversuche sendet.

</Callout>

<Request tabs="HTTP" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/phone-numbers/twilio-webhook" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "BundleSID=BU7f3b0d9c5a1e44e6a8c2f11d9a7b3c4"
```
</Request>

<Response tabs="200" default-tab="1">
```json
{
  "received": true,
  "status": "in_review",
  "matchedRequest": true
}
```
</Response>
