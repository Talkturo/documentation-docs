## Endpunkte für Nutzung und Verbrauch

Lesen Sie aktuelle Monatslimits pro Account aus und protokollieren Sie Sprachnutzung für Desktop-Sitzungen. Diese Endpunkte decken zwei unterschiedliche Fälle ab: Verbrauch anzeigen und Voice-Ereignisse erfassen.

<Callout kind="info">

`GET /api/usage/current` akzeptiert API-Key- oder Session-Authentifizierung. `POST /api/usage/voice` akzeptiert ein Desktop-Token und protokolliert Nutzung nach dem Best-Effort-Prinzip.

</Callout>

### GET /api/usage/current

Rufen Sie die aktuelle Monatsnutzung für einen Account ab. Die Antwort fasst Limits, bisherigen Verbrauch, verbleibende Kontingente, Prozentwerte und Guthabeninformationen zusammen.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X GET "https://api.talkturo.com/api/usage/current?accountId=acc_7f3k2m9q" \
  -H "Authorization: Bearer dkai_example_9xmk7q2r" \
  -H "Accept: application/json"
```

```javascript
const response = await fetch("https://api.talkturo.com/api/usage/current?accountId=acc_7f3k2m9q", {
  method: "GET",
  headers: {
    "Authorization": "Bearer dkai_example_9xmk7q2r",
    "Accept": "application/json"
  }
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200,400,401">
```json
{
  "limits": {
    "minutes": 5000,
    "sessions": 250
  },
  "usage": {
    "minutes": 1840,
    "sessions": 96
  },
  "remaining": {
    "minutes": 3160,
    "sessions": 154
  },
  "percentages": {
    "minutes": 36.8,
    "sessions": 38.4
  },
  "credit_info": {
    "balance": 120.5,
    "currency": "EUR"
  }
}
```

```json
{
  "error": "accountId is required"
}
```

```json
{
  "error": "Unauthorized"
}
```
</Response>

#### Authentifizierung

Verwenden Sie für diesen Endpunkt entweder einen API-Key oder eine aktive Session. Der Endpunkt ruft intern die RPCs `get_account_limits` und `get_current_month_usage` auf.

#### Query-Parameter

<ParamField query="accountId" param-type="string" required="true">
Die eindeutige Account-ID, für die die aktuelle Monatsnutzung berechnet werden soll.
</ParamField>

#### Antwortfelder

<ResponseField name="limits" field-type="object" required="true">
Monatliche Limits für den Account.
</ResponseField>

<ResponseField name="usage" field-type="object" required="true">
Bisher im aktuellen Monat verbrauchte Werte.
</ResponseField>

<ResponseField name="remaining" field-type="object" required="true">
Verbleibende Kontingente für den laufenden Monat.
</ResponseField>

<ResponseField name="percentages" field-type="object" required="true">
Prozentuale Auslastung der verfügbaren Limits.
</ResponseField>

<ResponseField name="credit_info" field-type="object" required="true">
Guthabenbezogene Informationen, die zusammen mit den Nutzungsdaten zurückgegeben werden.
</ResponseField>

### POST /api/usage/voice

Protokollieren Sie die Dauer einer Voice-Verbindung zusammen mit Provider- und Modellinformationen. Dieser Endpunkt ist für Desktop-Verbindungen gedacht und arbeitet nach dem Best-Effort-Prinzip, sodass fehlgeschlagene Logs nicht den Hauptablauf blockieren sollten.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/usage/voice" \
  -H "Authorization: Bearer dtok_example_4mz8pq1n" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "connectionId": "conn_8ab42f91c7",
    "durationSeconds": 420,
    "provider": "elevenlabs",
    "model": "eleven_flash_v2_5",
    "userEmail": "jane.chen@acme.com"
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/usage/voice", {
  method: "POST",
  headers: {
    "Authorization": "Bearer dtok_example_4mz8pq1n",
    "Content-Type": "application/json",
    "Accept": "application/json"
  },
  body: JSON.stringify({
    connectionId: "conn_8ab42f91c7",
    durationSeconds: 420,
    provider: "elevenlabs",
    model: "eleven_flash_v2_5",
    userEmail: "jane.chen@acme.com"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200,401">
```json
{
  "success": true
}
```

```json
{
  "error": "Unauthorized"
}
```
</Response>

#### Authentifizierung

Senden Sie für diesen Endpunkt ein Desktop-Token im `Authorization`-Header. Verwenden Sie ihn für die serverseitige Erfassung von Voice-Verbrauch aus Desktop-Sitzungen.

#### Request-Body

<ParamField body="connectionId" param-type="string" required="true">
Die Kennung der Voice-Verbindung, die protokolliert werden soll.
</ParamField>

<ParamField body="durationSeconds" param-type="number" required="true">
Die Dauer der Verbindung in Sekunden.
</ParamField>

<ParamField body="provider" param-type="string" required="true">
Der verwendete Voice-Provider.
</ParamField>

<ParamField body="model" param-type="string" required="true">
Das verwendete Voice-Modell.
</ParamField>

<ParamField body="userEmail" param-type="string" required="true">
Die E-Mail-Adresse des Benutzers, dem die Nutzung zugeordnet werden soll.
</ParamField>

#### Verhalten

Der Endpunkt protokolliert Voice-Nutzung bestmöglich, statt den Aufrufer bei einem Logging-Problem hart zu blockieren. Verwenden Sie ihn für Telemetrie und Verbrauchserfassung, nicht als Bestätigungsmechanismus für abgeschlossene Audioverarbeitung.

<Callout kind="tip">

Prüfen Sie den Endpunkt `GET /api/usage/current`, um die aggregierten Auswirkungen protokollierter Voice-Nutzung im aktuellen Monat abzurufen.

</Callout>
