## CRM-Kampagnen für ausgehende Anrufe verwalten

Mit den CRM-Kampagnen-Endpunkten erstellen, filtern und verwalten Sie ausgehende Anrufkampagnen in Talkturo. Sie können Kampagnen anlegen, einzelne Kampagnen abrufen, Kontakte zuordnen, Statusänderungen steuern und Kampagnen weich löschen.

<Callout kind="info">

`GET /api/crm/campaigns` und `POST /api/crm/campaigns` akzeptieren entweder API-Schlüssel oder Sitzungscookies. `GET /api/crm/campaigns/[id]`, `PUT /api/crm/campaigns/[id]` und `DELETE /api/crm/campaigns/[id]` erfordern eine angemeldete Talkturo-Sitzung per Session-Cookie.

</Callout>

## Endpunktübersicht

| Methode | Pfad | Zweck |
| --- | --- | --- |
| `GET` | `/api/crm/campaigns` | Kampagnen auflisten |
| `POST` | `/api/crm/campaigns` | Kampagne erstellen |
| `GET` | `/api/crm/campaigns/[id]` | Kampagne abrufen |
| `PUT` | `/api/crm/campaigns/[id]` | Kampagne aktualisieren oder Status ändern |
| `DELETE` | `/api/crm/campaigns/[id]` | Kampagne weich löschen |
| `GET` | `/api/crm/campaigns/[id]/contacts` | Kontakte einer Kampagne auflisten |
| `POST` | `/api/crm/campaigns/[id]/contacts` | Kontakte zu einer Kampagne hinzufügen |

## Kampagnen auflisten

Listen Sie Kampagnen gefiltert nach Team, Status, Assistent oder Kontaktzustand auf. Die Antwort verwendet Offset-Paginierung mit `count`, `limit` und `offset`.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl "https://app.talkturo.com/api/crm/campaigns?status=running&includeContactStats=true&limit=20&offset=0" \
  -H "Authorization: Bearer tk_example_9xmk7q2r"
```

```javascript
const params = new URLSearchParams({
  status: "running",
  includeContactStats: "true",
  limit: "20",
  offset: "0"
});

const response = await fetch(`https://app.talkturo.com/api/crm/campaigns?${params.toString()}`, {
  headers: {
    Authorization: "Bearer tk_example_9xmk7q2r"
  }
});

const campaigns = await response.json();
console.log(campaigns);
```
</Request>

### Query-Parameter

<ParamField query="teamId" param-type="string" required="false">
Filtert Kampagnen auf ein bestimmtes Team. Wenn Sie diesen Wert nicht übergeben, verwendet der Endpunkt den Kontext der authentifizierten Anfrage.
</ParamField>

<ParamField query="status" param-type="string" required="false" enum="draft,scheduled,running,paused,completed,cancelled">
Gibt nur Kampagnen mit genau diesem Status zurück.
</ParamField>

<ParamField query="assistantId" param-type="string" required="false">
Filtert Kampagnen nach der zugewiesenen Assistenten-ID.
</ParamField>

<ParamField query="deleted" param-type="string" required="false" enum="exclude,include,only">
Steuert, ob weich gelöschte Kampagnen ausgeschlossen, eingeschlossen oder ausschließlich zurückgegeben werden. Standardwert ist `exclude`.
</ParamField>

<ParamField query="contactFilter" param-type="string" required="false" enum="voicemail,awaiting_retry,answered,no_answer,busy,error">
Filtert Kampagnen anhand eines Kontakt- oder Anrufergebnisses vor.
</ParamField>

<ParamField query="includeContactStats" param-type="string" required="false" enum="1,true">
Erweitert jedes Kampagnenobjekt um `contact_stats` mit aggregierten Werten wie `voicemail` und `awaiting_retry`.
</ParamField>

<ParamField query="limit" param-type="integer" required="false">
Maximale Anzahl zurückgegebener Kampagnen. Standardwert ist `50`.
</ParamField>

<ParamField query="offset" param-type="integer" required="false">
Anzahl der zu überspringenden Datensätze. Standardwert ist `0`.
</ParamField>

### Antwortsfelder

<ResponseField name="count" field-type="number">
Anzahl der in dieser Antwort enthaltenen Kampagnen.
</ResponseField>

<ResponseField name="limit" field-type="number">
Angewendetes Limit für die aktuelle Abfrage.
</ResponseField>

<ResponseField name="offset" field-type="number">
Angewendeter Offset für die aktuelle Abfrage.
</ResponseField>

<ResponseField name="campaigns" field-type="array">
Liste der Kampagnen, die den übergebenen Filtern entsprechen.
</ResponseField>

## Kampagne erstellen

Erstellen Sie eine Kampagne mit CamelCase-Feldern im Request-Body. Wenn Sie `scheduledStartAt` setzen, legt die API die Kampagne im Status `scheduled` an. Ohne diesen Wert startet die Kampagne als `draft`.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/crm/campaigns" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_example_9xmk7q2r" \
  -d '{
    "teamId": "team_7b31aa92",
    "assistantId": "asst_7f3d2c91",
    "companyId": "co_52bc9d18",
    "fromNumberIds": ["pn_4d0912aa", "pn_9981bc21"],
    "name": "Q3 Renewal Outreach",
    "description": "Bestandskunden vor Vertragsverlängerung anrufen",
    "scheduledStartAt": "2025-07-20T07:00:00.000Z",
    "callWindowStart": "09:00",
    "callWindowEnd": "17:00",
    "callWindowTimezone": "Europe/Berlin",
    "maxConcurrentCalls": 4,
    "maxAttemptsPerContact": 3,
    "retryDelayMinutes": 30,
    "settings": {
      "voicemailDetectionEnabled": true,
      "unavailableAction": "retry"
    },
    "noAutoComplete": false,
    "webhookEnabled": true,
    "webhookUrl": "https://ops.northstar-industries.com/talkturo/webhooks/campaigns",
    "webhookSecret": "whsec_example_7f3k29ab",
    "webhookEvents": ["campaign.started", "campaign.completed", "call.failed"]
  }'
```

### Request-Body

<ParamField body="teamId" param-type="string" required="false">
Team-ID für die Kampagne. Dieser Wert ist nur erforderlich, wenn der Teamkontext nicht aus der authentifizierten Anfrage abgeleitet werden kann.
</ParamField>

<ParamField body="assistantId" param-type="string" required="true">
ID eines outbound-fähigen Assistenten, der die Anrufe für diese Kampagne ausführt.
</ParamField>

<ParamField body="companyId" param-type="string" required="true">
ID des Unternehmens, zu dem die Kampagne gehört.
</ParamField>

<ParamField body="fromNumberIds" param-type="array" required="true">
Array mit UUIDs der ausgehenden Rufnummern. Das Array darf leer sein, wenn die Standard- oder Demo-Nummer verwendet werden soll.
</ParamField>

<ParamField body="name" param-type="string" required="true">
Anzeigename der Kampagne.
</ParamField>

<ParamField body="description" param-type="string" required="false">
Freitextbeschreibung der Kampagne.
</ParamField>

<ParamField body="scheduledStartAt" param-type="string" required="false">
Geplanter Startzeitpunkt im ISO-8601-Format. Wenn gesetzt, erhält die Kampagne den Status `scheduled`.
</ParamField>

<ParamField body="callWindowStart" param-type="string" required="false">
Beginn des Anruffensters im Format `HH:MM`.
</ParamField>

<ParamField body="callWindowEnd" param-type="string" required="false">
Ende des Anruffensters im Format `HH:MM`.
</ParamField>

<ParamField body="callWindowTimezone" param-type="string" required="false">
IANA-Zeitzone für das Anruffenster, zum Beispiel `Europe/Berlin`.
</ParamField>

<ParamField body="maxConcurrentCalls" param-type="integer" required="false">
Maximale Anzahl gleichzeitiger Anrufe für diese Kampagne.
</ParamField>

<ParamField body="maxAttemptsPerContact" param-type="integer" required="false">
Maximale Anzahl von Kontaktversuchen pro Kontakt.
</ParamField>

<ParamField body="retryDelayMinutes" param-type="integer" required="false">
Wartezeit in Minuten bis zum nächsten allgemeinen Wiederholungsversuch.
</ParamField>

<ParamField body="settings" param-type="object" required="false">
Zusätzliche Kampagneneinstellungen als JSON-Objekt.
</ParamField>

<ParamField body="noAutoComplete" param-type="boolean" required="false">
Deaktiviert das automatische Abschließen der Kampagne, wenn alle Kontakte verarbeitet wurden.
</ParamField>

<ParamField body="webhookEnabled" param-type="boolean" required="false">
Aktiviert Webhooks für Kampagnenereignisse.
</ParamField>

<ParamField body="webhookUrl" param-type="string" required="false">
Ziel-URL für Webhook-Benachrichtigungen.
</ParamField>

<ParamField body="webhookSecret" param-type="string" required="false">
Secret zum Signieren oder Validieren ausgehender Webhook-Anfragen.
</ParamField>

<ParamField body="webhookEvents" param-type="array" required="false">
Liste der Webhook-Ereignisse, die für diese Kampagne gesendet werden sollen.
</ParamField>

## Kampagne aktualisieren oder Status ändern

Aktualisieren Sie eine vorhandene Kampagne mit `PUT /api/crm/campaigns/[id]`. Der Request-Body verwendet dieselben CamelCase-Felder wie beim Erstellen.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X PUT "https://app.talkturo.com/api/crm/campaigns/cmp_2d9a4c71" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-session=example_session_token" \
  -d '{
    "status": "paused",
    "settings": {
      "voicemailDropMessage": "Hallo, hier ist Talkturo. Wir melden uns später noch einmal.",
      "voicemailDetectionEnabled": true,
      "voicemailAction": "drop_message",
      "unavailableAction": "retry",
      "retryDelayMinutesNoAnswer": 45,
      "retryDelayMinutesBusy": 20,
      "retryDelayMinutesError": 60,
      "retryOnError": true,
      "useContactTimezoneForCallWindow": true,
      "retryBackoffMode": "exponential",
      "retryBackoffMultiplier": 2,
      "retryBackoffMaxMinutes": 180,
      "maxAttemptsNoAnswer": 3,
      "maxAttemptsBusy": 2,
      "maxAttemptsError": 2,
      "noAutoComplete": false
    }
  }'
```

### Wichtige Aktualisierungsregeln

<Callout kind="alert">

Wenn eine Kampagne den Status `running` hat, dürfen Sie nur `status` ändern. Jeder Versuch, andere Felder in diesem Zustand zu aktualisieren, führt zu `409 Conflict`.

</Callout>

<Callout kind="alert">

Der Wechsel zu `status="running"` erfordert mindestens einen verfügbaren Credit. Wenn keine Credits vorhanden sind, lehnt die API den Statuswechsel ab.

</Callout>

Im Feld `settings` können Sie unter anderem diese Schlüssel setzen:

- `voicemailDropMessage`
- `voicemailDetectionEnabled`
- `voicemailAction`
- `unavailableAction`
- `retryDelayMinutesNoAnswer`
- `retryDelayMinutesBusy`
- `retryDelayMinutesError`
- `retryOnError`
- `useContactTimezoneForCallWindow`
- `retryBackoffMode`
- `retryBackoffMultiplier`
- `retryBackoffMaxMinutes`
- `maxAttemptsNoAnswer`
- `maxAttemptsBusy`

## Kampagne weich löschen

Löschen Sie Kampagnen weich über `DELETE /api/crm/campaigns/[id]`. Die API setzt dabei `deleted_at` und `deleted_by`, entfernt den Datensatz aber nicht endgültig.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X DELETE "https://app.talkturo.com/api/crm/campaigns/cmp_2d9a4c71" \
  -H "Cookie: sb-session=example_session_token"
```

```javascript
const response = await fetch("https://app.talkturo.com/api/crm/campaigns/cmp_2d9a4c71", {
  method: "DELETE",
  credentials: "include"
});

const result = await response.json();
console.log(result);
```
</Request>

<Response tabs="200,400">
```json
{
  "success": true
}
```

```json
{
  "error": "Only draft or cancelled campaigns can be deleted."
}
```
</Response>

### Pfadparameter

<ParamField path="id" param-type="string" required="true">
ID der Kampagne, die Sie weich löschen möchten.
</ParamField>

### Antwort

<ResponseField name="success" field-type="boolean">
Gibt an, ob die Kampagne erfolgreich weich gelöscht wurde.
</ResponseField>

<Callout kind="info">

Sie können nur Kampagnen im Status `draft` oder `cancelled` löschen. Für alle anderen Status gibt die API `400 Bad Request` zurück.

</Callout>

## Kampagnenkontakte auflisten

Rufen Sie die einer Kampagne zugeordneten Kontakte über den Kontakt-Endpunkt der Kampagne ab. Dieser Endpunkt unterstützt außerdem `POST`, um zusätzliche Kontakte zu einer vorhandenen Kampagne hinzuzufügen.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl "https://app.talkturo.com/api/crm/campaigns/cmp_2d9a4c71/contacts" \
  -H "Cookie: sb-session=example_session_token"
```

```javascript
const response = await fetch("https://app.talkturo.com/api/crm/campaigns/cmp_2d9a4c71/contacts", {
  credentials: "include"
});

const contacts = await response.json();
console.log(contacts);
```
</Request>

<Response tabs="200">
