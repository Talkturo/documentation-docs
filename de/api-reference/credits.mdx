## Guthaben für Ihr Konto verwalten

Mit den Guthaben-Endpunkten prüfen Sie Ihren aktuellen Kontostand, ziehen Nutzungsguthaben ab, starten den Kauf zusätzlicher Credits und rufen verlaufsbezogene Daten ab. Die API deckt sowohl programmgesteuerte Nutzungsvorgänge als auch abrechnungsnahe Workflows wie Checkout, Auto-Reload und Guthaben-Statements ab.

Ein Teil dieser Endpunkte verwendet Dual-Auth über `withApiAuth`. Sie können diese Endpunkte entweder mit einem API-Schlüssel oder mit einer bestehenden Sitzung aufrufen. Andere Endpunkte sind ausschließlich für authentifizierte Sitzungen verfügbar, während `GET /api/credits/plans` öffentlich erreichbar ist.

<Callout kind="info">

Verwenden Sie für serverseitige Integrationen bevorzugt einen API-Schlüssel. Sitzungsgebundene Endpunkte setzen eine aktive Benutzeranmeldung voraus. Der Endpunkt `GET /api/credits/plans` benötigt keine Authentifizierung und eignet sich für öffentliche Preis- oder Checkout-Flows.

</Callout>

## Endpunkte im Überblick

| Methode | Pfad | Authentifizierung | Zweck |
| --- | --- | --- | --- |
| `GET` | `/api/credits` | API-Schlüssel oder Sitzung | Aktuellen Guthabenstand eines Kontos abrufen |
| `POST` | `/api/credits` | API-Schlüssel oder Sitzung | Guthaben für Nutzungsvorgänge abziehen |
| `POST` | `/api/credits/checkout` | API-Schlüssel oder Sitzung | Stripe-Checkout für den Guthabenkauf erstellen |
| `PATCH` | `/api/credits/auto-reload` | API-Schlüssel oder Sitzung | Auto-Reload-Konfiguration aktualisieren |
| `POST` | `/api/credits/auto-reload` | API-Schlüssel oder Sitzung | Einen Auto-Reload-Versuch sofort auslösen |
| `GET` | `/api/credits/claim-grants` | Nur Sitzung | Nicht beanspruchte Guthaben-Grants abrufen |
| `POST` | `/api/credits/claim-grants` | Nur Sitzung | Verfügbare Grants beanspruchen |
| `GET` | `/api/credits/plans` | Keine (öffentlich) | Verfügbare Guthabenpläne abrufen |
| `GET` | `/api/credits/statement` | API-Schlüssel oder Sitzung | Guthabenauszug als CSV abrufen |
| `GET` | `/api/credits/transactions` | API-Schlüssel oder Sitzung | Transaktionsverlauf abrufen |

## Guthabenstand abrufen

Rufen Sie den aktuellen Guthabenstand eines Kontos mit `GET /api/credits` ab. Wenn für das angegebene Konto noch kein Guthabeneintrag existiert, erstellt der Endpunkt ihn automatisch.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X GET "https://api.talkturo.com/api/credits?accountId=acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r"
```

```javascript
const response = await fetch(
  "https://api.talkturo.com/api/credits?accountId=acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931",
  {
    method: "GET",
    headers: {
      Authorization: "Bearer tk_live_example_9xmk7q2r"
    }
  }
);

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "credits": {
    "id": "cred_4a8d6f12",
    "account_id": "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931",
    "credits": 18420,
    "total_purchased": 25000,
    "total_used": 6580,
    "auto_reload_enabled": true,
    "auto_reload_threshold": 2000,
    "auto_reload_amount_usd": 199
  }
}
```
</Response>

## Guthaben abziehen

Verwenden Sie `POST /api/credits`, um Guthaben für Nutzungsvorgänge zu verbuchen. Der Endpunkt führt die Abbuchung serverseitig aus und gibt den aktualisierten Saldo sowie Informationen zu einem möglichen Auto-Reload zurück.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/credits" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "accountId": "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931",
    "amount": 120,
    "description": "Outbound call usage",
    "metadata": {
      "assistantId": "asst_b83bde21",
      "callId": "call_91fd2e74"
    }
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/credits", {
  method: "POST",
  headers: {
    Authorization: "Bearer tk_live_example_9xmk7q2r",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    accountId: "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931",
    amount: 120,
    description: "Outbound call usage",
    metadata: {
      assistantId: "asst_b83bde21",
      callId: "call_91fd2e74"
    }
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200,402" default-tab="1">
```json
{
  "success": true,
  "transactionId": "txn_6c1f3ab9",
  "balance": 18300,
  "autoReloadTriggered": false
}
```

```json
{
  "success": false,
  "error": "Insufficient credits"
}
```
</Response>

### Body-Parameter

<ParamField body="accountId" param-type="string" required="true">
Die ID des Kontos, von dem Guthaben abgezogen werden soll.
</ParamField>

<ParamField body="amount" param-type="number" required="true">
Die abzuziehende Guthabenmenge.
</ParamField>

<ParamField body="description" param-type="string" required="false">
Eine optionale Beschreibung des Nutzungsvorgangs, die in der Transaktion gespeichert werden kann.
</ParamField>

<ParamField body="metadata" param-type="object" required="false">
Optionale strukturierte Zusatzdaten zum Vorgang, zum Beispiel Referenzen auf Anrufe, Assistenten oder interne Nutzungs-IDs.
</ParamField>

### Antwortfelder

<ResponseField name="success" field-type="boolean" required="true">
Gibt an, ob die Abbuchung erfolgreich war.
</ResponseField>

<ResponseField name="transactionId" field-type="string" required="true">
Die ID der erzeugten Guthabentransaktion.
</ResponseField>

<ResponseField name="balance" field-type="number" required="true">
Der verbleibende Guthabenstand nach der Abbuchung.
</ResponseField>

<ResponseField name="autoReloadTriggered" field-type="boolean" required="true">
Gibt an, ob die Abbuchung ein automatisches Nachladen ausgelöst hat.
</ResponseField>

<Callout kind="alert">

Wenn das Konto nicht über ausreichend Guthaben verfügt, antwortet der Endpunkt mit HTTP-Status `402`. Planen Sie diesen Fall in Ihrer Integration explizit ein, bevor Sie nachgelagerte Nutzungsvorgänge als erfolgreich markieren.

</Callout>

## Checkout für Guthabenkauf erstellen

Erstellen Sie mit `POST /api/credits/checkout` eine Stripe-Checkout-Sitzung für den Kauf zusätzlicher Credits. Sie übergeben entweder eine `planId` oder ein benutzerdefiniertes Paar aus Betrag und Guthabenmenge.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/credits/checkout" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "accountId": "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931",
    "accountSlug": "acme-sales",
    "planId": "credits_growth_199",
    "customerEmail": "finance@acme-sales.com"
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/credits/checkout", {
  method: "POST",
  headers: {
    Authorization: "Bearer tk_live_example_9xmk7q2r",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    accountId: "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931",
    accountSlug: "acme-sales",
    planId: "credits_growth_199",
    customerEmail: "finance@acme-sales.com"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "checkoutToken": "seti_example_7b34f2c8",
  "sessionId": "cs_test_b1a92c7d5e",
  "credits": 20000,
  "amount": 199
}
```
</Response>

### Body-Parameter

<ParamField body="accountId" param-type="string" required="true">
Die ID des Kontos, für das die Checkout-Sitzung erstellt wird.
</ParamField>

<ParamField body="accountSlug" param-type="string" required="true">
Der Slug des Kontos. Der Endpunkt verwendet ihn für die Zuordnung des Kaufs.
</ParamField>

<ParamField body="planId" param-type="string" required="false">
Die ID eines vordefinierten Guthabenplans. Geben Sie entweder `planId` oder die Kombination aus `customAmount` und `customCredits` an.
</ParamField>

<ParamField body="customAmount" param-type="number" required="false">
Ein benutzerdefinierter Betrag in US-Dollar. Bei benutzerdefinierten Käufen beträgt das Minimum `99`.
</ParamField>

<ParamField body="customCredits" param-type="number" required="false">
Die Guthabenmenge, die mit einem benutzerdefinierten Betrag gekauft werden soll.
</ParamField>

<ParamField body="customerId" param-type="string" required="false">
Eine optionale Stripe-Kunden-ID, wenn der Kauf einem bestehenden Kunden zugeordnet werden soll.
</ParamField>

<ParamField body="customerEmail" param-type="string" required="false">
Eine optionale E-Mail-Adresse für den Stripe-Checkout.
</ParamField>

<ParamField body="toltReferral" param-type="string" required="false">
Eine optionale Referral-Kennung, die beim Checkout mitgegeben wird.
</ParamField>

### Antwortfelder

<ResponseField name="success" field-type="boolean" required="true">
Gibt an, ob die Checkout-Sitzung erfolgreich erstellt wurde.
</ResponseField>

<ResponseField name="checkoutToken" field-type="string" required="true">
Das vom Checkout zurückgegebene Token für die initiale Einbettung oder Weiterverarbeitung.
</ResponseField>

<ResponseField name="sessionId" field-type="string" required="true">
Die ID der erzeugten Stripe-Checkout-Sitzung.
</ResponseField>

<ResponseField name="credits" field-type="number" required="true">
Die Guthabenmenge, die mit diesem Kauf verbunden ist.
</ResponseField>

<ResponseField name="amount" field-type="number" required="true">
Der Kaufbetrag in US-Dollar.
</ResponseField>

<Callout kind="info">

Für benutzerdefinierte Käufe müssen Sie `customAmount` und `customCredits` gemeinsam senden. Ein benutzerdefinierter Betrag unter `99` US-Dollar wird nicht akzeptiert.

</Callout>

## Auto-Reload konfigurieren und auslösen

Verwalten Sie Auto-Reload mit zwei Endpunkten. `PATCH /api/credits/auto-reload` speichert die Konfiguration für ein Konto, und `POST /api/credits/auto-reload` stößt einen sofortigen Prüf- und Nachladevorgang an.

### Auto-Reload-Konfiguration aktualisieren

Speichern Sie die Auto-Reload-Einstellungen eines Kontos mit `PATCH /api/credits/auto-reload`. Die Anfrage verwendet camelCase-Feldnamen und gibt den vollständigen aktualisierten Guthabeneintrag zurück.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X PATCH "https://api.talkturo.com/api/credits/auto-reload" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "accountId": "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931",
    "autoReloadEnabled": true,
    "autoReloadAmount": 199,
    "autoReloadThreshold": 2000
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/credits/auto-reload", {
  method: "PATCH",
  headers: {
    Authorization: "Bearer tk_live_example_9xmk7q2r",

    autoReloadEnabled: true,
    autoReloadAmount: 199,
    autoReloadThreshold: 2000
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">

### Auto-Reload sofort prüfen und ausführen

Stoßen Sie mit `POST /api/credits/auto-reload` einen unmittelbaren Auto-Reload-Versuch an. Der Endpunkt führt intern `runMaybeAutoReload()` aus und meldet zurück, ob Guthaben aufgeladen, der Vorgang übersprungen oder ein Fehler erkannt wurde.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/credits/auto-reload" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "accountId": "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931"
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/credits/auto-reload", {
  method: "POST",
  headers: {
    Authorization: "Bearer tk_live_example_9xmk7q2r",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    accountId: "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200 geladen,200 übersprungen" default-tab="1">
```json
{
  "success": true,
  "kind": "charged",
  "creditsAdded": 20000,
  "paymentIntentId": "pi_4d19a7bce2"
}
```

```json
{
  "success": true,
  "kind": "skip"
}
```
</Response>

#### Body-Parameter

<ParamField body="accountId" param-type="string" required="true">
Die ID des Kontos, für das ein Auto-Reload-Versuch ausgeführt werden soll.
</ParamField>

#### Antwortfelder

<ResponseField name="success" field-type="boolean" required="true">
Gibt an, ob die Anfrage erfolgreich verarbeitet wurde.
</ResponseField>

<ResponseField name="kind" field-type="string" required="true">
Das Ergebnis des Versuchs. Mögliche Werte sind `charged`, `skip` und `error`.
</ResponseField>

<ResponseField name="creditsAdded" field-type="number" required="false">
Die zusätzlich gutgeschriebene Guthabenmenge, wenn der Endpunkt ein Nachladen durchgeführt hat.
</ResponseField>

<ResponseField name="paymentIntentId" field-type="string" required="false">
Die ID des zugehörigen Zahlungsversuchs, wenn ein Nachladen ausgelöst wurde.
</ResponseField>

<Callout kind="info">

Wenn `kind` den Wert `skip` zurückgibt, hat der Endpunkt keinen Nachladevorgang ausgeführt. Das ist der erwartete Fall, wenn der Schwellenwert nicht unterschritten wurde oder Auto-Reload für das Konto deaktiviert ist.

</Callout>

## Grants abrufen und beanspruchen

Verwenden Sie die Grant-Endpunkte, um verfügbare Guthabenpakete aus Käufen oder Zuweisungen abzurufen und einem Konto gutzuschreiben. Beide Endpunkte sind nur in einem angemeldeten Sitzungskontext verfügbar.

### Nicht beanspruchte Grants abrufen

Rufen Sie mit `GET /api/credits/claim-grants` alle noch nicht beanspruchten Grants für die aktuelle Sitzung ab.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X GET "https://api.talkturo.com/api/credits/claim-grants" \
  -H "Cookie: better-auth.session_token=session_example_8fd31c7b"
```

```javascript
const response = await fetch("https://api.talkturo.com/api/credits/claim-grants", {
  method: "GET",
  credentials: "include"
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "grants": [
    {
      "id": "2d12d0e2-6a8b-4dc0-bf4f-5a7b3f11f8d1",
      "credits": 5000,

      "status": "unclaimed",
      "stripe_session_id": "cs_test_b1a92c7d5e"
```

</Response>

#### Antwortfelder

<ResponseField name="grants" field-type="array" required="true">
Liste der noch nicht beanspruchten Grants für die aktuelle Sitzung.

<ResponseField name="grants[].id" field-type="string" required="true">

### Grant beanspruchen

Schreiben Sie mit `POST /api/credits/claim-grants` einen Grant einem Konto gut. Die Anfrage benötigt sowohl die Grant-ID als auch die Ziel-Konto-ID.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/credits/claim-grants" \
  -H "Cookie: better-auth.session_token=session_example_8fd31c7b" \
  -H "Content-Type: application/json" \
  -d '{
    "grantId": "2d12d0e2-6a8b-4dc0-bf4f-5a7b3f11f8d1",
    "accountId": "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931"
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/credits/claim-grants", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  credentials: "include",
  body: JSON.stringify({
    grantId: "2d12d0e2-6a8b-4dc0-bf4f-5a7b3f11f8d1",
    accountId: "acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "transactionId": "txn_4c71b0d2",
  "clonedAssistantId": "asst_92d17ab4"
}
```
</Response>

<ParamField body="grantId" param-type="string" required="true">

</ParamField>

<ParamField body="accountId" param-type="string" required="true">
Die UUID des Kontos, dem der Grant gutgeschrieben werden soll.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X GET "https://api.talkturo.com/api/credits/statement?accountId=acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931&month=01&year=2026" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r"
```

```javascript
const response = await fetch(
  "https://api.talkturo.com/api/credits/statement?accountId=acc_7f2c91d8-3b31-4b4d-bf80-5c6f11a2d931&month=01&year=2026",
  {
    method: "GET",
    headers: {
      Authorization: "Bearer tk_live_example_9xmk7q2r"
    }
  }
);

const csv = await response.text();
console.log(csv);
```
</Request>

<Response tabs="200">
```text
date,type,amount,balance_after,description
2026-01-04T10:14:22.000Z,purchase,20000,20000,Growth plan

```
</Response>

### Query-Parameter

<ParamField query="accountId" param-type="string" required="false">

</ParamField>

<ParamField query="month" param-type="string" required="false">
Der Monat des Exports im Format `01` bis `12`.

### Antwort

## Transaktionsverlauf abrufen

```bash
  -H "Authorization: Bearer tk_live_example_9xmk7q2r"
```

```javascript
const response = await fetch(

  {
    method: "GET",
    headers: {
      Authorization: "Bearer tk_live_example_9xmk7q2r"
    }
  }
```

</Request>

### Query-Parameter

<ParamField query="accountId" param-type="string" required="false">
Die Konto-ID, deren Transaktionen abgerufen werden sollen. Wenn Sie den Parameter weglassen, verwendet der Endpunkt die `accountId` aus dem authentifizierten Kontext.
</ParamField>

<ParamField query="type" param-type="string" required="false">
Filtert nach einem oder mehreren Transaktionstypen. Unterstützte Werte sind `purchase`, `usage`, `refund` und `bonus`. Mehrere Werte übergeben Sie kommasepariert.
</ParamField>

<ParamField query="source" param-type="string" required="false">
Filtert nach einer Quelle wie `calls`, `kb_storage`, `phone` oder `usage`.
</ParamField>

<ParamField query="from" param-type="string" required="false">
Startzeitpunkt des Zeitraums im ISO-8601-Format.
</ParamField>

<ParamField query="to" param-type="string" required="false">
Endzeitpunkt des Zeitraums im ISO-8601-Format.
</ParamField>

<ParamField query="limit" param-type="number" required="false">
Maximale Anzahl zurückgegebener Einträge. Der Standardwert ist `50`.
</ParamField>

<ParamField query="offset" param-type="number" required="false">
Anzahl der zu überspringenden Einträge für die Paginierung. Der Standardwert ist `0`.
</ParamField>

Liste der gefundenen Guthabentransaktionen.
</ResponseField>

<ResponseField name="transactions[].id" field-type="string" required="true">
