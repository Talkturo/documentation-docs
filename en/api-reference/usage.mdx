## Monitor usage and log voice events

Use the Usage API to read current-month limits and consumption for an account, then record desktop speech-to-text usage events for billing. The two endpoints serve different clients: account usage is available to your web app or backend, while voice usage logging is intended for the desktop app.

<Callout kind="info">

`GET /api/usage/current` accepts either a session or an API key through `withApiAuth`. `POST /api/usage/voice` uses desktop-token authentication through `authenticateDesktop`, not API-key auth. Use `https://api.talkturo.com` for API-key requests, and `https://app.talkturo.com` for session-based or desktop-token requests.

</Callout>

## Endpoint summary

| Method | Endpoint | Auth | Purpose |
|---|---|---|---|
| `GET` | `/api/usage/current` | Session or API key | Return account limits, current-month usage, remaining capacity, percentages, and credit details |
| `POST` | `/api/usage/voice` | Desktop token | Log a desktop STT usage event for billing |

## Get current usage

`GET /api/usage/current` returns the current month's usage snapshot for an account. The response includes raw limits and usage plus server-calculated remaining values and percentages, so you can render usage meters without duplicating billing logic.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X GET "https://api.talkturo.com/api/usage/current?accountId=acc_7f3a2c19" \
  -H "Authorization: Bearer tk_example_9xmk7q2r" \
  -H "Accept: application/json"
```

```javascript
const response = await fetch(
  "https://api.talkturo.com/api/usage/current?accountId=acc_7f3a2c19",
  {
    method: "GET",
    headers: {
      "Authorization": "Bearer tk_example_9xmk7q2r",
      "Accept": "application/json"
    }
  }
);

const data = await response.json();
console.log(data);
```
</Request>

### Query parameters

<ParamField query="accountId" param-type="string" required="true">

Account identifier to load usage and billing limits for.

</ParamField>

### Authentication

Add either a valid API key or an authenticated session. For API-key access, send the request to `https://api.talkturo.com`. For browser-session access, send the request to `https://app.talkturo.com`.

### How usage is calculated

The endpoint combines account limits from `get_account_limits` with current-month consumption from `get_current_month_usage`. It supports a dual billing model: when credits are enabled, the response emphasizes credits-based accounting; when credits are not available, usage falls back to minute-based tracking.

That calculation happens on the server. The `remaining` and `percentages` objects are already derived from the account's limits and current usage, so your client does not need to recompute them.

### Error responses

<ResponseField name="error" field-type="string" required="true">

Error message returned when the request fails.

</ResponseField>

A `400` response means the `accountId` query parameter is missing. A `404` response means Talkturo could not find account limits for the requested account. A `500` response means one of the underlying RPC calls failed.

## Log voice usage

`POST /api/usage/voice` records a speech-to-text billing event from the desktop app. The endpoint rounds `durationSeconds` to the nearest whole second, clamps negative values to `0`, and calculates `cost_usd` as `seconds / 60 * 0.0077`.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/usage/voice" \
  -H "Authorization: Bearer dt_example_4km2q8sx" \
  -H "Content-Type: application/json" \
  -d '{
    "connectionId": "conn_01hzy4w8m9q2",
    "durationSeconds": 187.4,
    "provider": "deepgram",
    "model": "nova-3",
    "userEmail": "jane.chen@acme.co"
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/usage/voice", {
  method: "POST",
  headers: {
    "Authorization": "Bearer dt_example_4km2q8sx",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    connectionId: "conn_01hzy4w8m9q2",
    durationSeconds: 187.4,
    provider: "deepgram",
    model: "nova-3",
    userEmail: "jane.chen@acme.co"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

### Request body

<ParamField body="connectionId" param-type="string | null" required="true">

Connection identifier associated with the desktop session. Pass `null` when no connection is available.

</ParamField>

<ParamField body="durationSeconds" param-type="number" required="true">

Voice duration in seconds before normalization. The server rounds the value to the nearest whole second and treats negative values as `0`.

</ParamField>

<ParamField body="provider" param-type="string" required="false">

Speech-to-text provider name. Defaults to `deepgram`.

</ParamField>

<ParamField body="model" param-type="string" required="false">

Model name used for transcription. Defaults to `nova-3`.

</ParamField>

<ParamField body="userEmail" param-type="string | null" required="true">

Email address associated with the desktop user, or `null` when unavailable.

</ParamField>

### Behavior

This endpoint is best-effort billing telemetry. If the `talkturo_desktop_usage_events` table does not exist, the server logs a warning internally and still returns `200` with an empty JSON object.

<Callout kind="tip">

Use this endpoint for usage logging, not for billing reconciliation on the client. The server stores the normalized duration and computes cost from the fixed Deepgram pay-as-you-go rate of `0.0077` USD per minute.

</Callout>

### Response fields

<ResponseField name="root" field-type="object" required="true">

The success response is an empty JSON object.

</ResponseField>

<ResponseField name="error" field-type="string" required="true">

Error message returned when the request fails.

</ResponseField>

A `400` response means the request body could not be parsed as JSON. A `401` response means desktop authentication failed. A `500` response means an unexpected database error occurred while writing the usage event.
