## Manage desktop sessions

Use the Sessions API to create desktop sessions, resume active work, update session metadata, end sessions cleanly, and remove session records when you no longer need them.

<Callout kind="info">

All session endpoints require a desktop Bearer JWT in the `Authorization` header. Get the token from the desktop sign-in flow, then send `Authorization: Bearer dtk_example_9xmk7q2r`.

Use the optional `x-talkturo-account` header to scope requests to a workspace. If you omit the header, requests run in the authenticated user's default scope.

</Callout>

## Endpoint summary

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/sessions` | Desktop Bearer JWT | List sessions for the authenticated user |
| `POST` | `/api/sessions` | Desktop Bearer JWT | Create a session or reuse an active one |
| `GET` | `/api/sessions/{id}` | Desktop Bearer JWT | Get one session by ID |
| `PATCH` | `/api/sessions/{id}` | Desktop Bearer JWT | Update session fields or end a session |
| `DELETE` | `/api/sessions/{id}` | Desktop Bearer JWT | Delete a session and related data |
| `POST` | `/api/sessions/end-all` | Desktop Bearer JWT | End all active sessions for the user |

## GET /api/sessions

List sessions for the authenticated desktop user, ordered by `started_at` descending.

### Request example

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X GET "https://api.talkturo.com/api/sessions" \
  -H "Authorization: Bearer dtk_example_9xmk7q2r" \
  -H "x-talkturo-account: acme-revenue"
```

```javascript
const response = await fetch("https://api.talkturo.com/api/sessions", {
  method: "GET",
  headers: {

    "x-talkturo-account": "acme-revenue"

});

const data = await response.json();
```

## POST /api/sessions

Create a new session, or return an existing active session instead of creating a duplicate.

### Request example

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://api.talkturo.com/api/sessions" \
  -H "Authorization: Bearer dtk_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -H "x-talkturo-account: acme-revenue" \
  -d '{
    "mode": "getOrCreateActive",
    "session_type": "listen"
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/sessions", {
  method: "POST",
  headers: {
    "Authorization": "Bearer dtk_example_9xmk7q2r",
    "Content-Type": "application/json",
    "x-talkturo-account": "acme-revenue"
  },
  body: JSON.stringify({
    mode: "getOrCreateActive",
    session_type: "listen"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200,401,500" default-tab="1">
```json
{
  "id": "2d214f0b-b3d4-4bf0-95ab-4ef865f8d6b2"
}
```

```json

  "error": "Unauthorized"
}
```

```json

  "error": "Failed to create session"
}
```
</Response>

### Headers

<ParamField header="Authorization" param-type="string" required="true">
Bearer JWT for a signed-in desktop user.
</ParamField>

<ParamField header="Content-Type" param-type="string" required="true">
Send `application/json`.
</ParamField>

<ParamField header="x-talkturo-account" param-type="string" required="false">
Workspace identifier for account scoping. The server uses this header when creating or backfilling the session account association.
</ParamField>

### Body parameters

<ParamField body="mode" param-type="string" required="false" enum="create,getOrCreateActive">
Session creation strategy. Defaults to `create`. Use `getOrCreateActive` to reuse an active session for the current user when one exists.
</ParamField>

<ParamField body="session_type" param-type="string" required="false" enum="ask,listen">
Requested session type. Defaults to `ask`.
</ParamField>

<ParamField body="sessionType" param-type="string" required="false" enum="ask,listen">
Alternative body field accepted by the endpoint for session type. Prefer `session_type` in new integrations.
</ParamField>

### Response fields

<ResponseField name="id" field-type="string" required="true">
UUID of the created session or the reused active session.
</ResponseField>

<Callout kind="info">

When `mode` is `getOrCreateActive`, the API looks for an active session before inserting a new row. If you request `listen` and the existing active session is `ask`, the API promotes that session to `listen`.

</Callout>

## PATCH /api/sessions/{id}

Update mutable session fields, attach notes and voice metrics, or end the session in one request.

### Request example

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X PATCH "https://api.talkturo.com/api/sessions/2d214f0b-b3d4-4bf0-95ab-4ef865f8d6b2" \
  -H "Authorization: Bearer dtk_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Discovery call with Northwind",
    "notes": "Buyer asked for competitor pricing comparison.",
    "voice_metrics": {
      "talk_share_pct": 54,
      "wpm": 146,
      "patience_pct": 72,
      "longest_monologue_seconds": 41
    },
    "end": true
  }'
```

```javascript
const sessionId = "2d214f0b-b3d4-4bf0-95ab-4ef865f8d6b2";

const response = await fetch(`https://api.talkturo.com/api/sessions/${sessionId}`, {
  method: "PATCH",
  headers: {
    "Authorization": "Bearer dtk_example_9xmk7q2r",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    title: "Discovery call with Northwind",
    notes: "Buyer asked for competitor pricing comparison.",
    voice_metrics: {
      talk_share_pct: 54,
      wpm: 146,
      patience_pct: 72,
      longest_monologue_seconds: 41
    },
    end: true
  })
});

const data = await response.json();
console.log(data);
```
</Request>

</ParamField>

### Response fields

<ResponseField name="changes" field-type="integer" required="true">
Number of rows updated. A successful single-session update returns `1`.
</ResponseField>

<Callout kind="alert">

Do not send client-calculated duration values when ending a session. When `end` is `true`, the server computes `ended_at` and `duration_seconds` from the stored `started_at` value, then triggers asynchronous AI session analysis.

</Callout>

## Typical workflow

Most integrations follow the same lifecycle: create or resume a session, keep it updated while work happens, then end it explicitly.

<Steps>
<Step title="Create or resume a session" icon="play-circle">

Call `POST /api/sessions` with `mode: "getOrCreateActive"` when your client may reconnect or restart. A successful response returns an `id` that you use for all later calls.

Success signal: the API returns `200` with a body like `{"id":"2d214f0b-b3d4-4bf0-95ab-4ef865f8d6b2"}`.

</Step>

<Step title="Fetch or display session state" icon="database">

Call `GET /api/sessions` to populate recent activity, or `GET /api/sessions/{id}` to reload one session after reconnecting.

Success signal: the response body includes either a `sessions` array or a `session` object with the expected `status`, timestamps, and title.

</Step>

<Step title="Update metadata during the session" icon="edit">

Call `PATCH /api/sessions/{id}` as notes, title, status, or voice metrics change. Keep the request focused on fields that changed.

Success signal: the API returns `{"changes":1}`, which means the session row was updated.

</Step>

<Step title="End the session explicitly" icon="check-circle">

Call `PATCH /api/sessions/{id}` with `end: true` when the session finishes. If the client exits unexpectedly or signs out, call `POST /api/sessions/end-all` as a cleanup step.

Success signal: the API returns `{"changes":1}` for a single session, or a larger count from `end-all` when multiple active sessions were closed.

</Step>
</Steps>
