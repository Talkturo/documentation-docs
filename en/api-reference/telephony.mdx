## Telephony endpoints

Manage an assistant's calling configuration, attached phone numbers, outbound test calls, and compliance templates from the telephony API. All telephony routes are scoped to a single assistant and require an authenticated browser session.

<Callout kind="info">

All endpoints on this page require **session cookie authentication**. Send requests from an authenticated Talkturo session. These routes are available under `/api/assistants/[assistantId]/telephony/`.

</Callout>

### Base path

`/api/assistants/[assistantId]/telephony`

### Endpoint summary

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/assistants/[assistantId]/telephony/test-call` | Start a test outbound SIP call |
| `POST` | `/api/assistants/[assistantId]/telephony/inbound` | Toggle inbound calling on or off |
| `POST` | `/api/assistants/[assistantId]/telephony/outbound` | Toggle outbound calling on or off |
| `POST` | `/api/assistants/[assistantId]/telephony/settings` | Save full telephony settings |
| `GET` `PATCH` | `/api/assistants/[assistantId]/telephony/phone-numbers` | List or assign phone numbers |
| `POST` | `/api/assistants/[assistantId]/telephony/assign-phone-numbers` | Assign phone numbers to the assistant |
| `GET` | `/api/assistants/[assistantId]/telephony/compliance-templates` | List available compliance templates |

## POST test-call

Start a test outbound call from a phone number already assigned to the assistant. The endpoint creates a room, dispatches the agent, and then creates the outbound SIP participant.

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">

Assistant UUID.

</ParamField>

### Request body

<ParamField body="accountSlug" param-type="string" required="true">

Account slug used to validate account membership and resolve the billing context for the call.

</ParamField>

<ParamField body="fromNumber" param-type="string" required="true">

The outbound phone number the assistant should call from. The number must be active and already assigned to the assistant.

</ParamField>

<ParamField body="toNumber" param-type="string" required="true">

The destination phone number to dial for the test call.

</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">

Whether the test call was created successfully.

</ResponseField>

<ResponseField name="roomName" field-type="string" required="true">

LiveKit room name created for the call session.

</ResponseField>

<ResponseField name="sipCallId" field-type="string" required="true">

Identifier for the outbound SIP call participant.

</ResponseField>

<ResponseField name="message" field-type="string" required="true">

Human-readable status message describing the result.

</ResponseField>

<Callout kind="alert">

`POST /telephony/test-call` performs a credit pre-flight check before creating the call. If the account balance is below `MIN_CREDITS_TO_RUN_OUTBOUND`, the API returns `402` and does not create the room or SIP participant.

</Callout>

### Validation rules

The test call endpoint rejects requests unless all of the following are true:

- Outbound calling is enabled for the assistant.
- The assistant has a valid `livekit_outbound_trunk_id`.
- `fromNumber` is active.
- `fromNumber` is assigned to the assistant.
- The authenticated user has access to the account identified by `accountSlug`.

### Execution flow

When the request passes validation, Talkturo runs the call setup in this order:

1. Create a LiveKit room.
2. Dispatch the assistant agent into the room.
3. Create the outbound SIP participant.

If the request succeeds, the response includes both the room name and SIP call identifier.

## POST inbound

Toggle inbound calling on or off for an assistant. When enabled, provisions a LiveKit inbound SIP trunk and dispatch rule. When disabled, tears them down.

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">

Assistant UUID.

</ParamField>

### Body parameters

<ParamField body="accountSlug" param-type="string" required="true">

The workspace slug.

</ParamField>

<ParamField body="enabled" param-type="boolean" required="true">

Set to `true` to provision and enable inbound calling; `false` to deprovision and disable.

</ParamField>

<Callout kind="alert">

When `enabled` is `true`, the assistant must have at least one active phone number assigned. The API returns `400` if no active numbers are found.

</Callout>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">

Returns `true` when the toggle completes.

</ResponseField>

<ResponseField name="assistant" field-type="object" required="true">

Updated assistant record.

</ResponseField>

<ResponseField name="assistant.inbound_enabled" field-type="boolean" required="true">

Current inbound enabled state.

</ResponseField>

<ResponseField name="assistant.livekit_inbound_trunk_id" field-type="string" required="false">

LiveKit inbound trunk ID. `null` when inbound is disabled.

</ResponseField>

<ResponseField name="assistant.livekit_dispatch_rule_id" field-type="string" required="false">

LiveKit dispatch rule ID. `null` when inbound is disabled.

</ResponseField>

</ResponseField>

## POST settings

The main telephony settings endpoint. Assigns phone numbers, sets the Telnyx FQDN connection, enables or disables inbound and outbound calling, provisions LiveKit SIP trunks, and optionally configures voicemail detection and compliance briefing.

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">

Assistant UUID.

</ParamField>

### Body parameters

<ParamField body="accountSlug" param-type="string" required="true">

Workspace slug.

</ParamField>

<ParamField body="phoneNumberIds" param-type="array" required="true">

Array of phone-number UUIDs to assign to the assistant.

</ParamField>

<ParamField body="inboundEnabled" param-type="boolean" required="true">

Toggle inbound calling.

</ParamField>

<ParamField body="outboundEnabled" param-type="boolean" required="true">

Toggle outbound calling.

</ParamField>

<ParamField body="inboundCompanyId" param-type="string" required="false">

Company UUID for inbound routing. Required at runtime when `inboundEnabled` is `true`.

</ParamField>

<ParamField body="telnyxConnectionId" param-type="string" required="false">

Telnyx FQDN connection ID. Nullable because Twilio-based assistants do not use it.

</ParamField>

<ParamField body="destinationCountry" param-type="string" required="false">

ISO country code for LiveKit outbound region pinning. Allowed values: `ae`, `au`, `br`, `ch`, `de`, `fr`, `gb`, `il`, `in`, `jp`, `sa`, `sg`, `us`, `za`. Set to `null` for auto-routing.

</ParamField>

<ParamField body="voicemail" param-type="object" required="false">

Voicemail detection settings. Omit to leave unchanged.

</ParamField>

<ParamField body="voicemail.detectionEnabled" param-type="boolean" required="false">

Enable voicemail detection.

</ParamField>

<ParamField body="voicemail.action" param-type="string" required="false">

Voicemail action, max 40 characters.

</ParamField>

<ParamField body="voicemail.message" param-type="string" required="false">

Voicemail message text, max 2000 characters.

</ParamField>

<ParamField body="compliance" param-type="object" required="false">

Compliance briefing settings. Omit to leave unchanged.

</ParamField>

<ParamField body="compliance.enabled" param-type="boolean" required="false">

Enable compliance briefing.

</ParamField>

<ParamField body="compliance.templateId" param-type="string" required="false">

Compliance template UUID.

</ParamField>

<ParamField body="compliance.briefingText" param-type="string" required="false">

Compliance briefing text, max 2000 characters.

</ParamField>

<ParamField body="compliance.language" param-type="string" required="false">

Briefing language, max 20 characters.

</ParamField>

<ParamField body="compliance.requireAck" param-type="boolean" required="false">

Require caller acknowledgment.

</ParamField>

<ParamField body="compliance.fallbackPolicy" param-type="string" required="false">

Fallback policy when acknowledgment fails. Allowed values: `retry`, `block`, `continue`.

</ParamField>

<ParamField body="compliance.ackTimeoutSeconds" param-type="integer" required="false">

Acknowledgment timeout in seconds, range 3–60.

</ParamField>

<Callout kind="info">

When compliance is enabled, either `templateId` must be non-null or `briefingText` must be non-empty. The API validates this cross-field requirement before saving.

</Callout>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">

Returns `true` when settings are saved.

</ResponseField>

<ResponseField name="assistant" field-type="object" required="true">

Updated assistant record with `inbound_enabled`, `outbound_enabled`, `telnyx_fqdn_connection_id`, `inbound_company_id`, and `destination_country`.

</ResponseField>

<ResponseField name="assignedActive" field-type="integer" required="true">

Count of active phone numbers after the save.

</ResponseField>

## GET and PATCH phone-numbers

List phone numbers available to the assistant, or assign phone numbers to the assistant. The `GET` method returns numbers that are active and either unassigned or already assigned to this assistant. The `PATCH` method replaces the assistant's phone-number assignments.

<Callout kind="info">

The `GET` and `PATCH` methods on this endpoint support both session cookie and API key authentication. All other telephony routes on this page require session cookie authentication only.

</Callout>

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">

Assistant UUID.

</ParamField>

### GET query parameters

<ParamField query="accountSlug" param-type="string" required="false">

Optional account slug override. When using API key auth, this overrides the key's associated account.

</ParamField>

### PATCH body parameters

<ParamField body="accountSlug" param-type="string" required="false">

Optional account slug override.

</ParamField>

<ParamField body="phoneNumberIds" param-type="array" required="true">

Array of phone-number UUIDs to assign. Replaces all current assignments.

</ParamField>

<Callout kind="alert">

`PATCH` replaces all current phone-number assignments. Include the full set of UUIDs you want assigned, not just new additions.

</Callout>

### GET response fields

<ResponseField name="success" field-type="boolean" required="true">

Returns `true`.

</ResponseField>

<ResponseField name="numbers" field-type="array" required="true">

Array of phone number objects. Each includes `id`, `phone_number`, `status`, `is_trial`, `assistant_id`, `provider`, `accountKey`, `accountLabel`, and `accountSid`.

</ResponseField>

### PATCH response fields

<ResponseField name="success" field-type="boolean" required="true">

Returns `true` when assignment completes.

</ResponseField>

<ResponseField name="message" field-type="string" required="true">

Confirmation message.

</ResponseField>

## POST assign-phone-numbers

Assign one or more phone numbers to an assistant. Use this endpoint when numbers already exist in the account and need to be attached to a specific assistant for inbound or outbound use.

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">

Assistant UUID.

</ParamField>

### Expected behavior

Call this route after provisioning or selecting numbers elsewhere in the account. Once a number is assigned and active, you can use it in assistant telephony workflows such as inbound routing and outbound test calls.

## GET compliance-templates

Return the compliance templates available for telephony configuration. Use this endpoint when your phone-number or carrier workflow requires a predefined compliance template.

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">

Assistant UUID.

</ParamField>

### Response fields

<ResponseField name="templates" field-type="array">

List of available compliance templates for the assistant's telephony context.

</ResponseField>

### Expected behavior

Fetch compliance templates before presenting telephony compliance choices in your application. This keeps your UI aligned with the templates currently available in Talkturo.

## Common integration notes

A successful telephony integration usually follows this order:

1. Configure inbound or outbound settings for the assistant.
2. Attach or assign the phone numbers the assistant will use.
3. Fetch compliance templates if your setup requires regulated number provisioning.
4. Run a test outbound call to verify the assistant, number assignment, and trunk configuration together.

### Common failure cases

- **`401` or `403`** — the request was sent without a valid authenticated session or without access to the target account.
- **`402`** — the account does not have enough credits to run an outbound test call.
- **Validation failure on test-call** — outbound telephony is disabled, the outbound trunk is missing or invalid, or `fromNumber` is not active and assigned to the assistant.

## Related telephony context

Talkturo also exposes an account-level session-auth endpoint outside the assistant telephony namespace:

- `GET /api/assistant-phone-numbers` — lists phone numbers attached to an assistant across the account.

Use the assistant-scoped telephony routes on this page for configuration changes tied to one assistant. Use the account-level listing route when you need a broader lookup across the account.
