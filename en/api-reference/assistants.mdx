## Manage assistants

Create assistants, update their configuration, clone existing setups, delete assistants you no longer need, and retrieve usage data for reporting or operational checks.

<Callout kind="info">

All assistant endpoints support dual authentication through `withApiAuth`. Authenticate with either a Talkturo API key or an authenticated session cookie.

</Callout>

### Base path

All endpoints on this page are rooted at ` /api/assistants `.

### Authentication

Send your API key in the `Authorization` header as a bearer token.

<Request tabs="cURL" default-tab="1">

```bash
curl -X POST "https://app.talkturo.com/api/assistants" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8" \
  -H "Content-Type: application/json" \
  -d '{
    "accountSlug": "acme-sales",
    "name": "Inbound Sales Assistant"
  }'
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "assistant": {
    "id": "7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
    "name": "Inbound Sales Assistant"
  }
}
```

</Response>

If you use session-based auth from the Talkturo app, the browser sends the session cookie automatically. External integrations usually use API keys.

## Create an assistant

Create a new assistant under an account by sending the account slug and assistant name. If you provide a template ID, Talkturo sets the assistant type from that template.

<Request tabs="cURL,JavaScript,Python" default-tab="1">

```bash
curl -X POST "https://app.talkturo.com/api/assistants" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8" \
  -H "Content-Type: application/json" \
  -d '{
    "accountSlug": "acme-sales",
    "name": "Inbound Sales Assistant",
    "templateId": "tmpl_sales_inbound_v1"
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/assistants", {
  method: "POST",
  headers: {
    "Authorization": "Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    accountSlug: "acme-sales",
    name: "Inbound Sales Assistant",
    templateId: "tmpl_sales_inbound_v1"
  })
});

const data = await response.json();
console.log(data);
```

```python
import requests

response = requests.post(
    "https://app.talkturo.com/api/assistants",
    headers={
        "Authorization": "Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8",
        "Content-Type": "application/json"
    },
    json={
        "accountSlug": "acme-sales",
        "name": "Inbound Sales Assistant",
        "templateId": "tmpl_sales_inbound_v1"
    }
)

print(response.json())
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "assistant": {
    "id": "7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
    "account_slug": "acme-sales",
    "name": "Inbound Sales Assistant",
    "type": "sales",
    "created_at": "2025-02-18T14:22:31.114Z",
    "updated_at": "2025-02-18T14:22:31.114Z"
  }
}
```

</Response>

### Endpoint

`POST /api/assistants`

### Body parameters

The account slug that owns the assistant.
</ParamField>

<ParamField body="name" param-type="string" required="true">
The assistant name.
</ParamField>

<ParamField body="templateId" param-type="string" required="false">
An optional template identifier. When present, Talkturo sets the assistant type from the template.
</ParamField>

<ResponseField name="success" field-type="boolean" required="true">

</ResponseField>

</ResponseField>

<ResponseField name="assistant.id" field-type="string" required="true">
The assistant UUID.
</ResponseField>

<ResponseField name="assistant.name" field-type="string" required="true">
The assistant name stored by Talkturo.
</ResponseField>

<ResponseField name="assistant.type" field-type="string" required="false">
The assistant type derived from the template when `templateId` is provided.
</ResponseField>

Talkturo creates the assistant with default or null values for fields you do not provide at creation time. Update the assistant afterward to configure prompts, voices, models, or telephony settings.

## Update an assistant

Update an existing assistant by assistant ID. The update endpoint accepts `accountSlug` and any assistant fields supported by the backend.

<Request tabs="cURL,JavaScript" default-tab="1">

```bash
curl -X PATCH "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8" \
  -H "Content-Type: application/json" \
  -d '{
    "accountSlug": "acme-sales",
    "name": "Inbound Sales Assistant v2",
    "voice": "alloy",
    "model": "gpt-4o-realtime"
  }'
```

```javascript
const response = await fetch(
  "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
  {
    method: "PATCH",
    headers: {
      "Authorization": "Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8",
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      accountSlug: "acme-sales",
      name: "Inbound Sales Assistant v2",
      voice: "alloy",
      model: "gpt-4o-realtime"
    })
  }
);

const data = await response.json();
console.log(data);
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "assistant": {
    "id": "7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
    "name": "Inbound Sales Assistant v2",
    "voice": "alloy",
    "model": "gpt-4o-realtime",
    "updated_at": "2025-02-18T14:31:09.027Z"
  }
}
```

</Response>

### Endpoint

`PATCH /api/assistants/{assistantId}`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID.
</ParamField>

### Body parameters

<ParamField body="accountSlug" param-type="string" required="false">
The owning account slug. Include it when your integration scopes updates to a specific account context.
</ParamField>

<ParamField body="assistant fields" param-type="object" required="false">
Any assistant fields accepted by the backend. Use this endpoint to update configuration such as prompts, voices, models, and telephony-related settings.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the assistant is updated successfully.
</ResponseField>

<ResponseField name="assistant" field-type="object" required="true">
The updated assistant record.
</ResponseField>

<Callout kind="info">

If you send `transcriptor_options`, Talkturo validates them against the effective STT provider and model before saving the update. If you send `voice_options`, Talkturo validates them against the configured voice provider. Invalid options return a `400` response with `error: "invalid_transcriptor_options"` or `error: "invalid_voice_options"` and an `issues` array describing the problems.

</Callout>

When the update succeeds, the response includes the saved assistant object. Use that object as the source of truth for the assistant's latest configuration.

## Delete an assistant

Delete an assistant permanently by ID. Talkturo checks ownership before removing the record.

<Request tabs="cURL" default-tab="1">

```bash
curl -X DELETE "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8"
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "message": "Assistant deleted successfully"
}
```

</Response>

### Endpoint

`DELETE /api/assistants/{assistantId}`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID to delete.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the assistant is deleted successfully.
</ResponseField>

<ResponseField name="message" field-type="string" required="true">
A confirmation message. The value is `Assistant deleted successfully`.
</ResponseField>

<Callout kind="alert">

Deleting an assistant is irreversible. Remove it only after you confirm that no active workflows, phone numbers, or operational processes still depend on it.

</Callout>

## Clone an assistant

Clone an existing assistant to duplicate its configuration into a new assistant record. The cloned assistant copies the original's prompt, voice, model, and transcription settings but does not inherit phone numbers, telephony trunks, or tool configurations. Use cloning when you want a starting point for a variant instead of rebuilding settings manually.

<Request tabs="cURL,JavaScript" default-tab="1">

```bash
curl -X POST "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a/clone" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8"
```

```javascript
const response = await fetch(
  "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a/clone",
  {
    method: "POST",
    headers: {
      "Authorization": "Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8"
    }
  }
);

const data = await response.json();
console.log(data);
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "assistant": {
    "id": "0f3f8bc6-5e95-4344-88d2-8e5660ec9bf1",
    "name": "Inbound Sales Assistant (Copy)",
    "created_at": "2025-02-18T14:39:12.442Z",
    "updated_at": "2025-02-18T14:39:12.442Z"

```

</Response>

### Endpoint

`POST /api/assistants/{assistantId}/clone`

### Response fields

## Retrieve usage statistics

Fetch usage data for a single assistant within a specific account. Use this endpoint for monitoring, dashboards, or account-level reporting workflows.

<Callout kind="info">

This endpoint requires an authenticated session cookie. API keys are not supported. The caller must be a member of the account identified by `accountId`.

</Callout>

<Request tabs="cURL,JavaScript" default-tab="1">

```bash
curl -X GET "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a/usage-stats?accountId=8f6b7a40-8f86-4cfd-a7ec-0b0b52f5c8d2" \
  -H "Cookie: talkturo_session=session_example_4f7b2d1c9a8e6f5d3b1a"
```

```javascript
const response = await fetch(
  "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a/usage-stats?accountId=8f6b7a40-8f86-4cfd-a7ec-0b0b52f5c8d2",
  {
    method: "GET",
    credentials: "include"
  }
);

const data = await response.json();
console.log(data);
```

</Request>

<Response tabs="200" default-tab="1">

```json

  "avgDurationMinutes": 6.3,

  "timeline": {
    "today": 2,
    "last7Days": 15,
    "last30Days": 45,
    "last365Days": 148
  },
  "dailySeries": [
    {
      "date": "2026-02-18",
      "count": 3

```

</Response>

### Endpoint

`GET /api/assistants/{assistantId}/usage-stats`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID whose usage statistics you want to retrieve.
</ParamField>

### Query parameters

<ParamField query="accountId" param-type="string" required="true">
The account UUID used to scope the usage query. The authenticated session user must belong to this account.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when usage statistics are returned successfully.
</ResponseField>

<ResponseField name="totalCalls" field-type="integer" required="true">
The total number of calls associated with the assistant in the selected account scope.
</ResponseField>

<ResponseField name="totalMinutes" field-type="number" required="true">
The total completed call duration in minutes.
</ResponseField>

<ResponseField name="avgDurationMinutes" field-type="number" required="true">
The average duration in minutes across calls that include duration data.
</ResponseField>

<ResponseField name="completedCallsWithDuration" field-type="integer" required="true">
The number of completed calls included in duration-based calculations.
</ResponseField>

<ResponseField name="successRatePercent" field-type="number" required="true">
The success rate as a percentage for calls that were evaluated for success.
</ResponseField>

<ResponseField name="successEvaluatedCount" field-type="integer" required="true">
The number of calls included in the success rate calculation.
</ResponseField>

<ResponseField name="timeline" field-type="object" required="true">
Aggregate counts across standard time windows.
</ResponseField>

<ResponseField name="dailySeries" field-type="array" required="true">
Daily call counts represented as objects with `date` and `count` fields.
</ResponseField>

Build your client against the camelCase field names in the response. The endpoint returns usage metrics at the top level rather than under a nested `stats` object.

## Estimate billing costs

Estimate per-minute credit costs for an assistant based on its STT, LLM, and TTS configuration. Use query parameters to test model or provider overrides before saving assistant changes.

<Callout kind="info">

This endpoint requires an authenticated session cookie. API keys are not supported. The caller must be a member of the account identified by `accountId`.

</Callout>

<Request tabs="cURL" default-tab="1">

```bash
curl -X GET "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a/billing/estimate?accountId=8f6b7a40-8f86-4cfd-a7ec-0b0b52f5c8d2&llm_provider=openai&llm_model=gpt-4o-mini&stt_provider=deepgram&stt_model=nova-3&tts_provider=openai&tts_model=gpt-4o-mini-tts&is_realtime=true" \
```

Use this endpoint before updating an assistant when you want to compare model combinations without changing the saved configuration.

## Test assistant webhook

Queue a synthetic test event to verify webhook delivery configuration. This endpoint inserts a synthetic `call.ended` event and schedules normal webhook delivery for the assistant.

<Callout kind="info">

The assistant must already have `webhook_enabled` set to `true`, plus valid `webhook_url` and `webhook_secret` values.

</Callout>

<Request tabs="cURL" default-tab="1">

```bash
curl -X POST "https://app.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a/webhooks/test" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8"
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "delivery_id": "whd_7f2a16b8f9d84f56b31c2a4e9087d114",
  "message": "Test event queued"
}
```

</Response>

### Endpoint

`POST /api/assistants/{assistantId}/webhooks/test`

### Authentication

Authenticate with either a Talkturo API key or an authenticated session. The caller must be an account member.

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">

### Response fields

</ResponseField>

<ResponseField name="delivery_id" field-type="string" required="true">

<ResponseField name="message" field-type="string" required="true">

## Common response shape

All endpoints on this page return a top-level `success` field. Mutation endpoints also return either an `assistant` object or a `message`, depending on the operation.

### Success fields

<ResponseField name="success" field-type="boolean" required="true">
Indicates whether the request completed successfully.
</ResponseField>

<ResponseField name="assistant" field-type="object" required="false">
Returned by the create, update, and clone endpoints.
</ResponseField>

<ResponseField name="totalCalls" field-type="integer" required="false">
Returned by the usage statistics endpoint as a top-level field.
</ResponseField>

<ResponseField name="message" field-type="string" required="false">

</ResponseField>
