## Manage assistants

Create assistants, update their configuration, clone existing setups, delete assistants you no longer need, and retrieve usage data for reporting or operational checks.

<Callout kind="info">

All assistant endpoints support dual authentication through `withApiAuth`. Authenticate with either a Talkturo API key or an authenticated session cookie.

</Callout>

### Base path

All endpoints on this page are rooted at ` /api/assistants `.

### Authentication

Send your API key in the `Authorization` header as a bearer token.

<Request tabs="cURL" default-tab="1">

```bash
curl -X POST "https://api.talkturo.com/api/assistants" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8" \
  -H "Content-Type: application/json" \
  -d '{
    "accountSlug": "acme-sales",
    "name": "Inbound Sales Assistant"
  }'
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "assistant": {
    "id": "7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
    "name": "Inbound Sales Assistant"
  }
}
```

</Response>

If you use session-based auth from the Talkturo app, the browser sends the session cookie automatically. External integrations usually use API keys.

## Create an assistant

Create a new assistant under an account by sending the account slug and assistant name. If you provide a template ID, Talkturo sets the assistant type from that template.

<Request tabs="cURL,JavaScript,Python" default-tab="1">

```bash
curl -X POST "https://api.talkturo.com/api/assistants" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8" \
  -H "Content-Type: application/json" \
  -d '{
    "accountSlug": "acme-sales",
    "name": "Inbound Sales Assistant",
    "templateId": "tmpl_sales_inbound_v1"
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/assistants", {
  method: "POST",
  headers: {
    "Authorization": "Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    accountSlug: "acme-sales",
    name: "Inbound Sales Assistant",
    templateId: "tmpl_sales_inbound_v1"
  })
});

const data = await response.json();
console.log(data);
```

```python
import requests

response = requests.post(
    "https://api.talkturo.com/api/assistants",
    headers={
        "Authorization": "Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8",
        "Content-Type": "application/json"
    },
    json={
        "accountSlug": "acme-sales",
        "name": "Inbound Sales Assistant",
        "templateId": "tmpl_sales_inbound_v1"
    }
)

print(response.json())
```

</Request>

<Response tabs="200" default-tab="1">

```json

    "id": "7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
    "account_slug": "acme-sales",

    "type": "sales",
    "created_at": "2025-02-18T14:22:31.114Z",
```

</Response>

`POST /api/assistants`

</ParamField>

<ParamField body="templateId" param-type="string" required="false">
An optional template identifier. When present, Talkturo sets the assistant type from the template.

</ResponseField>

<ResponseField name="assistant.type" field-type="string" required="false">
The assistant type derived from the template when `templateId` is provided.

Talkturo creates the assistant with default or null values for fields you do not provide at creation time. Update the assistant afterward to configure prompts, voices, models, or telephony settings.

## Update an assistant

Update an existing assistant by assistant ID. The update endpoint accepts `accountSlug` and any assistant fields supported by the backend.

<Request tabs="cURL,JavaScript" default-tab="1">

```bash
curl -X PATCH "https://api.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8" \
  -H "Content-Type: application/json" \
  -d '{
    "accountSlug": "acme-sales",
    "name": "Inbound Sales Assistant v2",
    "voice": "alloy",
    "model": "gpt-4o-realtime"
  }'
```

```javascript
const response = await fetch(
  "https://api.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
  {
    method: "PATCH",
    headers: {
      "Authorization": "Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8",
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      accountSlug: "acme-sales",
      name: "Inbound Sales Assistant v2",
      voice: "alloy",
      model: "gpt-4o-realtime"
    })
  }
);

const data = await response.json();
console.log(data);
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "assistant": {
    "id": "7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a",
    "name": "Inbound Sales Assistant v2",
    "voice": "alloy",
    "model": "gpt-4o-realtime",
    "updated_at": "2025-02-18T14:31:09.027Z"
  }
}
```

</Response>

### Endpoint

`PATCH /api/assistants/{assistantId}`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID.
</ParamField>

### Body parameters

<ParamField body="accountSlug" param-type="string" required="false">
The owning account slug. Include it when your integration scopes updates to a specific account context.
</ParamField>

<ParamField body="assistant fields" param-type="object" required="false">
Any assistant fields accepted by the backend. Use this endpoint to update configuration such as prompts, voices, models, and telephony-related settings.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the assistant is updated successfully.
</ResponseField>

<ResponseField name="assistant" field-type="object" required="true">
The updated assistant record.
</ResponseField>

<Callout kind="info">

If you send `transcriptor_options`, Talkturo validates those options against the selected provider and model before saving the update.

</Callout>

When the update succeeds, the response includes the saved assistant object. Use that object as the source of truth for the assistant's latest configuration.

## Delete an assistant

Delete an assistant permanently by ID. Talkturo checks ownership before removing the record.

<Request tabs="cURL" default-tab="1">

```bash
curl -X DELETE "https://api.talkturo.com/api/assistants/7f5a4d6e-1d1b-4f76-9b03-2e9f48d09f6a" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r4f8n6p1s3d5h7j9k2m4q6w8"
```

</Request>

<Response tabs="200" default-tab="1">

```json
{
  "success": true,
  "message": "Assistant deleted successfully"
}
```

</Response>

### Endpoint

`DELETE /api/assistants/{assistantId}`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID to delete.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the assistant is deleted successfully.
</ResponseField>

<ResponseField name="message" field-type="string" required="true">
A confirmation message. The value is `Assistant deleted successfully`.
</ResponseField>

<Callout kind="alert">

Deleting an assistant is irreversible. Remove it only after you confirm that no active workflows, phone numbers, or operational processes still depend on it.

</Callout>

Array of daily call counts for the trailing 30 days. Each entry contains a date in `YYYY-MM-DD` UTC format and a count.

## Tool configurations

Tool configs let you attach third-party tools such as Cal.com scheduling, Zapier, or custom webhooks to an assistant.

<Callout kind="info">

All tool configuration endpoints require session authentication.

</Callout>

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/assistants/{assistantId}/tool-configs` | List all enabled tool configs |
| `GET` | `/api/assistants/{assistantId}/tool-configs/{toolType}` | Get configs for a specific tool type |
| `POST` | `/api/assistants/{assistantId}/tool-configs/{toolType}` | Create or update a tool config |
| `DELETE` | `/api/assistants/{assistantId}/tool-configs/{toolType}` | Delete tool config(s) |

### Get tool configs by type

Use this endpoint to retrieve one config, or all configs, for a specific tool type.

`GET /api/assistants/{assistantId}/tool-configs/{toolType}`

<ParamField path="assistantId" param-type="string" required="true">

<ParamField query="all" param-type="boolean" required="false">
Set to `true` to return all configs of this type.
</ParamField>

### Create or update a tool config

## Billing estimate

Fetch an estimated credits-per-minute cost based on the assistant's provider settings and the active cost catalog.

### Endpoint

`GET /api/assistants/{assistantId}/billing/estimate`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID.
</ParamField>

### Query parameters

<ParamField query="accountId" param-type="string" required="true">
Account UUID.
</ParamField>

<ParamField query="llm_provider" param-type="string" required="false">
Override the LLM provider for live preview.
</ParamField>

<ParamField query="llm_model" param-type="string" required="false">
Override the LLM model for live preview.
</ParamField>

<ParamField query="stt_provider" param-type="string" required="false">
Override the STT provider for live preview.
</ParamField>

<ParamField query="stt_model" param-type="string" required="false">
Override the STT model for live preview.
</ParamField>

<ParamField query="tts_provider" param-type="string" required="false">
Override the TTS provider for live preview.
</ParamField>

<ParamField query="tts_model" param-type="string" required="false">
Override the TTS model for live preview.
</ParamField>

<ParamField query="is_realtime" param-type="string" required="false">
Set to `true` or `1` to estimate realtime mode.
</ParamField>

### Response fields

<ResponseField name="catalog" field-type="object" required="true">
Active cost catalog used for the estimate. Includes `id` and `name`.
</ResponseField>

<ResponseField name="assumptions" field-type="object" required="true">

Assistant provider and model information used for the estimate, including STT, LLM, and TTS settings.
</ResponseField>

<ResponseField name="rates" field-type="object" required="true">
Resolved provider rates used to build the estimate, including per-minute and per-1k rates.
</ResponseField>

<ResponseField name="breakdown_credits_per_minute" field-type="object" required="true">
Estimated credits-per-minute contribution from STT, TTS, LLM, and telephony components.
</ResponseField>

<ResponseField name="estimated_credits_per_minute" field-type="number" required="true">
Total estimated credits per minute.
</ResponseField>

## Knowledge base attachments

Manage knowledge-base files attached to an assistant. Attach existing files from the account library. These endpoints do not upload new files. See [Knowledge Base](/en/api-reference/knowledge-base) for file upload and management.

| Method | Path | Purpose | Auth | Scope |
| --- | --- | --- | --- | --- |
| `GET` | `/api/assistants/{assistantId}/knowledge-base` | List attached knowledge-base files | API key or session | `kb:read` |
| `POST` | `/api/assistants/{assistantId}/knowledge-base` | Attach an existing file | API key or session | `kb:write` |
| `DELETE` | `/api/assistants/{assistantId}/knowledge-base/{fileId}` | Detach a file | API key or session | `kb:write` |

### List knowledge-base files

Retrieve all knowledge-base files attached to the assistant. Results are ordered by attachment creation time, newest first.

### Endpoint

`GET /api/assistants/{assistantId}/knowledge-base`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the request succeeds.
</ResponseField>

<ResponseField name="files" field-type="array" required="true">
Array of attached knowledge-base file objects. Each object includes `id`, `filename`, `mime_type`, `size_bytes`, `status`, `status_error`, `char_count`, `chunk_count`, `created_at`, and `updated_at`.
</ResponseField>

### Attach a knowledge-base file

Attach an existing knowledge-base file from the account library to the assistant. The file must already exist and belong to the same account as the assistant. This operation is idempotent. Attaching a file that is already attached returns success without creating a duplicate.

### Endpoint

`POST /api/assistants/{assistantId}/knowledge-base`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID.
</ParamField>

### Body parameters

<ParamField body="file_id" param-type="string" required="true">
UUID of the knowledge-base file to attach. The file must already exist in the account library.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the file is attached or was already attached.
</ResponseField>

<ResponseField name="idempotent" field-type="boolean" required="false">
Returns `true` when the file was already attached and no new attachment was created.
</ResponseField>

### Detach a knowledge-base file

Remove a knowledge-base file from an assistant. This only removes the attachment. The underlying file remains in the account library. Detaching a non-existent attachment still returns success.

### Endpoint

`DELETE /api/assistants/{assistantId}/knowledge-base/{fileId}`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID.
</ParamField>

<ParamField path="fileId" param-type="string" required="true">
UUID of the knowledge-base file to detach.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the file is detached or was not attached.
</ResponseField>

## Telephony management

Manage inbound and outbound telephony for an assistant. These endpoints provision and configure LiveKit trunks, assign phone numbers, and start test calls.

<Callout kind="alert">

Most telephony management endpoints require session authentication and do not support API key authentication. Only the phone-numbers list endpoint supports API keys.

</Callout>

| Method | Path | Purpose | Auth |
| --- | --- | --- | --- |
| `GET` | `/api/assistants/{assistantId}/telephony/phone-numbers` | List phone numbers assigned to the assistant | API key or session |
| `PATCH` | `/api/assistants/{assistantId}/telephony/phone-numbers` | Assign phone numbers to the assistant | API key or session |
| `POST` | `/api/assistants/{assistantId}/telephony/inbound` | Enable or disable inbound calling | Session only |
| `POST` | `/api/assistants/{assistantId}/telephony/outbound` | Enable or disable outbound calling | Session only |
| `POST` | `/api/assistants/{assistantId}/telephony/settings` | Update telephony settings (phone numbers, voicemail, compliance) | Session only |
| `POST` | `/api/assistants/{assistantId}/telephony/test-call` | Start a test call | Session only |
| `POST` | `/api/assistants/{assistantId}/telephony/assign-phone-numbers` | Assign phone numbers with carrier validation | Session only |

### List assigned phone numbers

Retrieve active, non-deleted phone numbers assigned to the assistant. Results include numbers that are unassigned or assigned to this assistant, sorted by phone number ascending.

### Endpoint

`GET /api/assistants/{assistantId}/telephony/phone-numbers`

### Path parameters

<ParamField path="assistantId" param-type="string" required="true">
The assistant UUID.
</ParamField>

### Query parameters

<ParamField query="accountSlug" param-type="string" required="false">
Account slug to resolve the workspace.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the request succeeds.
</ResponseField>

<ResponseField name="numbers" field-type="array" required="true">
Array of phone number objects. Each object includes `id`, `phone_number`, `status`, `is_trial`, `trial_expires_at`, `assistant_id`, `provider`, `ownership_type`, `country_code`, `provider_account_id`, `provider_account_sid`, and account label fields.

### Update telephony settings

Configure phone number assignments, voicemail, compliance, and destination country in a single request. This endpoint handles LiveKit provisioning, voicemail detection, and compliance consent flows.

### Endpoint

`POST /api/assistants/{assistantId}/telephony/settings`

### Body parameters

<ParamField body="accountSlug" param-type="string" required="true">
Account slug for workspace resolution.
</ParamField>

<ParamField body="phoneNumberIds" param-type="array" required="true">
Array of phone number UUIDs to assign. IDs are deduplicated automatically.
</ParamField>

<ParamField body="inboundEnabled" param-type="boolean" required="true">

</ParamField>

<ParamField body="outboundEnabled" param-type="boolean" required="true">
Whether to enable outbound calling.
</ParamField>

<ParamField body="telnyxConnectionId" param-type="string" required="false">
Telnyx connection credential ID. An empty string is converted to null.

<ParamField body="destinationCountry" param-type="string" required="false">

</ParamField>

<ParamField body="voicemail" param-type="object" required="false">
Voicemail detection settings. Includes `detectionEnabled` (boolean), `action` (string, maximum 40 characters), and `message` (string, maximum 2000 characters).
</ParamField>

<ParamField body="compliance" param-type="object" required="false">
Compliance consent settings. Includes `enabled` (boolean), `templateId` (string, UUID when non-null), `briefingText` (string, maximum 2000 characters), `language` (string, maximum 20 characters), `requireAck` (boolean), `fallbackPolicy` (`retry`, `block`, or `continue`), and `ackTimeoutSeconds` (integer, 3 to 60). </ResponseField>

<ResponseField name="assignedActive" field-type="number" required="true">
Number of active phone numbers assigned after the update.
</ResponseField>

<Callout kind="info">

</Callout>
