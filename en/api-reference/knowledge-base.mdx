## Knowledge base endpoints

Manage knowledge base files in two layers:

- **Account-level files** under `/api/kb/files` store the source documents for your workspace.
- **Assistant attachments** under `/api/assistants/{assistantId}/knowledge-base` control which account-level files a specific assistant can use during retrieval.

Upload files at the account level first. After a file finishes processing, attach it to one or more assistants.

<Callout kind="info">

Most knowledge base management endpoints support either an authenticated browser session or API key authentication through `withApiAuth`.

- Use API keys with **`kb:read`** scope to list or read files.
- Use API keys with **`kb:write`** scope to upload, delete, reprocess, or attach files.
- Two endpoints are **session-only**:
  - `GET /api/kb/files/{fileId}/download`
  - `POST /api/kb/search`
  - `DELETE /api/assistants/{assistantId}/knowledge-base/{fileId}`

</Callout>

<Callout kind="alert">

Assistant-level `POST /api/assistants/{assistantId}/knowledge-base` does **not** upload a file. It attaches an existing account-level file by `file_id`.

</Callout>

## Endpoint summary

| Method | Path | Purpose | Auth |
| --- | --- | --- | --- |
| `GET` | `/api/kb/files` | List account-level knowledge base files | API key with `kb:read` or session cookie |
| `POST` | `/api/kb/files` | Upload an account-level knowledge base file | API key with `kb:write` or session cookie |
| `GET` | `/api/kb/files/{fileId}` | Get a single account-level file record | API key with `kb:read` or session cookie |
| `DELETE` | `/api/kb/files/{fileId}` | Delete an account-level file record | API key with `kb:write` or session cookie |
| `POST` | `/api/kb/files/{fileId}/reprocess` | Re-enqueue a file for processing | API key with `kb:write` or session cookie |
| `GET` | `/api/kb/files/{fileId}/download` | Get a signed download URL | Session cookie |
| `POST` | `/api/kb/search` | Run semantic search across knowledge base content | Session cookie |
| `GET` | `/api/assistants/{assistantId}/knowledge-base` | List files attached to an assistant | API key with `kb:read` or session cookie |
| `POST` | `/api/assistants/{assistantId}/knowledge-base` | Attach an existing account-level file to an assistant | API key with `kb:write` or session cookie |
| `DELETE` | `/api/assistants/{assistantId}/knowledge-base/{fileId}` | Detach a file from an assistant | Session cookie |

## Upload an account-level knowledge base file

Upload a source document to your account before attaching it to an assistant.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/files" \
  --header "Authorization: Bearer tt_key_example_kb_write_4mn8pz" \
  --form "file=@./docs/acme-support-playbook.pdf;type=application/pdf"
```

```javascript
const formData = new FormData();
formData.append("file", fileInput.files[0]);

const response = await fetch("https://app.talkturo.com/api/kb/files", {
  method: "POST",
  headers: {
    Authorization: "Bearer tt_key_example_kb_write_4mn8pz",
  },
  body: formData,
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "credits_charged": 0,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "filename": "acme-support-playbook.pdf",
    "mime_type": "application/pdf",
    "size_bytes": 248193,
    "status": "pending"
  }
}
```
</Response>

A successful upload means Talkturo accepted the file and queued it for processing. The file may remain in `pending` or `processing` status before it becomes searchable or attachable for production use.

<Callout kind="info">

Upload behavior follows these rules:

- Accepted MIME types: `application/pdf`, `application/msword`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `text/plain`, `text/markdown`
- Maximum file size: 1 GB
- First 50 MB of total account knowledge base storage is free
- Each additional 50 MB costs 1 credit
- Duplicate uploads are deduplicated by SHA-256 hash

</Callout>

## Search knowledge base content

Run semantic search across processed knowledge base chunks.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/search" \
  --cookie "sb-access-token=sb_example_session_token" \
  --header "Content-Type: application/json" \
  --data '{
    "accountId": "acc_7k29qm41xv",
    "query": "What is Acme Healths return window for unopened devices?",
    "assistantId": "9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2",
    "limit": 3
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/kb/search", {
  method: "POST",
  credentials: "include",
  headers: {
    "Content-Type": "application/json",
```

## Typical workflow

Use the knowledge base endpoints in this order when automating document management:

<Steps>
<Step title="Upload the file to your account" icon="upload">

Send `POST /api/kb/files` with `multipart/form-data` and a `file` field.

Success looks like a response with `success: true`, `credits_charged`, and a `file` object whose initial `status` is `pending`.

</Step>
<Step title="Wait for processing to finish" icon="check-circle">

Call `GET /api/kb/files` or `GET /api/kb/files/{fileId}` and inspect the file `status`.

Your workflow can continue once the file reaches a ready state such as `processed` and `status_error` remains empty.

</Step>
<Step title="Attach the file to an assistant" icon="plus">

Send `POST /api/assistants/{assistantId}/knowledge-base` with a JSON body containing `file_id`.

A successful attach returns `success: true`. If the file was already attached, the response also includes `idempotent: true`.

</Step>
<Step title="Search processed content" icon="search">

Send `POST /api/kb/search` with your `accountId`, query text, and optional `assistantId`.

Success looks like a response with a `results` array containing matched chunks and similarity scores.

</Step>
</Steps>
