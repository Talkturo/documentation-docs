## Knowledge base endpoints

Manage assistant-specific knowledge base files with authenticated endpoints under `/api/kb`. Uploaded files are stored per account, can be attached to assistants, and are processed for retrieval during calls.

<Callout kind="info">

These endpoints accept either an authenticated browser session or API key Bearer token authentication.

When you use an API key, include the required scope for each operation:

- `GET /api/kb/files` requires `kb:read`
- `POST /api/kb/files` requires `kb:write`
- `DELETE /api/kb/files/{fileId}` requires `kb:write`
- `POST /api/kb/files/{fileId}/reprocess` requires `kb:write`
- `POST /api/kb/search` requires `kb:read`

</Callout>

<Callout kind="alert">

Upload requests use `multipart/form-data` and must include a file field. Accepted file types are `application/pdf`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `application/msword`, `text/plain`, and `text/markdown`. Maximum file size is 1 GB.

Files are deduplicated by SHA-256 hash. Processing happens after upload, so a newly uploaded file may appear with a non-ready `status` before it becomes available for retrieval.

</Callout>

## Endpoint summary

| Method | Path | Purpose | Auth |
| --- | --- | --- | --- |
| `GET` | `/api/kb/files` | List knowledge base files | Session cookie or Bearer token |
| `POST` | `/api/kb/files` | Upload a knowledge base file | Session cookie or Bearer token |
| `DELETE` | `/api/kb/files/{fileId}` | Delete a knowledge base file | Session cookie or Bearer token |
| `POST` | `/api/kb/files/{fileId}/reprocess` | Reprocess a knowledge base file | Session cookie or Bearer token |
| `POST` | `/api/kb/search` | Search the knowledge base for assistant retrieval | Session cookie or Bearer token |

## List knowledge base files

Return all knowledge base files in your account. Add `?include=attachment_count` if you need the number of assistant attachments for each file.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request GET \
  --url "https://app.talkturo.com/api/kb/files?include=attachment_count" \
  --header "Authorization: Bearer ttr_example_kb_read_token"
```

```javascript
const response = await fetch(
  "https://app.talkturo.com/api/kb/files?include=attachment_count",
  {
    method: "GET",
    headers: {
      Authorization: "Bearer ttr_example_kb_read_token",
    },
  }
);

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "files": [
    {
      "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
      "filename": "acme-pricing-guide.pdf",
      "size": 248193,
      "type": "application/pdf",
      "status": "ready",
      "attachment_count": 2,
      "created_at": "2026-02-11T14:22:09.000Z"
    },
    {
      "id": "4f6c291e-a60d-4ff3-9cb2-52e2b65f6b31",
      "filename": "returns-policy.docx",
      "size": 91344,
      "type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
      "status": "embedding",
      "attachment_count": 1,
      "created_at": "2026-02-11T14:24:51.000Z"

```
</Response>

### Query parameters

<ParamField query="include" param-type="string" required="false" enum="attachment_count">
Optional related data to include in the response. Set to `attachment_count` to add an `attachment_count` field to each file object.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the request succeeds.
</ResponseField>

<ResponseField name="files" field-type="array" required="true">
List of knowledge base files in the account.
</ResponseField>

<ResponseField name="files[].id" field-type="uuid" required="true">
Unique file identifier. Use this value when deleting a file or requesting reprocessing.
</ResponseField>

<ResponseField name="files[].filename" field-type="string" required="true">
Original uploaded filename.
</ResponseField>

<ResponseField name="files[].size" field-type="number" required="true">
File size in bytes.
</ResponseField>

<ResponseField name="files[].type" field-type="string" required="true">
Detected file MIME type.
</ResponseField>

<ResponseField name="files[].status" field-type="string" required="true">
Processing state for the file. The pipeline moves through `pending`, `parsing`, `embedding`, `indexing`, and then ends in `ready` or `failed`.
</ResponseField>

<ResponseField name="files[].attachment_count" field-type="number" required="false">
Number of assistant attachments for the file. This field is returned only when you request `include=attachment_count`.
</ResponseField>

Timestamp when the file was uploaded.
</ResponseField>

## Upload a knowledge base file

Upload a file to the knowledge base with `multipart/form-data`.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/files" \
  --header "Authorization: Bearer ttr_example_kb_write_token" \
  --form "file=@./docs/acme-support-playbook.pdf"
```

```javascript
const formData = new FormData();
formData.append("file", fileInput.files[0]);

const response = await fetch("https://app.talkturo.com/api/kb/files", {
  method: "POST",
  headers: {
    Authorization: "Bearer ttr_example_kb_write_token",
  },
  body: formData,
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "filename": "acme-support-playbook.pdf",
    "size": 248193,
    "type": "application/pdf",
    "status": "pending",
    "created_at": "2026-02-11T14:22:09.000Z"
  }
}
```
</Response>

A successful upload confirms the file was accepted and queued for processing. Files with the same SHA-256 hash are deduplicated, so repeated uploads of identical content do not create separate stored copies.

### Body parameters

<ParamField body="file" param-type="binary" required="true">
The file to upload, sent as a `multipart/form-data` field.
</ParamField>

### File requirements

- Accepted MIME types: `application/pdf`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `application/msword`, `text/plain`, `text/markdown`
- Maximum file size: 1 GB
- Billing: the first 50 MB of total account knowledge base storage is free, and every additional 50 MB costs 1 credit

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the upload is accepted.
</ResponseField>

<ResponseField name="file" field-type="object" required="true">
Metadata for the uploaded file.
</ResponseField>

<ResponseField name="file.id" field-type="uuid" required="true">
Unique file identifier.
</ResponseField>

<ResponseField name="file.filename" field-type="string" required="true">
Original uploaded filename.
</ResponseField>

<ResponseField name="file.size" field-type="number" required="true">
File size in bytes.
</ResponseField>

<ResponseField name="file.type" field-type="string" required="true">
Detected file MIME type.
</ResponseField>

<ResponseField name="file.status" field-type="string" required="true">
Initial processing state after upload. New files enter the pipeline at `pending`.
</ResponseField>

<ResponseField name="file.created_at" field-type="string" required="true">
Timestamp when the file was created.
</ResponseField>

  --url "https://app.talkturo.com/api/kb/files/6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714" \
  --header "Authorization: Bearer ttr_example_kb_write_token"

const response = await fetch(
  "https://app.talkturo.com/api/kb/files/6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
  {
    method: "DELETE",
    headers: {
      Authorization: "Bearer ttr_example_kb_write_token",

## Get billing estimate

Retrieve the billing estimate for knowledge base storage and processing.

```bash
curl --request GET \
  --url "https://app.talkturo.com/api/kb/files" \
  --header "Authorization: Bearer ttr_example_kb_read_token"
```

The storage model includes 50 MB of free account knowledge base storage. Every additional 50 MB costs 1 credit.

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the estimate is available.
</ResponseField>

<ResponseField name="estimate" field-type="object" required="true">

</ResponseField>

## Standalone knowledge base endpoint

Search the knowledge base with `POST /api/kb/search` when you need retrieval results for a specific assistant.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/search" \
  --header "Authorization: Bearer ttr_example_kb_read_token" \
  --header "Content-Type: application/json" \
  --data '{
    "assistant_id": "9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2",
    "query": "What is the current return policy for annual contracts?",
    "top_k": 3
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/kb/search", {
  method: "POST",
  headers: {
    Authorization: "Bearer ttr_example_kb_read_token",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    assistant_id: "9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2",
    query: "What is the current return policy for annual contracts?",
    top_k: 3,
  }),
});

const data = await response.json();
console.log(data);
```
</Request>

### Body parameters

<ParamField body="assistant_id" param-type="uuid" required="true">
Assistant identifier used to scope retrieval.
</ParamField>

<ParamField body="query" param-type="string" required="true">
Natural-language search query to run against the knowledge base.
</ParamField>

<ParamField body="top_k" param-type="number" required="false">
Maximum number of results to return.
</ParamField>

<Callout kind="info">

The repository context for this page confirms the request body for `POST /api/kb/search`, but it does not provide a verified response schema. Check your deployed API before depending on a specific result shape in production.

</Callout>

If `POST /api/kb/search` exists in your environment, treat it as separate from file upload and deletion flows. Use it when you need retrieval results rather than file management.

## Typical workflow

Use the knowledge base endpoints in this order when automating document management:

<Steps>
<Step title="Upload the file" icon="upload">

Send a `POST` request with `multipart/form-data` to `/api/kb/files`.

Success looks like a response with `success: true` and a `file` object.

</Step>
<Step title="Poll for processing status" icon="check-circle">

Call `GET /api/kb/files` and inspect each file's `status`.

Your workflow can continue once the uploaded file appears in the list and its status reaches `ready`.

</Step>
<Step title="Estimate storage cost when needed" icon="bar-chart">

Review total account knowledge base storage before large uploads. The first 50 MB is free, and every additional 50 MB costs 1 credit.

Success looks like a storage total that matches your expected billing tier.

</Step>
<Step title="Search or remove files" icon="trash">

Use `POST /api/kb/search` when you need retrieval results, or `DELETE /api/kb/files/{fileId}` when you no longer want to keep a file.

A successful deletion returns `success: true` and a confirmation message.

</Step>
</Steps>
