## Knowledge base API

Use the Knowledge Base API to upload, search, download, reprocess, and delete files in your workspace library. Attach existing library files to assistants so they can use ready documents when answering questions during voice calls.

The API exposes two related surfaces:

- **Workspace library:** `/api/kb/*` manages files and searches attached, processed documents.
- **Assistant attachments:** `/api/assistants/{assistantId}/knowledge-base` attaches or detaches existing library files from an assistant.

<Callout kind="info">

Both session JWT authentication and API key authentication are supported. API keys require `kb:read` for file listing, metadata, downloads, and search. They require `kb:write` for uploads, deletion, reprocessing, and assistant attachment changes.

</Callout>

## Endpoint summary

| Method | Path | Purpose | Required API key scope |
| --- | --- | --- | --- |
| `POST` | `/api/kb/files` | Upload a file to the workspace library | `kb:write` |
| `GET` | `/api/kb/files` | List workspace library files | `kb:read` |
| `GET` | `/api/kb/files/{fileId}` | Get file metadata | `kb:read` |
| `DELETE` | `/api/kb/files/{fileId}` | Permanently delete a file | `kb:write` |
| `GET` | `/api/kb/files/{fileId}/download` | Create a signed download URL | `kb:read` |
| `POST` | `/api/kb/files/{fileId}/reprocess` | Reprocess a file | `kb:write` |
| `POST` | `/api/kb/search` | Search ready files attached to an assistant | `kb:read` |
| `GET` | `/api/assistants/{assistantId}/knowledge-base` | List files attached to an assistant | `kb:read` |
| `POST` | `/api/assistants/{assistantId}/knowledge-base` | Attach an existing library file | `kb:write` |
| `DELETE` | `/api/assistants/{assistantId}/knowledge-base/{fileId}` | Detach a file from an assistant | `kb:write` |

## File object

File endpoints return a file object with the following fields.

<ResponseField name="id" field-type="uuid" required="true">
Unique identifier for the file in the workspace library.
</ResponseField>

<ResponseField name="filename" field-type="string" required="true">
Original name of the uploaded file.
</ResponseField>

<ResponseField name="mime_type" field-type="string" required="true">
MIME type detected for the uploaded file.
</ResponseField>

<ResponseField name="size_bytes" field-type="number" required="true">
File size in bytes.
</ResponseField>

<ResponseField name="status" field-type="string" required="true">
Processing status. Possible values are `pending`, `parsing`, `embedding`, `indexing`, `ready`, and `failed`.
</ResponseField>

<ResponseField name="status_error" field-type="string" required="true">
Processing error details when `status` is `failed`. Returns `null` when no processing error exists.
</ResponseField>

<ResponseField name="char_count" field-type="number" required="true">
Number of extracted characters. Returns `null` before extraction completes or when extraction does not produce a count.
</ResponseField>

<ResponseField name="chunk_count" field-type="number" required="true">
Number of chunks generated for retrieval. Returns `null` before chunking completes or when no chunks are available.
</ResponseField>

<ResponseField name="created_at" field-type="string" required="true">
Timestamp when the file was added to the workspace library.
</ResponseField>

<ResponseField name="updated_at" field-type="string" required="true">
Timestamp when the file metadata or processing state was last updated.
</ResponseField>

<Callout kind="info">

File processing follows this status flow: `pending` → `parsing` → `embedding` → `indexing` → `ready`. A processing error changes the status to `failed`, and `status_error` contains the failure details when available.

</Callout>

## Upload a file

Upload a PDF, DOCX, TXT, or MD file to the workspace knowledge base library.

The endpoint accepts one `file` field in a `multipart/form-data` request. Files can be up to 1 GiB. The first 50 MiB of stored files is free; each additional 50 MiB costs 1 storage credit.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/files" \
  --header "Authorization: Bearer tk_live_example_7f3a9c2d" \
  --form "file=@./docs/acme-support-playbook.pdf"
```

```javascript
const formData = new FormData();
formData.append("file", fileInput.files[0]);

const response = await fetch("https://app.talkturo.com/api/kb/files", {
  method: "POST",
  body: formData,
  credentials: "include",
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="201,200">
```json
{
  "success": true,
  "credits_charged": 0,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "filename": "acme-support-playbook.pdf",
    "mime_type": "application/pdf",
    "size_bytes": 248193,
    "status": "pending",
    "status_error": null,
    "char_count": null,
    "chunk_count": null,
    "created_at": "2026-02-11T14:22:09.000Z",
    "updated_at": "2026-02-11T14:22:09.000Z"
  }
}
```

```json
{
  "success": true,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "status": "ready"
  },
  "deduplicated": true,
  "message": "File already exists"
}
```
</Response>

A new upload returns `credits_charged` and a complete file object. The file remains unavailable to search until its status becomes `ready`.

If the library already contains the same file, the API avoids storing a duplicate and returns `deduplicated: true`. The deduplicated response includes the existing file identifier and current status instead of charging storage for another copy.

### Body parameters

<ParamField body="file" param-type="binary" required="true">
PDF, DOCX, TXT, or MD file to add to the workspace library. The maximum file size is 1 GiB.
</ParamField>

<ParamField path="fileId" param-type="uuid" required="true">

## Search the knowledge base

Search files attached to a specific assistant. Search only considers files with a `ready` status.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/search" \
  --header "Authorization: Bearer tk_live_example_7f3a9c2d" \
  --header "Content-Type: application/json" \
  --data '{
    "assistant_id": "9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2",
    "query": "What is the return window for unopened equipment?",
    "top_k": 6
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/kb/search", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  credentials: "include",
  body: JSON.stringify({
    assistant_id: "9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2",
    query: "What is the return window for unopened equipment?",
    top_k: 6,
  }),
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "hits": [
    {
      "rank": 1,
      "file_id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
      "filename": "acme-support-playbook.pdf",
      "chunk_index": 12,
      "page_number": 4,
      "content": "Unopened equipment may be returned within 30 days of delivery.",
      "similarity": 0.9241,
      "match_type": "semantic",
      "adjacent": false
    }
  ]
}
```

```json
{
  "success": true,
  "hits": [],
  "reason": "no_ready_files"
}
```
</Response>

The search is restricted to files attached to the specified assistant. A file must have `status` set to `ready` before it can produce a hit.

### Body parameters

<ParamField body="assistant_id" param-type="uuid" required="true">
Assistant whose attached knowledge base files should be searched.
</ParamField>

<ParamField body="query" param-type="string" required="true">
Search query with 1 to 2000 characters.
</ParamField>

<ParamField body="top_k" param-type="integer" required="false">
Maximum number of results to return. Accepts values from 1 to 20 and defaults to 6.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the search request succeeds.
</ResponseField>

<ResponseField name="hits" field-type="array" required="true">
Ranked search results. The array is empty when no attached files are ready or no files are attached.
</ResponseField>

<ResponseField name="hits[].rank" field-type="number" required="true">
One-based ranking of the result.
</ResponseField>

<ResponseField name="hits[].file_id" field-type="uuid" required="true">
Identifier of the file containing the matching chunk.
</ResponseField>

<ResponseField name="hits[].filename" field-type="string" required="true">
Filename containing the matching chunk.
</ResponseField>

<ResponseField name="hits[].chunk_index" field-type="number" required="true">
Zero-based index of the matching chunk within the file.
</ResponseField>

<ResponseField name="hits[].page_number" field-type="number" required="true">
Page number associated with the matching content when available.
</ResponseField>

<ResponseField name="hits[].content" field-type="string" required="true">
Text content of the matching chunk.
</ResponseField>

<ResponseField name="hits[].similarity" field-type="number" required="true">
Similarity score for the match.
</ResponseField>

<ResponseField name="hits[].match_type" field-type="string" required="true">
Matching strategy used for the result.
</ResponseField>

<ResponseField name="hits[].adjacent" field-type="boolean" required="true">
Indicates whether the result represents adjacent context included with a primary match.
</ResponseField>

<ResponseField name="reason" field-type="string" required="false">
Reason returned with an empty result set. Possible values include `no_files_attached` and `no_ready_files`.

## Typical workflow

Use the workspace library and assistant attachment endpoints together when preparing retrieval content for a voice assistant.

<Steps>
<Step title="Upload the file" icon="upload">

Send `POST /api/kb/files` with the document in the `file` multipart field.

A successful response returns a file object with `status: pending`, or a deduplicated response for an existing file.

</Step>

<Step title="Poll the processing status" icon="check-circle">

Call `GET /api/kb/files/{fileId}` or `GET /api/kb/files` and inspect the file status.

Continue when the status becomes `ready`. If the status becomes `failed`, inspect `status_error` before retrying or reprocessing the file.

</Step>

<Step title="Search the knowledge base" icon="search">

Call `POST /api/kb/search` with the assistant identifier and a query.

Search returns chunks only from ready files attached to the specified assistant.

</Step>

<Step title="Attach the file to an assistant" icon="users">

Send `POST /api/assistants/{assistantId}/knowledge-base` with the existing `file_id`.

The endpoint returns `idempotent: true` when the relationship already exists.

</Step>

<Step title="Detach the file when needed" icon="minus">

Send `DELETE /api/assistants/{assistantId}/knowledge-base/{fileId}` to remove the file from the assistant.

The file remains in the workspace library and can be attached to another assistant.

</Step>
</Steps>
