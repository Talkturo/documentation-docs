## Knowledge base endpoints

Manage knowledge base files in two layers: an **account-level library** under `/api/kb/files` and **assistant-scoped attachments** under `/api/assistants/{assistantId}/knowledge-base`. Upload files once to your account library, wait for processing to finish, then attach ready files to one or more assistants.

<Callout kind="info">

Knowledge base endpoints accept either an authenticated browser session or an API key.

- Use a **session cookie** when calling from the Talkturo app at `app.talkturo.com`.
- Use an **API key** when calling from server-side integrations at `api.talkturo.com`.
- API keys need `kb:read` scope for `GET` endpoints and `kb:write` scope for `POST` and `DELETE` endpoints.

</Callout>

<Callout kind="alert">

Uploading a file does not attach it to any assistant. Upload creates or reuses an account-level library file first. Assistants can only search files that are both attached and in `ready` status.

</Callout>

## Endpoint summary

| Method | Path | Purpose | Auth |
| --- | --- | --- | --- |
| `GET` | `/api/kb/files` | List account KB files | Session or API Key (`kb:read`) |
| `POST` | `/api/kb/files` | Upload a new KB file | Session or API Key (`kb:write`) |
| `GET` | `/api/kb/files/{fileId}` | Get metadata for one file | Session or API Key (`kb:read`) |
| `DELETE` | `/api/kb/files/{fileId}` | Delete a KB file permanently | Session or API Key (`kb:write`) |
| `GET` | `/api/kb/files/{fileId}/download` | Get a signed download URL | Session or API Key (`kb:read`) |
| `POST` | `/api/kb/files/{fileId}/reprocess` | Force reprocessing for a file | Session or API Key (`kb:write`) |
| `POST` | `/api/kb/search` | Run semantic search across attached files | Session or API Key (`kb:read`) |
| `GET` | `/api/assistants/{assistantId}/knowledge-base` | List files attached to an assistant | Session or API Key (`kb:read`) |
| `POST` | `/api/assistants/{assistantId}/knowledge-base` | Attach an existing account KB file to an assistant | Session or API Key (`kb:write`) |
| `DELETE` | `/api/assistants/{assistantId}/knowledge-base/{fileId}` | Detach a file from an assistant | Session or API Key (`kb:write`) |

## Upload a knowledge base file

Upload a new file into the account-level library with `multipart/form-data`. Talkturo accepts PDF, DOCX, DOC, TXT, and Markdown files up to 1 GB.

<Request tabs="cURL session,cURL API key,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/kb/files" \
  --cookie "sb-access-token=sb_example_session_token" \
  --form "file=@./docs/acme-support-playbook.pdf"
```

```bash
curl --request POST \
  --url "https://api.talkturo.com/api/kb/files" \
  --header "Authorization: Bearer tk_example_kb_write_4pm3r8n1" \
  --form "file=@./docs/acme-support-playbook.pdf"
```

```javascript
const formData = new FormData();
formData.append("file", fileInput.files[0]);

const response = await fetch("https://api.talkturo.com/api/kb/files", {
  method: "POST",
  headers: {
    Authorization: "Bearer tk_example_kb_write_4pm3r8n1",
  },
  body: formData,
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200 accepted,200 deduplicated,402 insufficient credits" default-tab="1">
```json
{
  "success": true,
  "credits_charged": 0,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "filename": "acme-support-playbook.pdf",
    "mime_type": "application/pdf",
    "size_bytes": 248193,
    "status": "pending"
  }
}
```

```json
{
  "success": true,
  "file": {
    "id": "6b9d58b9-4b43-4f94-8cb8-2d3d9f18d714",
    "status": "ready"
  },
  "deduplicated": true,
  "message": "Identical file already in your library — reusing existing record."
}
```

```json
{
  "error": "Not enough credits to store this file",
  "reason": "insufficient_credits",
  "required_credits": 2,
  "balance": 1
}
```
</Response>

A successful upload means the file was accepted into the account library. It may remain in `pending` or `processing` status until parsing, chunking, and embedding complete.

<Callout kind="info">

Storage billing includes the first 50 MB at no charge. Each additional 50 MB of stored knowledge base data costs 1 credit.

</Callout>

| Status code | Meaning |
| --- | --- |

| `413` | File exceeds the 1 GB limit |
| `415` | Unsupported file type |

## Search the knowledge base

Run semantic search against the ready files attached to an assistant. Search does not query the entire account library. It only searches files currently attached to the assistant you specify.

<Request tabs="cURL API key,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://api.talkturo.com/api/kb/search" \
  --header "Authorization: Bearer tk_example_kb_read_9xmk7q2r" \
  --header "Content-Type: application/json" \
  --data '{
    "assistant_id": "9d3f6cf5-3c12-4e60-bd8a-1b1d57a8c4d2",
    "query": "What is Acme Health''s return window for unopened devices?",
    "top_k": 3
  }'
```

```javascript
const response = await fetch("https://api.talkturo.com/api/kb/search", {
  method: "POST",
  headers: {
    Authorization: "Bearer tk_example_kb_read_9xmk7q2r",

    query: "What is Acme Health's return window for unopened devices?",
```

## Common workflow

Move files from raw upload to searchable assistant context in four steps.

<Steps>
<Step title="Upload a file to the account library" icon="upload">

Send `POST /api/kb/files` with a `multipart/form-data` file field.

Success looks like `success: true` with a `file.id` you can reuse later.

</Step>
<Step title="Wait until the file is ready" icon="check-circle">

Poll `GET /api/kb/files` or `GET /api/kb/files/{fileId}` until the file status becomes `ready`.

If processing fails, the file returns `status: failed` and `status_error` explains why.

</Step>
<Step title="Attach the file to an assistant" icon="users">

Send `POST /api/assistants/{assistantId}/knowledge-base` with the existing `file_id`.

Success looks like `success: true`. Attaching the same file again does not create duplicates.

</Step>
<Step title="Search attached content" icon="search">

Send `POST /api/kb/search` with `assistant_id` and a query string.

A successful search returns ranked `hits`. If you get `reason: no_ready_files`, wait for processing to finish before searching again.

</Step>
</Steps>
