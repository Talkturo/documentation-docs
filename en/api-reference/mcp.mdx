## Endpoint summary

| Method | Path | Purpose | Auth |
| --- | --- | --- | --- |
| `GET` | `/api/mcp/providers` | List available MCP providers | Session cookie |
| `GET` | `/api/mcp/plugins` | List plugins, connections, and assistant selections | Session cookie |
| `POST` | `/api/mcp/plugins/select` | Attach or detach a plugin for an assistant | Session cookie |
| `GET` | `/api/mcp/plugins/tools` | List tools available for a workspace connection | Session cookie |
| `POST` | `/api/mcp/plugins/connect-key` | Connect a provider using an API key | Session cookie |
| `POST` | `/api/mcp/oauth/authorize` | Generate an OAuth authorization URL for a provider | Session cookie |
| `GET` | `/api/mcp/oauth/callback` | Handle the OAuth callback from a provider | None (redirect target) |

<Callout kind="info">

All MCP plugin endpoints use the Talkturo web session for authentication. Send the authenticated Supabase session cookie with each request. These endpoints do not accept API keys.

</Callout>

## POST /api/mcp/plugins/select

Attaches a provider connection to an assistant and stores the selected tool list. If `tools` is an empty array, Talkturo detaches the plugin from the assistant and deletes the saved configuration.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl --request POST \
  --url "https://app.talkturo.com/api/mcp/plugins/select" \
  --header "Content-Type: application/json" \
  --header "Cookie: sb-access-token=sb_example_access_token; sb-refresh-token=sb_example_refresh_token" \
  --data '{
    "assistantId": "1d9d4e3c-5296-4f9b-a6b7-4f0f2f5851d4",
    "accountSlug": "acme",
    "provider": "google-drive",
    "connectionId": "8f2546ec-2f4f-4e1d-8f39-654f7f2bbf2d",
    "tools": ["drive.search", "drive.get_file"]
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/mcp/plugins/select", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Cookie: "sb-access-token=sb_example_access_token; sb-refresh-token=sb_example_refresh_token"
  },
  body: JSON.stringify({
    assistantId: "1d9d4e3c-5296-4f9b-a6b7-4f0f2f5851d4",
    accountSlug: "acme",
    provider: "google-drive",
    connectionId: "8f2546ec-2f4f-4e1d-8f39-654f7f2bbf2d",
    tools: ["drive.search", "drive.get_file"]
  })
})

const data = await response.json()
console.log(data)
```
</Request>

<Response tabs="200,400,404" default-tab="1">
```json
{
  "ok": true,
  "attached": true
}
```

```json
{
  "error": "tools must contain at most 100 items"
}
```

```json
{
  "error": "Connection not found"
}
```
</Response>

### Body parameters

<ParamField body="assistantId" param-type="string" required="true">
Assistant UUID that will receive the plugin selection.
</ParamField>

<ParamField body="accountSlug" param-type="string" required="true">
Workspace account slug.
</ParamField>

<ParamField body="provider" param-type="string" required="true">

<ResponseField name="attached" field-type="boolean" required="true">

</ResponseField>

## GET /api/mcp/oauth/callback

Handle the OAuth callback from a provider. After the user authorizes the connection at the provider's site, the provider redirects back to this endpoint with an authorization code.

<Callout kind="info">

This endpoint does not return JSON. It returns an HTML popup page that communicates the result to the opener window using `postMessage`, `BroadcastChannel`, and `localStorage`. The published payload has the shape `{ type: "mcp_oauth_result", ok: boolean, provider: string, connectionId?: string, error?: string, at: number }`.

</Callout>

### Query parameters

<ParamField query="code" param-type="string" required="false">
Authorization code returned by the provider. Required unless the provider returns an `error`.
</ParamField>

<ParamField query="state" param-type="string" required="false">
State value returned by the provider. Required unless the provider returns an `error`.
</ParamField>

<ParamField query="error" param-type="string" required="false">
OAuth error returned by the provider when authorization fails.
</ParamField>

### Published payload

The HTML page publishes the following JSON payload to the opener window:

<ResponseField name="type" field-type="string" required="true">
Always `mcp_oauth_result`.
</ResponseField>

<ResponseField name="ok" field-type="boolean" required="true">
Whether the OAuth connection succeeded.
</ResponseField>

<ResponseField name="provider" field-type="string" required="true">
Provider identifier.
</ResponseField>

<ResponseField name="connectionId" field-type="string" required="false">
Connection UUID. Present only when `ok` is `true`.
</ResponseField>

<ResponseField name="error" field-type="string" required="false">
Error identifier. Present only when `ok` is `false`.
</ResponseField>

<ResponseField name="at" field-type="number" required="true">
Timestamp when the payload was generated.
</ResponseField>

### Possible error values

| Error value | Meaning |
| --- | --- |
| `missing_code_or_state` | The provider did not return `code` or `state` |
| `state_missing` | State cookie was not found |
| `state_mismatch` | State hash did not match the expected value |
| `bad_context` | OAuth context could not be deserialized |
| `unknown_provider` | Provider not recognized |
| `client_secret_missing` | Provider client secret is not configured |
| `token_exchange_failed` | Token exchange with the provider failed |
| `save_failed` | Connection could not be saved |
| `callback_failed` | Unexpected error during callback processing |

## Error behavior

All endpoints require an authenticated Talkturo session. Beyond `401 Unauthorized`, MCP plugin endpoints can return the following status codes depending on the route and workspace state:

| Status | Meaning |
| --- | --- |
| `400` | Missing or invalid query or body parameters |
| `401` | Missing or invalid session |
| `403` | Authenticated, but not allowed to access the workspace or assistant |
| `404` | Requested assistant or connection was not found |
| `500` | Unexpected server error |
