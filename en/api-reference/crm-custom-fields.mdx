## Manage CRM custom fields

Custom fields let you extend Talkturo CRM records with data that does not fit the default schema. Use these endpoints to define fields for **contacts** and **companies**, then read, update, or remove those definitions later.

<Callout kind="info">

All CRM custom field endpoints require **session cookie authentication**. These endpoints do not accept API keys.

</Callout>

## Endpoints at a glance

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/crm/custom-fields` | List all custom fields |
| `POST` | `/api/crm/custom-fields` | Create a custom field |
| `GET` | `/api/crm/custom-fields/{id}` | Get one custom field by ID |
| `PUT` | `/api/crm/custom-fields/{id}` | Update a custom field |
| `DELETE` | `/api/crm/custom-fields/{id}` | Delete a custom field |

## Field types and entity types

Use one of the supported field types when you create a custom field:

- **`text`** — single-line string values
- **`textarea`** — multi-line string values
- **`number`** — numeric values
- **`date`** — date values
- **`select`** — one value from a defined list of options
- **`boolean`** — true or false values

Attach each custom field to one CRM entity type:

- **`contact`**
- **`company`**

If you create a `select` field, include `options.options` in the request body as a non-empty array.

## Create a custom field

Creates a new custom field definition for a contact or company.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/crm/custom-fields" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m" \
  -d '{
    "teamId": "team_9f2b7c41",
    "key": "customer_tier",
    "label": "Customer tier",
    "fieldType": "select",
    "entityType": "company",
    "options": {
      "options": ["Starter", "Growth", "Enterprise"]
    },
    "isRequired": false,
    "sortOrder": 30,
    "isActive": true
  }'
```
</Request>

<Response>
```json
{
  "success": true,
  "field": {
    "id": "ec607f3e-77c8-45e7-a58d-62b8d09c4d5d",
    "teamId": "team_9f2b7c41",
    "key": "customer_tier",
    "label": "Customer tier",
    "fieldType": "select",
    "entityType": "company",
    "options": {
      "options": [
        "Starter",
        "Growth",
        "Enterprise"
      ]
    },
    "isRequired": false,
    "sortOrder": 30,
    "isActive": true,
    "created_at": "2025-01-14T15:27:49.000Z",
    "updated_at": "2025-01-14T15:27:49.000Z"
  }
}
```
</Response>

### Body parameters

<ParamField body="teamId" param-type="string" required="true">
Team identifier that owns the custom field.
</ParamField>

<ParamField body="key" param-type="string" required="true">
Stable field key. The API normalizes this value to `snake_case` and validates it against `^[a-z][a-z0-9_]{1,63}$`. The database enforces uniqueness, and duplicate keys return a `23505` constraint violation.
</ParamField>

<ParamField body="label" param-type="string" required="true">
Field label shown in the CRM.
</ParamField>

<ParamField body="fieldType" param-type="string" required="true" enum="text,number,boolean,date,select,textarea">
Custom field type.
</ParamField>

<ParamField body="entityType" param-type="string" required="true" enum="company,contact">
CRM record type that this field applies to.
</ParamField>

<ParamField body="options" param-type="object" required="false">
Configuration object for `select` fields. For `select`, pass `options.options` as a non-empty array of allowed values. Omit `options` for other field types.
</ParamField>

<ParamField body="isRequired" param-type="boolean" required="false">
Marks the field as required in supported CRM forms and workflows.
</ParamField>

<ParamField body="sortOrder" param-type="number" required="false">
Controls display order. Lower values appear first.
</ParamField>

<ParamField body="isActive" param-type="boolean" required="false">
Controls whether the field is active.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
`true` when the field is created successfully.
</ResponseField>

<ResponseField name="field" field-type="object" required="true">
The newly created custom field definition, including its `id`.
</ResponseField>

## Usage notes

Choose the field type carefully before you create it. A `select` field requires `options.options` as a non-empty array, while other field types do not use an options object.

Use the entity type to keep field definitions scoped to the right records. A field created for `contact` records does not apply to `company` records.

Use a stable `key` because the database enforces uniqueness per field definition. If you submit a duplicate key, the API returns a `23505` constraint violation.
