## Manage CRM custom fields

Custom fields let you extend Talkturo CRM records with data that does not fit the default schema. Use these endpoints to define fields for **contacts** and **companies**, then update or remove those definitions later.

<Callout kind="info">

All CRM custom field endpoints require **session cookie authentication**. These endpoints do not accept API keys.

</Callout>

## Endpoints at a glance

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/crm/custom-fields` | List custom fields |
| `POST` | `/api/crm/custom-fields` | Create a custom field |
| `PUT` | `/api/crm/custom-fields/{id}` | Update a custom field |
| `DELETE` | `/api/crm/custom-fields/{id}` | Delete a custom field |

## Supported entity types and field types

Create custom fields for these CRM entity types:

- **`contact`**
- **`company`**

Use one of these field types:

- **`text`** — single-line text
- **`textarea`** — multi-line text
- **`number`** — numeric values
- **`boolean`** — true or false values
- **`date`** — date values
- **`select`** — one value from a defined list of options

<Callout kind="tip">

When you create a `select` field, send `options` as an object with an `options` array. The array must contain at least one value.

</Callout>

## Create a custom field

Creates a new custom field definition for a contact or company. The server normalizes `key` by trimming whitespace, converting it to lowercase, and replacing internal spaces with underscores before validation and storage.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/crm/custom-fields" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m" \
  -d '{
    "teamId": "team_7f3d2a91",
    "entityType": "company",
    "key": "Customer Tier",
    "label": "Customer tier",
    "fieldType": "select",
    "options": {
      "options": ["Starter", "Growth", "Enterprise"]
    },
    "isRequired": false,
    "sortOrder": 10,
    "isActive": true
  }'
```
</Request>

<Response>
```json
{
  "success": true,
  "field": {
    "id": "ec607f3e-77c8-45e7-a58d-62b8d09c4d5d",
    "team_id": "team_7f3d2a91",
    "entity_type": "company",
    "key": "customer_tier",
    "label": "Customer tier",
    "field_type": "select",
    "options": {
      "options": [
        "Starter",
        "Growth",
        "Enterprise"
      ]
    },
    "is_required": false,

```

### Body parameters

<ParamField body="teamId" param-type="string" required="true">
Team identifier that owns the custom field.
</ParamField>

<ParamField body="entityType" param-type="string" required="true" enum="company,contact">
CRM record type that this field applies to.
</ParamField>

<ParamField body="key" param-type="string" required="true">
Unique field key for the team and entity type. The server normalizes the value before validation. The final key must match `^[a-z][a-z0-9_]{1,63}$`.
</ParamField>

<ParamField body="label" param-type="string" required="true">
Display label shown in the CRM.
</ParamField>

<ParamField body="fieldType" param-type="string" required="true" enum="text,number,boolean,date,select,textarea">
Custom field type.
</ParamField>

<ParamField body="options" param-type="object" required="false">
Required when `fieldType` is `select`. Send an object with an `options` array containing one or more allowed values.
</ParamField>

<ParamField body="isRequired" param-type="boolean" required="false">
Marks the field as required. Defaults to `false`.
</ParamField>

<ParamField body="sortOrder" param-type="number" required="false">
Controls display order. Defaults to `0`.
</ParamField>

<ParamField body="isActive" param-type="boolean" required="false">
Controls whether the field is active. Defaults to `true`.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
`true` when the field is created successfully.
</ResponseField>

<ResponseField name="field" field-type="object" required="true">
The newly created custom field definition.
</ResponseField>

## Update a custom field

Updates an existing custom field by ID. You can change the label, field type, options, required status, sort order, and active status. You cannot update `key` or `entity_type`.

<Request>
```bash
curl -X PUT "https://app.talkturo.com/api/crm/custom-fields/ec607f3e-77c8-45e7-a58d-62b8d09c4d5d" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m" \
  -d '{
    "label": "Account tier",
    "fieldType": "select",
    "options": {
      "options": ["Starter", "Growth", "Enterprise", "Strategic"]
    },
    "isRequired": true,
    "sortOrder": 5,
    "isActive": true
  }'
```
</Request>

## Delete a custom field

Deletes a custom field definition by ID. This endpoint permanently removes the field.

<Request>
```bash
curl -X DELETE "https://app.talkturo.com/api/crm/custom-fields/ec607f3e-77c8-45e7-a58d-62b8d09c4d5d" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m"
```
</Request>

<Response>
```json
{
  "success": true
}
```
</Response>

### Path parameters

<ParamField path="id" param-type="string" required="true">
UUID of the custom field to delete.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
`true` when the field is deleted successfully.
</ResponseField>
