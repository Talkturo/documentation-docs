## Manage CRM custom fields

Custom fields let you extend Talkturo CRM records with data that does not fit the default schema. Use these endpoints to define fields for **contacts**, then read, update, or remove those definitions later.

<Callout kind="info">

All CRM custom field endpoints require **session cookie authentication**. These endpoints do not accept API keys.

</Callout>

<Callout kind="alert">

Custom fields are only supported for the `contact` entity type. Company-level custom fields are deprecated.

</Callout>

## Endpoints at a glance

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/crm/custom-fields` | List all custom fields |
| `POST` | `/api/crm/custom-fields` | Create a custom field |
| `GET` | `/api/crm/custom-fields/{id}` | Get one custom field by ID |
| `PUT` | `/api/crm/custom-fields/{id}` | Update a custom field |
| `DELETE` | `/api/crm/custom-fields/{id}` | Delete a custom field |

## Field types and entity types

Use one of the supported field types when you create a custom field:

- **`text`** — freeform string values
- **`number`** — numeric values
- **`boolean`** — true or false values
- **`date`** — date values
- **`select`** — one value from a defined list of options
- **`textarea`** — multi-line text values

Attach each custom field to the supported CRM entity type:

- **`contact`**

<Callout kind="info">

Field keys must be `snake_case`, start with a letter, and be 2-64 characters long.

</Callout>

If you create a `select` field, set `options` to an object that contains an `options` array of strings.

## Create a custom field

Creates a new custom field definition for contacts.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/crm/custom-fields" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m" \
  -d '{
    "teamId": "2b6f1d24-9f0d-4df0-93c0-4db5d7468f12",
    "entityType": "contact",
    "key": "customer_tier",
    "label": "Customer tier",
    "fieldType": "select",
    "options": {
      "options": ["Starter", "Growth", "Enterprise"]
    },
    "isRequired": false,
    "sortOrder": 0,
    "isActive": true
  }'
```
</Request>

<Response>
```json
{
  "success": true,
  "field": {
    "id": "ec607f3e-77c8-45e7-a58d-62b8d09c4d5d",
    "teamId": "2b6f1d24-9f0d-4df0-93c0-4db5d7468f12",
    "key": "customer_tier",
    "label": "Customer tier",
    "fieldType": "select",
    "entityType": "contact",
    "options": {
      "options": [
        "Starter",
        "Growth",
        "Enterprise"
      ]
    },
    "isRequired": false,
    "sortOrder": 0,
    "isActive": true
  }
}
```
</Response>

### Body parameters

<ParamField body="teamId" param-type="string" required="true">
Team UUID that owns the custom field.
</ParamField>

<ParamField body="entityType" param-type="string" required="true" enum="contact">
CRM record type that this field applies to. Only `contact` is supported.
</ParamField>

<ParamField body="key" param-type="string" required="true">
Field key used internally. Use `snake_case`, start with a letter, and keep it between 2 and 64 characters.
</ParamField>

<ParamField body="label" param-type="string" required="true">
Display label shown in the CRM.
</ParamField>

<ParamField body="fieldType" param-type="string" required="true" enum="text,number,boolean,date,select,textarea">
Custom field type.
</ParamField>

<ParamField body="options" param-type="object" required="false">
Options object for configurable field types. For `select` fields, set this to an object with an `options` array of strings.
</ParamField>

<ParamField body="isRequired" param-type="boolean" required="false">
Marks the field as required. Defaults to `false`.
</ParamField>

<ParamField body="sortOrder" param-type="integer" required="false">
Display order for the field. Defaults to `0`.
</ParamField>

<ParamField body="isActive" param-type="boolean" required="false">
Controls whether the field is active. Defaults to `true`.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
`true` when the field is created successfully.
</ResponseField>

<ResponseField name="field" field-type="object" required="true">
The newly created custom field definition, including its `id`.
</ResponseField>

## Usage notes

Choose the field type carefully before you create it. A `select` field requires an `options` object with an `options` array, while other field types store single values without that configuration.

Use the entity type to keep field definitions scoped to the right records. Custom fields currently apply only to `contact` records.
