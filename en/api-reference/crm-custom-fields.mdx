## Manage CRM custom fields

Custom fields extend Talkturo CRM contact records beyond the default schema. Define each field with a stable `key`, display `label`, supported `fieldType`, and optional validation and display settings.

<Callout kind="info">

All CRM custom field endpoints require session cookie authentication. These endpoints do not accept API keys. Include the `teamId` query parameter or request field when required.

</Callout>

The API currently supports custom fields for `contact` records only.

## Endpoints at a glance

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/crm/custom-fields` | List custom fields for a team |
| `POST` | `/api/crm/custom-fields` | Create a custom field |
| `PUT` | `/api/crm/custom-fields/{id}` | Update a custom field |
| `DELETE` | `/api/crm/custom-fields/{id}` | Delete a custom field |

## Field types

Use one of these values for `fieldType`:

- **`text`**: Short freeform text.
- **`number`**: Numeric values.
- **`boolean`**: True or false values.
- **`date`**: Date values.
- **`select`**: One value from the list in `options`.
- **`textarea`**: Longer freeform text.

The `entityType` value is currently limited to `contact`. For `select` fields, include an `options` array containing the allowed values.

## List custom fields

Returns custom field definitions for a team. Inactive fields are excluded unless you set `includeInactive` to `true`.

<Request>
```bash
curl -G "https://app.talkturo.com/api/crm/custom-fields" \
  --data-urlencode "teamId=team_7f3a9c2d" \
  --data-urlencode "entityType=contact" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m"
```
</Request>

<Response>
```json
{
  "success": true,
  "fields": [
    {
      "id": "8bb0cf7b-6f0e-45e3-8f40-c0d6dc4c9a11",
      "teamId": "team_7f3a9c2d",
      "entityType": "contact",
      "key": "lead_source",
      "label": "Lead source",
      "fieldType": "select",
      "options": [
        "Website",
        "Referral",
        "Conference"
      ],
      "isRequired": false,
      "sortOrder": 10,
      "isActive": true
    },
    {
      "id": "1cf4bc3d-cad3-4d8b-8a4f-5c5c33bc3a86",
      "teamId": "team_7f3a9c2d",
      "entityType": "contact",
      "key": "renewal_date",
      "label": "Renewal date",
      "fieldType": "date",
      "isRequired": true,
      "sortOrder": 20,
      "isActive": true
    }
  ]
}
```
</Response>

## Create a custom field

Creates a custom field definition for contact records in a team.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/crm/custom-fields" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m" \
  -d '{
    "teamId": "team_7f3a9c2d",
    "entityType": "contact",
    "key": "customer_tier",
    "label": "Customer tier",
    "fieldType": "select",
    "options": [
      "Starter",
      "Growth",
      "Enterprise"
    ],
    "isRequired": false,
    "sortOrder": 30,
    "isActive": true
  }'
```
</Request>

<Response>
```json
{
  "success": true,
  "field": {
    "id": "ec607f3e-77c8-45e7-a58d-62b8d09c4d5d",
    "teamId": "team_7f3a9c2d",
    "entityType": "contact",
    "key": "customer_tier",
    "label": "Customer tier",
    "fieldType": "select",
    "options": [
      "Starter",
      "Growth",
      "Enterprise"
    ],
    "isRequired": false,
    "sortOrder": 30,
    "isActive": true
  }
}
```
</Response>

### Body parameters

<ParamField body="teamId" param-type="string" required="true">
Team that owns the custom field definition.
</ParamField>

<ParamField body="entityType" param-type="string" required="true" enum="contact">
CRM record type that the field applies to. The API currently supports `contact`.
</ParamField>

<ParamField body="key" param-type="string" required="true">
Stable key used to identify the field in contact data.
</ParamField>

<ParamField body="label" param-type="string" required="true">
Display label shown for the field in the CRM.
</ParamField>

<ParamField body="fieldType" param-type="string" required="true" enum="text,number,boolean,date,select,textarea">
Data type used to store and render the field value.
</ParamField>

<ParamField body="options" param-type="array" required="false">
Allowed values for a `select` field. Omit this field for other field types.
</ParamField>

<ParamField body="isRequired" param-type="boolean" required="false">
Whether a value is required for the field.
</ParamField>

<ParamField body="sortOrder" param-type="number" required="false">
Numeric position used to order the field relative to other custom fields.
</ParamField>

<ParamField body="isActive" param-type="boolean" required="false">
Whether the field is active. Inactive fields are excluded from default list results.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
`true` when the field is created successfully.
</ResponseField>

<ResponseField name="field" field-type="object" required="true">
The created custom field definition, including its generated `id`.
</ResponseField>

## Update a custom field

Updates an existing custom field definition. The request can change the label, field type, select options, required state, display order, and active state.

<Request>
```bash
curl -X PUT "https://app.talkturo.com/api/crm/custom-fields/ec607f3e-77c8-45e7-a58d-62b8d09c4d5d" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=sb_session_example_f84k2m" \
  -d '{
    "label": "Account tier",
    "fieldType": "select",
    "options": [
      "Starter",
      "Growth",
      "Enterprise",
      "Strategic"
    ],
    "isRequired": true,
    "sortOrder": 25,
    "isActive": true
  }'
```
</Request>

<Response>
```json
{
  "success": true,
  "field": {
    "id": "ec607f3e-77c8-45e7-a58d-62b8d09c4d5d",
    "teamId": "team_7f3a9c2d",
    "entityType": "contact",
    "key": "customer_tier",
    "label": "Account tier",
    "fieldType": "select",
    "options": [
      "Starter",
      "Growth",
      "Enterprise",
      "Strategic"
    ],
    "isRequired": true,
    "sortOrder": 25,
    "isActive": true
  }
}
```
</Response>

<Callout kind="info">

The update endpoint uses `PUT`. The field `key`, `teamId`, and `entityType` are not update parameters.

</Callout>

<ResponseField name="teamId" field-type="string" required="true">

<ResponseField name="entityType" field-type="string" required="true">

</ResponseField>

<ResponseField name="key" field-type="string" required="true">

<ResponseField name="label" field-type="string" required="true">

</ResponseField>

</ResponseField>

## Usage notes

Use a stable `key` when creating a field. The `key` identifies the field in contact data, while `label` controls the text displayed to CRM users.

Include `options` when `fieldType` is `select`. Do not include options for `text`, `number`, `boolean`, `date`, or `textarea` fields.

Set `isActive` to `false` when you need to stop using a field without removing its definition from the team. Pass `includeInactive=true` when listing inactive definitions.
