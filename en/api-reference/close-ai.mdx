## Close AI endpoints

Read dashboard analytics, inspect call sessions, generate narrative summaries, manage prompt presets and sales scripts, and update Close AI user settings from signed-in web sessions.

<Callout kind="info">

**Authentication**

All Close AI endpoints use **session cookie authentication**. Sign in through the Talkturo web app before calling these routes.

- API keys are **not supported**
- Bearer token authentication is **not supported**
- Workspace-scoped endpoints require access to the target workspace

</Callout>

## Endpoint summary

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/close-ai/dashboard` | Read aggregated Close AI dashboard metrics for a workspace |
| `POST` | `/api/close-ai/dashboard/narrative` | Generate a structured narrative from dashboard data |
| `GET` | `/api/close-ai/sessions` | List Close AI sessions with pagination and title search |
| `GET` | `/api/close-ai/sessions/:sessionId` | Read a full session with transcripts, messages, summary, and analysis |
| `PATCH` | `/api/close-ai/sessions/:sessionId` | Rename or clear a session title |
| `DELETE` | `/api/close-ai/sessions/:sessionId` | Delete a session and all related records |
| `GET` | `/api/close-ai/prompts` | List prompt presets or templates |
| `POST` | `/api/close-ai/prompts` | Create a prompt preset |
| `GET` | `/api/close-ai/scripts?account=:slug` | List workspace sales scripts |
| `POST` | `/api/close-ai/scripts?account=:slug` | Create a workspace sales script |
| `PUT` | `/api/close-ai/scripts` | Update a workspace sales script |
| `DELETE` | `/api/close-ai/scripts?id=:id` | Delete a workspace sales script |
| `GET` | `/api/close-ai/settings` | Read the current user's analytics prompt settings |
| `PUT` | `/api/close-ai/settings` | Upsert the current user's analytics prompt settings |
| `GET` | `/api/close-ai/desktop-status` | Read plan and monthly call usage for Close AI desktop access |

## Generate a dashboard narrative

Generate a structured narrative from dashboard data when you need readable insights and recommendations for each analytics category.

<Request tabs="cURL,JavaScript" default-tab="1" show-lines="true">

```bash
curl -X POST "https://app.talkturo.com/api/close-ai/dashboard/narrative" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-access-token=sb_example_9xmk7q2r; sb-refresh-token=sb_example_4af82n1p" \
  -d '{
    "account": "acme-sales",
    "days": 30,
    "lang": "en",
    "data": {
      "kpis": {
        "calls": 42,
        "callsDeltaPct": 15,
        "avgCloseScore": 73,
        "avgDurationSeconds": 480.5,
        "activeMembers": 5,
        "analyzedCount": 38
      }
    }
  }'
```

```javascript
const response = await fetch(
  "https://app.talkturo.com/api/close-ai/dashboard/narrative",
  {
    method: "POST",
    credentials: "include",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      account: "acme-sales",
      days: 30,
      lang: "en",
      data: {
        kpis: {
          calls: 42,
          callsDeltaPct: 15,
          avgCloseScore: 73,
          avgDurationSeconds: 480.5,
          activeMembers: 5,
          analyzedCount: 38
        }
      }
    })
  }
);

```

## Error patterns

Close AI endpoints use a small set of repeated error shapes.

<ExpandableGroup>
<Expandable title="Authentication errors" default-open="true">

- `401` with `error: unauthorized` appears on most authenticated routes when no valid session is present.
- `401` with `ok: false` and `reason: unauthenticated` appears on `GET /api/close-ai/desktop-status`.

</Expandable>
<Expandable title="Workspace access errors">

- `400` with `error: account_required` appears when a required workspace slug is missing.
- `403` with `error: workspace_access_denied` appears when the signed-in user cannot access the workspace.
- `404` with `error: workspace_not_found` appears when the workspace slug does not resolve.

</Expandable>
<Expandable title="Validation errors">

- `400` with `error: invalid_body` appears on validated `POST` and `PUT` routes when the request body fails schema validation.
- Some routes also include a `detail` object with field-level validation errors.

</Expandable>
<Expandable title="Missing resource errors">

- `404` with `error: not_found` appears when a session ID does not resolve or is not visible to the current user.
- `400` with `error: id_required` appears when a script delete request omits the `id` query parameter.

</Expandable>
</ExpandableGroup>
