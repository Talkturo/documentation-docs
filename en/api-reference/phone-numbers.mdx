## Manage phone numbers

Use the phone number endpoints to search carrier inventory, provision numbers to a team, list purchased numbers, update an existing number, and release numbers you no longer need. This page also documents the carrier webhook endpoints Talkturo uses to keep KYC and compliance status in sync.

<Callout kind="info">

All non-webhook phone number endpoints use dual authentication through `withApiAuth`. Authenticate with either an API key in the `Authorization` header or a signed-in session cookie. The two webhook endpoints are exceptions because carriers call them directly.

</Callout>

<Callout kind="info">

Choose a carrier based on where you need numbers and who manages the telephony account:

- **`talkturo_1`** — Telnyx-managed carrier for United States and Canada numbers only
- **`talkturo_2`** — Twilio-managed sub-account with broader international coverage
- **`own_twilio`** — Bring Your Own Twilio Account and use your own Twilio credentials

</Callout>

## Endpoint summary

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/phone-numbers/search` | API key or session cookie | Search available numbers from the selected carrier |
| `GET` | `/api/phone-numbers/purchase` | API key or session cookie | List purchased phone numbers |
| `POST` | `/api/phone-numbers/purchase` | API key or session cookie | Purchase and provision a phone number |
| `GET` | `/api/phone-numbers/cities` | API key or session cookie | Get available cities for number search |
| `GET` | `/api/phone-numbers/{id}` | API key or session cookie | Retrieve a specific phone number |
| `PATCH` | `/api/phone-numbers/{id}` | API key or session cookie | Update a phone number label or assistant assignment |
| `DELETE` | `/api/phone-numbers/{id}` | API key or session cookie | Release a phone number |
| `POST` | `/api/phone-numbers/telnyx-webhook` | Carrier signature | Receive Telnyx KYC status updates |
| `POST` | `/api/phone-numbers/twilio-webhook` | None | Receive Twilio bundle status callbacks |

## Search available phone numbers

Search returns numbers currently available from the selected carrier, filtered by location, number type, and feature requirements.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/phone-numbers/search" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "teamId": "team_2f8d8d44-3db4-4e47-9d53-4f58d9d9b1c1",
    "carrier": "talkturo_1",
    "filters": {
      "countryCode": "US",
      "areaCode": "415",
      "numberType": "local",
      "features": ["sms", "voice"],
      "limit": 10
    }
  }'
```

## Purchase a phone number

Purchase provisions a number to a team. The request body includes the selected phone number and team identifier, and may include carrier-specific routing or regional fields.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/phone-numbers/purchase" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "phoneNumber": "+14155550182",
    "teamId": "team_2f8d8d44-3db4-4e47-9d53-4f58d9d9b1c1",
    "carrier": "talkturo_1",
    "connectionId": "2093381749294001",
    "numberType": "local",
    "region": {
      "country": "US",
      "state": "CA",
      "locality": "San Francisco"
    }
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/phone-numbers/purchase", {
  method: "POST",
  headers: {
    "Authorization": "Bearer tk_live_example_9xmk7q2r",
    "Content-Type": "application/json"

    phoneNumber: "+14155550182",
```

### Provisioning notes

Talkturo checks your credit balance before starting the purchase flow. If the team does not have enough credits, the request fails before the carrier order is submitted.

Telnyx purchases poll order status for up to 30 seconds using 10 retries at 3-second intervals. Twilio purchases provision synchronously and resolve the required trunk, bundle, and address details during the request.

After activation, Talkturo charges the upfront credits immediately and schedules the next recurring charge 30 days later.

## Telnyx webhook

Telnyx calls this endpoint when KYC or requirement group status changes. Talkturo verifies the request signature, extracts the `requirement_group_id`, and updates the matching compliance request.

<Callout kind="alert">

This endpoint requires ED25519 signature verification using the `TELNYX_PUBLIC_KEY` environment variable. If the public key is not configured, the endpoint returns `503`. If signature verification fails, the endpoint returns `400`.

</Callout>

### Endpoint behavior

- **Method:** `POST`
- **Path:** `/api/phone-numbers/telnyx-webhook`
- **Authentication:** Telnyx ED25519 signature verification
- **Body format:** Raw JSON body from Telnyx
- **Retry behavior:** After successful verification and processing, the endpoint always returns `200` to prevent carrier retries

### Request body

<ParamField body="Telnyx event payload" param-type="object" required="true">
Raw Telnyx event JSON. Talkturo reads the raw request body to verify the signature before parsing the payload.
</ParamField>

### Response fields

<ResponseField name="received" field-type="boolean" required="true">
Returns `true` after Talkturo accepts the webhook request for processing.
</ResponseField>

<ResponseField name="status" field-type="string" required="false">
Current requirement group or compliance status after synchronization.
</ResponseField>

<ResponseField name="updated" field-type="boolean" required="false">
Indicates whether Talkturo updated a matching compliance record.
</ResponseField>

<ResponseField name="matchedRequest" field-type="boolean" required="false">
Indicates whether the webhook matched an existing compliance request in Talkturo.
</ResponseField>

## Twilio webhook

Twilio calls this endpoint when bundle status changes. Talkturo does not trust the posted status value directly and instead re-fetches the current bundle status from Twilio before updating internal records.

<Callout kind="info">

This endpoint does not require a signature header. For security, Talkturo reads `BundleSID`, `BundleSid`, or `bundle_sid` from the form-encoded payload and verifies the current state by querying Twilio directly.

</Callout>

### Endpoint behavior

- **Method:** `POST`
- **Path:** `/api/phone-numbers/twilio-webhook`
- **Authentication:** None
- **Body format:** Form-encoded callback payload
- **Retry behavior:** The endpoint always returns `200` to prevent Twilio retries

### Request body

<ParamField body="BundleSID" param-type="string" required="false">
Twilio bundle identifier. The endpoint also accepts `BundleSid` and `bundle_sid`.
</ParamField>

<ParamField body="BundleSid" param-type="string" required="false">
Alternative Twilio field name for the bundle identifier.
</ParamField>

<ParamField body="bundle_sid" param-type="string" required="false">
Lowercase variant of the Twilio bundle identifier field.
</ParamField>

### Response fields

<ResponseField name="received" field-type="boolean" required="true">
Returns `true` after Talkturo accepts the callback.
</ResponseField>

<ResponseField name="status" field-type="string" required="false">
Bundle status retrieved directly from Twilio.
</ResponseField>

<ResponseField name="matchedRequest" field-type="boolean" required="false">
Indicates whether the callback matched an existing compliance request in Talkturo.
</ResponseField>
