## Manage phone numbers

Use the phone number endpoints to search carrier inventory, provision numbers to a workspace, list purchased numbers, and release numbers you no longer need. The API also retains a retired Telnyx callback route that acknowledges requests without processing them.

<Callout kind="info">

Phone number endpoints use shared API key or session authentication unless noted otherwise. The release endpoint accepts session authentication only, and the retired Telnyx route does not perform authentication or signature verification.

</Callout>

## Endpoint summary

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/phone-numbers/search` | Shared API key or session | Search available numbers from the carrier |
| `POST` | `/api/phone-numbers/purchase` | Shared API key or session | Purchase and provision a phone number |
| `GET` | `/api/phone-numbers/purchase` | Shared API key or session | List purchased phone numbers |
| `DELETE` | `/api/phone-numbers/{id}?account={workspaceSlug}` | Session cookie | Release a phone number owned by the workspace |
| `POST` | `/api/phone-numbers/telnyx-webhook` | None | Acknowledge a retired Telnyx callback route |

## Search available phone numbers

Search available numbers with a JSON request body. `filters.countryCode` is required; the remaining filters, team, carrier, and provider fields are optional.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://your-deployment-host/api/phone-numbers/search" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-session=sb-session-example-a92k3m" \
  -d '{
    "filters": {
      "countryCode": "US",
      "areaCode": "415",
      "numberType": "local",
      "contains": "555"
    },
    "carrier": "telnyx",
    "provider": "telnyx"
  }'
```

```javascript
const response = await fetch(
  "https://your-deployment-host/api/phone-numbers/search",
  {
    method: "POST",
    credentials: "include",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      filters: {
        countryCode: "US",
        areaCode: "415",
        numberType: "local",
        contains: "555"
      },
      carrier: "telnyx",
      provider: "telnyx"
    })
  }
);

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "numbers": [],
  "carrier": "telnyx",
  "provider": "telnyx",
  "verifiedLocalities": [],
  "pricing": {},
  "billing": {},
  "count": 0
}
```
</Response>

## Purchase a phone number

Purchase provisions a selected number to the current workspace. The request requires `phoneNumber`; use `teamId` when a session needs explicit workspace context. API-key authentication determines its workspace and cannot be overridden with `teamId`.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://your-deployment-host/api/phone-numbers/purchase" \
  -H "Content-Type: application/json" \
  -H "Cookie: sb-session=sb-session-example-a92k3m" \
  -d '{
    "phoneNumber": "+14155550182",
    "teamId": "team_acme_sales",
    "connectionId": "conn_7c9c4f2a61d1",
    "provider": "telnyx",
    "carrier": "telnyx",
    "numberType": "local"
  }'
```

```javascript
const response = await fetch(
  "https://your-deployment-host/api/phone-numbers/purchase",
  {
    method: "POST",
    credentials: "include",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      phoneNumber: "+14155550182",
      teamId: "team_acme_sales",
      connectionId: "conn_7c9c4f2a61d1",
      provider: "telnyx",
      carrier: "telnyx",
      numberType: "local"
    })
  }
);

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">

### Provisioning notes

Carrier requirements vary by country, number type, and regulatory flow. Confirm that the selected number is eligible before sending the purchase request.

## Release a phone number

Release removes a provisioned number from the workspace and releases it to the carrier. The operation is irreversible.

<Callout kind="alert">

Only the number owner can release a phone number. This endpoint accepts session authentication only and requires the workspace slug in the `account` query parameter.

</Callout>

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X DELETE "https://your-deployment-host/api/phone-numbers/pn_7c9c4f2a61d1?account=acme-sales" \
  -H "Cookie: sb-session=sb-session-example-a92k3m"
```

```javascript
const response = await fetch(
  "https://your-deployment-host/api/phone-numbers/pn_7c9c4f2a61d1?account=acme-sales",
  {
    method: "DELETE",
    credentials: "include"
  }
);

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "phoneNumber": "+14155550182"
}
```
</Response>

### Query parameters

<ParamField query="account" param-type="string" required="true">
Workspace slug that owns the phone number.
</ParamField>

### Path parameters

<ParamField path="id" param-type="string" required="true">
Unique phone number identifier to release.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Indicates whether the release succeeded.
</ResponseField>

<ResponseField name="phoneNumber" field-type="string" required="true">
Released phone number.
</ResponseField>

### Error responses

- `401`: The request is not authenticated with a valid session.
- `400`: The request is invalid.
- `403`: The authenticated user does not own the number.
- `404`: The phone number or workspace was not found.
- `502`: The carrier rejected or could not complete the release.

## Retired Telnyx webhook

The Telnyx phone-number webhook route is retired. It acknowledges requests without signature verification, KYC processing, or compliance status synchronization.

### Endpoint behavior

- **Method:** `POST`
- **Path:** `/api/phone-numbers/telnyx-webhook`
- **Authentication:** None
- **Response status:** `200`

<Response tabs="200">
```json
{
  "received": true,
  "retired": true
}
```
</Response>

### Response fields

<ResponseField name="received" field-type="boolean" required="true">
Always returns `true` when the retired route receives a request.
</ResponseField>

<ResponseField name="retired" field-type="boolean" required="true">
Always returns `true` to identify the route as retired.
</ResponseField>
