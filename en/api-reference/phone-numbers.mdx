## Manage phone numbers

Use the phone number endpoints to search carrier inventory, provision numbers to an account, inspect an existing number, and release numbers you no longer need. This page also documents the carrier webhook endpoints Talkturo uses to keep KYC and compliance status in sync.

<Callout kind="info">

The search, purchase, and retrieve endpoints support dual authentication — use either an API key (`Authorization: Bearer tk_live_...`) or an authenticated session cookie. The release endpoint requires a session cookie authenticated by the workspace owner. The two webhook endpoints are exceptions because carriers call them directly.

</Callout>

## Endpoint summary

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/phone-numbers/search` | API key or session | Search available numbers from the carrier |
| `POST` | `/api/phone-numbers/purchase` | API key or session | Purchase and provision a phone number |
| `GET` | `/api/phone-numbers/{id}` | API key or session | Retrieve a specific phone number |
| `DELETE` | `/api/phone-numbers/{id}` | Session (owner only) | Release a phone number |
| `POST` | `/api/phone-numbers/telnyx-webhook` | Carrier signature | Receive Telnyx KYC status updates |
| `POST` | `/api/phone-numbers/twilio-webhook` | None | Receive Twilio bundle status callbacks |

## Search available phone numbers

Search returns numbers currently available from the configured carrier, filtered by country, number type, and carrier-specific search fields.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/phone-numbers/search" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r5s8d4m1n6p3v7y2z" \
  -d '{
    "filters": {
      "countryCode": "US",
      "numberType": "local",
      "areaCode": "415",
      "features": ["sms", "voice"],
      "limit": 2
    },
    "teamId": "team_8f3d2c1b7a90",
    "carrier": "talkturo",
    "provider": "talkturo"
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/phone-numbers/search", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer tk_live_example_9xmk7q2r5s8d4m1n6p3v7y2z"
  },
  body: JSON.stringify({
    filters: {
      countryCode: "US",
      numberType: "local",
      areaCode: "415",
      features: ["sms", "voice"],
      limit: 2
    },
    teamId: "team_8f3d2c1b7a90",
    carrier: "talkturo",
    provider: "talkturo"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

### Request body

<ParamField body="filters" param-type="object" required="true">
Carrier search filters. The object must include `countryCode` and can include additional carrier-specific search fields.
</ParamField>

<ParamField body="filters.countryCode" param-type="string" required="true">
ISO 3166-1 alpha-2 country code to search in, such as `US`.
</ParamField>

<ParamField body="filters.numberType" param-type="string" required="false" enum="local,mobile,toll-free">
Number type to search for. Defaults to `local`.
</ParamField>

<ParamField body="filters.areaCode" param-type="string" required="false">
Local area code filter when the carrier and country support it.
</ParamField>

<ParamField body="filters.features" param-type="array" required="false">
Required capabilities for the number, such as `sms` or `voice`.
</ParamField>

<ParamField body="filters.limit" param-type="integer" required="false">
Maximum number of results to request from the carrier.
</ParamField>

<ParamField body="teamId" param-type="string" required="false">
Team identifier used for KYC country gating and billing-exempt checks.
</ParamField>

<ParamField body="carrier" param-type="string" required="false">
Carrier selection key to use for the search request, such as `talkturo`.
</ParamField>

<ParamField body="provider" param-type="string" required="false" enum="talkturo,twilio">
Legacy alias for `carrier`.
</ParamField>

<ResponseField name="success" field-type="boolean" required="true">

</ResponseField>

<ResponseField name="numbers[].features" field-type="array" required="false">
Capabilities available on the number, such as `sms` or `voice`.
</ResponseField>

<ResponseField name="carrier" field-type="string" required="false">

</ResponseField>

<ResponseField name="provider" field-type="string" required="false">
Provider name returned for compatibility, such as `talkturo` or `twilio`.
</ResponseField>

<ResponseField name="verifiedLocalities" field-type="array|null" required="false">

</ResponseField>

<ResponseField name="pricing" field-type="object|null" required="false">
Estimated or exact pricing details for the returned numbers, or `null` when unavailable.
</ResponseField>

<ResponseField name="pricing.upfrontCredits" field-type="number" required="false">
One-time purchase cost in credits.
</ResponseField>

<ResponseField name="pricing.monthlyCredits" field-type="number" required="false">
Recurring monthly cost in credits.
</ResponseField>

<ResponseField name="pricing.upfrontUsd" field-type="string" required="false">
One-time purchase cost in USD string form.
</ResponseField>

<ResponseField name="pricing.monthlyUsd" field-type="string" required="false">
Recurring monthly cost in USD string form.
</ResponseField>

<ResponseField name="pricing.estimated" field-type="boolean" required="false">
Indicates whether the pricing values are estimates instead of final billed amounts.
</ResponseField>

<ResponseField name="billing" field-type="string" required="false">
Billing mode for the returned search results. Possible values are `credits`, `exempt`, or `byoa`.
</ResponseField>

<ResponseField name="count" field-type="number" required="false">
Number of results returned in `numbers`.
</ResponseField>

### Error responses

- **`400`** — Missing `filters.countryCode`
- **`403`** — Country requires KYC verification
- **`409`** — Twilio carrier is not set up
- **`502`** — Carrier API failure

## Purchase a phone number

Purchase provisions a number to an account. The request body always includes the selected phone number and may include team, carrier, connection, and display metadata.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/phone-numbers/purchase" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_live_example_9xmk7q2r5s8d4m1n6p3v7y2z" \
  -d '{
    "phoneNumber": "+14155550182",
    "teamId": "team_8f3d2c1b7a90",
    "connectionId": "fqdn_conn_2dc14baf90",
    "carrier": "talkturo",
    "provider": "talkturo",
    "numberType": "local",
    "region": {
      "state": "CA",
      "locality": "San Francisco",
      "rateCenter": "SNFCISCOZN01"
    }
  }'
```

### Provisioning notes

Carrier requirements vary by country, number type, and regulatory flow. If the carrier requires compliance data, include those fields in the same purchase request body.

### Error responses

- **`400`** — Missing `phoneNumber` or `teamId`
- **`402`** — Insufficient credits. The response includes `balance` and `required`.
- **`403`** — KYC not completed. The response includes `requiresVerification`, `countryCode`, and `numberType`.
- **`403`** — Plan limit reached. The response includes `currentCount`, `maxAllowed`, `hasSubscription`, and `planName`.
- **`409`** — Number already exists

## Release a phone number

Release removes a provisioned number so it is no longer assigned to your account. This endpoint requires a session-authenticated workspace owner.

### Path parameters

<ParamField path="id" param-type="string" required="true">
Unique phone number identifier to release.
</ParamField>

### Query parameters

<ParamField query="account" param-type="string" required="true">
Workspace slug that owns the phone number.
</ParamField>

### Example response

```json
{
  "success": true,
  "phoneNumber": "+14155550182"
}
```

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the release request succeeds.
</ResponseField>

<ResponseField name="phoneNumber" field-type="string" required="true">
Released phone number in E.164 format.
</ResponseField>

### Error responses

- **`400`** — `account` is required
- **`403`** — Only the workspace owner can release a number
- **`404`** — Workspace or phone number not found
- **`502`** — Carrier would not release the number

## Telnyx webhook

Telnyx calls this endpoint when KYC or requirement group status changes. Talkturo verifies the request signature, extracts the `requirement_group_id`, and updates the matching compliance request.

<Callout kind="alert">

This endpoint requires ED25519 signature verification using the `TELNYX_PUBLIC_KEY` environment variable. If the public key is not configured, the endpoint returns `503`. If signature verification fails, the endpoint returns `400`.

</Callout>

### Endpoint behavior

- **Method:** `POST`
- **Path:** `/api/phone-numbers/telnyx-webhook`
- **Authentication:** Telnyx ED25519 signature verification
- **Body format:** Raw JSON body from Telnyx
- **Retry behavior:** After successful verification and processing, the endpoint always returns `200` to prevent carrier retries

### Request body

<ParamField body="Telnyx event payload" param-type="object" required="true">
Raw Telnyx event JSON. Talkturo reads the raw request body to verify the signature before parsing the payload.
</ParamField>

### Response fields

<ResponseField name="received" field-type="boolean" required="true">
Returns `true` after Talkturo accepts the webhook request for processing.
</ResponseField>

<ResponseField name="status" field-type="string" required="false">
Current requirement group or compliance status after synchronization.
</ResponseField>

<ResponseField name="updated" field-type="boolean" required="false">
Indicates whether Talkturo updated a matching compliance record.
</ResponseField>

<ResponseField name="matchedRequest" field-type="boolean" required="false">
Indicates whether the webhook matched an existing compliance request in Talkturo.
</ResponseField>

## Twilio webhook

Twilio calls this endpoint when bundle status changes. Talkturo does not trust the posted status value directly and instead re-fetches the current bundle status from Twilio before updating internal records.

<Callout kind="info">

This endpoint does not require a signature header. For security, Talkturo reads `BundleSID`, `BundleSid`, or `bundle_sid` from the form-encoded payload and verifies the current state by querying Twilio directly.

</Callout>

### Endpoint behavior

- **Method:** `POST`
- **Path:** `/api/phone-numbers/twilio-webhook`
- **Authentication:** None
- **Body format:** Form-encoded callback payload
- **Retry behavior:** The endpoint always returns `200` to prevent Twilio retries

### Request body

<ParamField body="BundleSID" param-type="string" required="false">
Twilio bundle identifier. The endpoint also accepts `BundleSid` and `bundle_sid`.
</ParamField>

<ParamField body="BundleSid" param-type="string" required="false">
Alternative Twilio field name for the bundle identifier.
</ParamField>

<ParamField body="bundle_sid" param-type="string" required="false">
Lowercase variant of the Twilio bundle identifier field.
</ParamField>

### Response fields

<ResponseField name="received" field-type="boolean" required="true">
Returns `true` after Talkturo accepts the callback.
</ResponseField>

<ResponseField name="status" field-type="string" required="false">
Bundle status retrieved directly from Twilio.
</ResponseField>

<ResponseField name="matchedRequest" field-type="boolean" required="false">
Indicates whether the callback matched an existing compliance request in Talkturo.
</ResponseField>
