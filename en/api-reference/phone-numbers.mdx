## Manage phone numbers

Use the phone number endpoints to search carrier inventory, provision numbers to a team, list purchased numbers, inspect an existing number, and release numbers you no longer need. This page also documents the carrier webhook endpoints Talkturo uses to keep KYC and compliance status in sync.

<Callout kind="info">

All phone number management endpoints accept either an authenticated session cookie or an API key bearer token. The two webhook endpoints are exceptions because carriers call them directly.

</Callout>

## Endpoint summary

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/phone-numbers/search` | Session cookie or Bearer token | Search available numbers from the carrier |
| `POST` | `/api/phone-numbers/purchase` | Session cookie or Bearer token | Purchase and provision a phone number |
| `GET` | `/api/phone-numbers/purchase` | Session cookie or Bearer token | List purchased phone numbers for a team |
| `GET` | `/api/phone-numbers/{id}` | Session cookie or Bearer token | Retrieve a specific phone number |
| `DELETE` | `/api/phone-numbers/{id}` | Session cookie or Bearer token | Release a phone number |
| `POST` | `/api/phone-numbers/telnyx-webhook` | Carrier signature | Receive Telnyx KYC status updates |
| `POST` | `/api/phone-numbers/twilio-webhook` | None | Receive Twilio bundle status callbacks |

## Search available phone numbers

Search returns numbers currently available from the configured carrier, filtered by country and optional number requirements.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/phone-numbers/search" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ttro_example_9xmk7q2r" \
  -d '{
    "filters": {
      "countryCode": "US",
      "numberType": "local",
      "areaCode": "415"
    },
    "teamId": "team_7f3d2c91a4b8",
    "carrier": "talkturo"
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/phone-numbers/search", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer ttro_example_9xmk7q2r"
  },
  body: JSON.stringify({
    filters: {
      countryCode: "US",
      numberType: "local",
      areaCode: "415"
    },
    teamId: "team_7f3d2c91a4b8",
    carrier: "talkturo"
  })
});

const data = await response.json();
console.log(data);
```
</Request>

### Request body

<ParamField body="filters" param-type="object" required="true">
Carrier search filters.
</ParamField>

<ParamField body="filters.countryCode" param-type="string" required="true">
Two-letter ISO 3166-1 alpha-2 country code, such as `US`.
</ParamField>

<ParamField body="filters.numberType" param-type="string" required="false" enum="local,mobile,toll-free">
Number type to search. Defaults to `local`.
</ParamField>

<ParamField body="filters.areaCode" param-type="string" required="false">
Local area code to narrow inventory results when the carrier supports it.
</ParamField>

<ParamField body="teamId" param-type="string" required="false">
Team identifier used to scope the search. Pass `teamId` when the authenticated context does not already resolve a team.
</ParamField>

<ParamField body="carrier" param-type="string" required="false" enum="talkturo,talkturo_2">
Carrier configuration to use for the search.
</ParamField>

<ParamField body="provider" param-type="string" required="false">
Legacy alias for `carrier`. Use `carrier` in new integrations.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when the search request succeeds.
</ResponseField>

<ResponseField name="numbers" field-type="array" required="true">
List of available numbers returned by the carrier after filters are applied.
</ResponseField>

<ResponseField name="numbers[].phoneNumber" field-type="string" required="true">
The purchasable phone number in E.164 format.
</ResponseField>

<ResponseField name="numbers[].country" field-type="string" required="false">
Country associated with the returned number.
</ResponseField>

<ResponseField name="numbers[].type" field-type="string" required="false">
Carrier number type, such as `local`, `mobile`, or `toll-free`.
</ResponseField>

<ResponseField name="numbers[].features" field-type="array" required="false">
Capabilities available on the number, such as `sms` or `voice`.
</ResponseField>

<ResponseField name="carrier" field-type="string" required="false">
Carrier used to fulfill the inventory search.
</ResponseField>

<ResponseField name="provider" field-type="string" required="false">
Provider name returned for backward compatibility.
</ResponseField>

<ResponseField name="pricing" field-type="object" required="false">
Credits pricing information for the matching inventory.
</ResponseField>

<ResponseField name="pricing.upfrontCredits" field-type="number" required="false">
One-time credits required to provision the number.
</ResponseField>

<ResponseField name="pricing.monthlyCredits" field-type="number" required="false">
Recurring monthly credits required to keep the number active.
</ResponseField>

<ResponseField name="billing" field-type="string" required="false">
Billing mode for the returned inventory. Supported values include `byoa`, `exempt`, and `credits`.
</ResponseField>

<ResponseField name="verifiedLocalities" field-type="array" required="false">
Localities already verified for the team when locality-based compliance applies.
</ResponseField>

<ResponseField name="addressRequirements" field-type="array" required="false">
Address or compliance requirements returned alongside the search results.
</ResponseField>

<ResponseField name="count" field-type="number" required="false">
Number of available results in the response.
</ResponseField>

### Error responses

Search rejects requests missing `filters.countryCode` with `400`. If the selected carrier requires KYC before inventory access, the endpoint returns `403` with `requiresVerification: true`. If the team has not configured the selected carrier, the endpoint returns `409`.

## Purchase a phone number

Purchase provisions a number to a team. The request body always includes the selected phone number and team identifier, and may include carrier or region metadata.

<Request tabs="cURL,JavaScript" default-tab="1">
```bash
curl -X POST "https://app.talkturo.com/api/phone-numbers/purchase" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ttro_example_9xmk7q2r" \
  -d '{
    "phoneNumber": "+14155550182",
    "teamId": "team_7f3d2c91a4b8",
    "connectionId": "conn_2d9f7a61b31c",
    "carrier": "talkturo",
    "numberType": "local",
    "region": {
      "state": "CA",
      "locality": "San Francisco",
      "rateCenter": "SNFC CNTRL"
    }
  }'
```

```javascript
const response = await fetch("https://app.talkturo.com/api/phone-numbers/purchase", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer ttro_example_9xmk7q2r"
  },
  body: JSON.stringify({
    phoneNumber: "+14155550182",
    teamId: "team_7f3d2c91a4b8",
    connectionId: "conn_2d9f7a61b31c",
    carrier: "talkturo",
    numberType: "local",
    region: {
      state: "CA",
      locality: "San Francisco",
      rateCenter: "SNFC CNTRL"
    }
  })
});

const data = await response.json();
console.log(data);
```
</Request>

<Response tabs="200">
```json
{
  "success": true,
  "phoneNumber": {
    "id": "pn_7c9c4f2a61d1",
    "phoneNumber": "+14155550182",
    "status": "active",
    "accountSlug": "acme-sales"
  }
}
```
</Response>

### Request body

<ParamField body="phoneNumber" param-type="string" required="true">
The phone number to provision in E.164 format. Pass the exact value returned by the search endpoint.
</ParamField>

<ParamField body="teamId" param-type="string" required="true">
Team identifier that will own the purchased number. When you authenticate with an API key, Talkturo may infer `teamId` from the key context.
</ParamField>

<ParamField body="connectionId" param-type="string" required="false">
Connection to associate with the purchased number.
</ParamField>

<ParamField body="carrier" param-type="string" required="false">
Carrier configuration to use for the purchase request.
</ParamField>

<ParamField body="provider" param-type="string" required="false">
Legacy alias for `carrier`. Use `carrier` in new integrations.
</ParamField>

<ParamField body="numberType" param-type="string" required="false">
Number type associated with the purchase request.
</ParamField>

<ParamField body="region" param-type="object" required="false">
Region metadata for carrier fulfillment.
</ParamField>

<ParamField body="region.state" param-type="string" required="false">
Region state or province code.
</ParamField>

<ParamField body="region.locality" param-type="string" required="false">
Locality or city associated with the requested number.
</ParamField>

<ParamField body="region.rateCenter" param-type="string" required="false">
Carrier rate center metadata when required.
</ParamField>

### Response fields

<ResponseField name="success" field-type="boolean" required="true">
Returns `true` when provisioning succeeds.
</ResponseField>

<ResponseField name="phoneNumber" field-type="object" required="true">
The newly provisioned phone number record.
</ResponseField>

<ResponseField name="phoneNumber.id" field-type="string" required="true">
Talkturo identifier for the phone number record.
</ResponseField>

<ResponseField name="phoneNumber.phoneNumber" field-type="string" required="true">
Provisioned phone number value.
</ResponseField>

Account slug associated with the provisioned number.
</ResponseField>

### Provisioning notes

Carrier requirements vary by country, number type, and regulatory flow. If the selected carrier requires compliance data, include those fields in the same purchase request body.

## Telnyx webhook

Telnyx calls this endpoint when KYC or requirement group status changes. Talkturo verifies the request signature, extracts the `requirement_group_id`, and updates the matching compliance request.

<Callout kind="alert">

This endpoint requires ED25519 signature verification using the `TELNYX_PUBLIC_KEY` environment variable. If the public key is not configured, the endpoint returns `503`. If signature verification fails, the endpoint returns `400`.

</Callout>

### Endpoint behavior

- **Method:** `POST`
- **Path:** `/api/phone-numbers/telnyx-webhook`
- **Authentication:** Telnyx ED25519 signature verification
- **Body format:** Raw JSON body from Telnyx
- **Retry behavior:** After successful verification and processing, the endpoint always returns `200` to prevent carrier retries

### Request body

<ParamField body="Telnyx event payload" param-type="object" required="true">
Raw Telnyx event JSON. Talkturo reads the raw request body to verify the signature before parsing the payload.
</ParamField>

### Response fields

<ResponseField name="received" field-type="boolean" required="true">
Returns `true` after Talkturo accepts the webhook request for processing.
</ResponseField>

<ResponseField name="status" field-type="string" required="false">
Current requirement group or compliance status after synchronization.
</ResponseField>

<ResponseField name="updated" field-type="boolean" required="false">
Indicates whether Talkturo updated a matching compliance record.
</ResponseField>

<ResponseField name="matchedRequest" field-type="boolean" required="false">
Indicates whether the webhook matched an existing compliance request in Talkturo.
</ResponseField>

## Twilio webhook

Twilio calls this endpoint when bundle status changes. Talkturo does not trust the posted status value directly and instead re-fetches the current bundle status from Twilio before updating internal records.

<Callout kind="info">

This endpoint does not require a signature header. For security, Talkturo reads `BundleSID`, `BundleSid`, or `bundle_sid` from the form-encoded payload and verifies the current state by querying Twilio directly.

</Callout>

### Endpoint behavior

- **Method:** `POST`
- **Path:** `/api/phone-numbers/twilio-webhook`
- **Authentication:** None
- **Body format:** Form-encoded callback payload
- **Retry behavior:** The endpoint always returns `200` to prevent Twilio retries

### Request body

<ParamField body="BundleSID" param-type="string" required="false">
Twilio bundle identifier. The endpoint also accepts `BundleSid` and `bundle_sid`.
</ParamField>

<ParamField body="BundleSid" param-type="string" required="false">
Alternative Twilio field name for the bundle identifier.
</ParamField>

<ParamField body="bundle_sid" param-type="string" required="false">
Lowercase variant of the Twilio bundle identifier field.
</ParamField>

### Response fields

<ResponseField name="received" field-type="boolean" required="true">
Returns `true` after Talkturo accepts the callback.
</ResponseField>

<ResponseField name="status" field-type="string" required="false">
Bundle status retrieved directly from Twilio.
</ResponseField>

<ResponseField name="matchedRequest" field-type="boolean" required="false">
Indicates whether the callback matched an existing compliance request in Talkturo.
</ResponseField>
