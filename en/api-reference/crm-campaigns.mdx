## Manage outbound CRM campaigns

Create campaigns, enroll contacts, inspect queue state, and start outbound calling runs from the CRM Campaigns API. Authentication depends on the endpoint: some routes accept either a session cookie or API key, while others require a browser session.

<Callout kind="info">

Authentication varies by route:

- **Session or API key**: `GET /api/crm/campaigns`, `POST /api/crm/campaigns`, `GET /api/crm/campaigns/[id]/contacts`, `POST /api/crm/campaigns/[id]/contacts`, `POST /api/crm/campaigns/[id]/run`
- **Session only**: `GET /api/crm/campaigns/[id]`, `PUT /api/crm/campaigns/[id]`, `DELETE /api/crm/campaigns/[id]`, `GET /api/crm/campaigns/[id]/dashboard`

API key access to `POST /api/crm/campaigns/[id]/run` requires the `campaigns:run` scope. API key access to `POST /api/crm/campaigns/[id]/contacts` requires the `campaigns:write` scope.

</Callout>

## Endpoint summary

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/crm/campaigns` | List campaigns |
| `POST` | `/api/crm/campaigns` | Create a campaign |
| `GET` | `/api/crm/campaigns/[id]` | Retrieve one campaign |
| `PUT` | `/api/crm/campaigns/[id]` | Update a campaign |
| `DELETE` | `/api/crm/campaigns/[id]` | Soft-delete a draft or cancelled campaign |
| `GET` | `/api/crm/campaigns/[id]/contacts` | List campaign contacts |
| `POST` | `/api/crm/campaigns/[id]/contacts` | Add contacts to a campaign |
| `GET` | `/api/crm/campaigns/[id]/dashboard` | Retrieve live dashboard data |
| `POST` | `/api/crm/campaigns/[id]/run` | Start or resume a campaign run |

## Campaign statuses

Campaigns move through a fixed set of statuses.

<ResponseField name="draft" field-type="string" required="false">
Campaign is configured but not scheduled or running.
</ResponseField>

<ResponseField name="scheduled" field-type="string" required="false">
Campaign has a scheduled start time and has not started yet.
</ResponseField>

<ResponseField name="running" field-type="string" required="false">
Campaign is actively placing or queueing calls.
</ResponseField>

<ResponseField name="paused" field-type="string" required="false">
Campaign is temporarily stopped and can be resumed.
</ResponseField>

<ResponseField name="completed" field-type="string" required="false">
Campaign finished and cannot return to an earlier configuration state.
</ResponseField>

<ResponseField name="cancelled" field-type="string" required="false">
Campaign was cancelled and may be deleted.
</ResponseField>

## Create a campaign

Create a draft or scheduled campaign with outbound settings, retry behavior, and optional webhook configuration.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/crm/campaigns" \
  -H "Content-Type: application/json" \
  -H "x-api-key: dkai_example_9xmk7q2r" \
  -d '{
    "teamId": "5ef8a8de-5c9f-4e4a-9d0f-39c8d11c124e",
    "assistantId": "ast_9c41f8e2-7e93-4f8e-8d6c-2c9bdf8b9a33",
    "companyId": "co_2d4f7d48-bd8c-47b5-a43f-2a7c1d0cf716",
    "fromNumberIds": [
      "num_b6c4f56d-1f21-4cf2-9ef4-9c8f2707fa22"
    ],
    "name": "Q3 renewal outreach",
    "description": "Reach customers with renewals due in the next 30 days.",
    "scheduledStartAt": "2026-08-13T16:00:00.000Z",
    "callWindowStart": "09:00",
    "callWindowEnd": "17:00",
    "callWindowTimezone": "America/Los_Angeles",
    "maxConcurrentCalls": 5,
    "maxAttemptsPerContact": 3,
    "retryDelayMinutes": 30,
    "settings": {
      "useContactTimezoneForCallWindow": true
    },
    "noAutoComplete": false,
    "webhookEnabled": true,
    "webhookUrl": "https://ops.acmecrm.com/webhooks/talkturo/campaigns",
    "webhookSecret": "whsec_example_campaigns_7j2m8q",
    "webhookEvents": [
      "call.completed",
      "campaign.completed"
    ]
  }'
```
</Request>

<Response>
```json
{
  "success": true,
  "campaign": {
    "id": "cmp_6df44cc0-5e10-4b0d-a3f5-ec6116f8c7d1",
    "name": "Q3 renewal outreach",
    "status": "scheduled",
    "description": "Reach customers with renewals due in the next 30 days.",
    "scheduled_start_at": "2026-08-13T16:00:00.000Z",
    "assistant_id": "ast_9c41f8e2-7e93-4f8e-8d6c-2c9bdf8b9a33",

  }

```
</Response>

A campaign becomes `scheduled` when you provide `scheduledStartAt`. Without it, the campaign is created in `draft`.

### Update rules

<Callout kind="alert">

State transitions are enforced:

- You cannot change configuration fields while the campaign status is `running`.
- While a campaign is running, only `status` can change.
- You cannot reverse a campaign from `completed` or `cancelled` to an earlier state.

</Callout>

## Common workflow

Most campaign integrations follow the same execution path.

<Steps>

<Step title="Create the campaign" icon="plus">

Create the campaign with `POST /api/crm/campaigns`. Include `assistantId`, `companyId`, `name`, and outbound number configuration. If you send `scheduledStartAt`, the campaign starts in `scheduled`; otherwise it starts in `draft`.

A successful response returns `success: true` and a new campaign ID.

</Step>

<Step title="Enroll contacts" icon="upload">

Add contacts with `POST /api/crm/campaigns/[id]/contacts`. Choose one mode per request:

- `contactIds` for existing contacts
- `contact` for inline creation
- `audience` for bulk enrollment from eligible company contacts

When enrollment succeeds, the response returns `success: true` and a `contacts` array.

</Step>

<Step title="Review the queue" icon="bar-chart">

Fetch `GET /api/crm/campaigns/[id]/contacts` to confirm contacts are enrolled, then use `GET /api/crm/campaigns/[id]/dashboard` to inspect queue counts and recent activity.

Your dashboard response includes `counts.byStatus`, `counts.byOutcome`, `queue`, and `recentCalls`.

</Step>

<Step title="Start or resume calling" icon="play-circle">

Send `POST /api/crm/campaigns/[id]/run` to start processing immediately. Use `dryRun: true` first if you want to validate picks without placing calls.

When the run starts successfully, the response includes `started`, `failed`, and `message`.

</Step>

<Step title="Update or pause as needed" icon="settings">

Use `PUT /api/crm/campaigns/[id]` to change status or configuration. If the campaign is already `running`, update only `status` until execution stops.

If you need to remove the campaign later, delete it only after it returns to `draft` or `cancelled`.

</Step>

</Steps>
