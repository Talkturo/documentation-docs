## Manage outbound CRM campaigns

Use the CRM Campaigns endpoints to create outbound calling campaigns, attach contacts, monitor live progress, and start or stop execution. CRM campaign endpoints accept either a Talkturo session cookie or an API key Bearer token for authentication.

<Callout kind="info">

Authenticate these endpoints with either a valid Talkturo session cookie or an API key Bearer token. When you call `POST /api/crm/campaigns/[id]/run` with API key authentication, the key must include the `campaigns:run` scope.

</Callout>

## Endpoint summary

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/crm/campaigns` | List campaigns |
| `POST` | `/api/crm/campaigns` | Create a campaign |
| `GET` | `/api/crm/campaigns/[id]` | Retrieve one campaign |
| `PATCH` | `/api/crm/campaigns/[id]` | Update a campaign |
| `DELETE` | `/api/crm/campaigns/[id]` | Delete a campaign |
| `GET` | `/api/crm/campaigns/[id]/contacts` | List campaign contacts |
| `POST` | `/api/crm/campaigns/[id]/contacts` | Add contacts to a campaign |
| `GET` | `/api/crm/campaigns/[id]/dashboard` | Retrieve real-time campaign stats |
| `POST` | `/api/crm/campaigns/[id]/run` | Start a campaign run |
| `GET` | `/api/crm/outbound-assistants` | List assistants available for outbound calls |
| `GET` | `/api/crm/calls` | List CRM call logs |
| `GET` | `/api/crm/intelligence` | Retrieve AI insights |

## List campaigns

Retrieve a filtered list of CRM campaigns.

### Request

<ParamField query="teamId" param-type="string" required="false">
Team ID to query. When omitted, the API uses `auth.accountId`.
</ParamField>

<ParamField query="status" param-type="string" required="false">
Exact campaign status to match.
</ParamField>

<ParamField query="assistantId" param-type="string" required="false">
Return only campaigns assigned to the specified assistant.
</ParamField>

<ParamField query="deleted" param-type="string" required="false" enum="exclude,include,only">
Soft-delete filter. Defaults to `exclude`.
</ParamField>

<ParamField query="contactFilter" param-type="string" required="false" enum="voicemail,awaiting_retry,answered,no_answer,busy,error">
Return campaigns that match a contact outcome filter.
</ParamField>

<ParamField query="includeContactStats" param-type="string" required="false" enum="1,true">
Attach per-campaign voicemail and `awaiting_retry` counts.
</ParamField>

<ParamField query="limit" param-type="integer" required="false">
Maximum number of campaigns to return. Defaults to `50`.
</ParamField>

<ParamField query="offset" param-type="integer" required="false">
Number of campaigns to skip before returning results. Defaults to `0`.
</ParamField>

Returns `true` when the request succeeds.
</ResponseField>

List of campaign objects.

## Create a campaign

Create a new outbound campaign with the assistant, company, and outbound numbers required to place calls.

<Request>
```bash

  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_example_9xmk7q2r_campaigns" \
  -d '{
    "teamId": "team_7f3d2c91-7d6a-45c7-9e6e-2d9b78a41a90",
    "assistantId": "ast_9c41f8e2-7e93-4f8e-8d6c-2c9bdf8b9a33",
    "companyId": "cmpny_3cb8f26a-bfd4-4de1-87af-86f16c07b841",
    "fromNumberIds": [
      "fnum_2f6ea6a0-5d7c-4d37-9b10-d7e4f4c1c102"
    ],
    "name": "Q3 renewal outreach",
    "description": "Priority renewal calls for accounts expiring this quarter",
    "scheduledStartAt": "2026-08-13T16:00:00Z",
    "callWindowStart": "09:00",
    "callWindowEnd": "17:00",
    "callWindowTimezone": "America/Los_Angeles",
```

### Body parameters

</ParamField>

ISO timestamp for a scheduled start. When set, the campaign status becomes `scheduled`.
</ParamField>

<ParamField body="callWindowStart" param-type="string" required="false">

</ParamField>

<ParamField body="callWindowEnd" param-type="string" required="false">
End of the allowed calling window.
</ParamField>

<ParamField body="callWindowTimezone" param-type="string" required="false">

</ParamField>

<ParamField body="maxConcurrentCalls" param-type="number" required="false">

</ParamField>

<ParamField body="maxAttemptsPerContact" param-type="number" required="false">

</ParamField>

<ParamField body="retryDelayMinutes" param-type="number" required="false">

</ParamField>

<ParamField body="settings" param-type="object" required="false">
Additional campaign settings object.
</ParamField>

<ParamField body="noAutoComplete" param-type="boolean" required="false">

<ParamField body="webhookEnabled" param-type="boolean" required="false">

<ParamField body="webhookUrl" param-type="string" required="false">

<ParamField body="webhookSecret" param-type="string" required="false">

## Start or stop a campaign

Start campaign execution with a run request. Use `PATCH /api/crm/campaigns/[id]` when you need to pause or stop a campaign.

<Request>
```bash
curl -X POST "https://app.talkturo.com/api/crm/campaigns/cmp_6df44cc0-5e10-4b0d-a3f5-ec6116f8c7d1/run" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer tk_example_9xmk7q2r_campaigns_run" \
  -d '{
    "accountSlug": "acme-revenue",
    "maxCalls": 10,
    "dryRun": false,
    "noAutoComplete": true
  }'
```
</Request>

<Response>
```json
{
  "success": true,
  "started": 10,
  "failed": 0,
  "calls": [
    {
      "contactId": "cnt_3a6dd2d9-0f7f-4c49-8ca5-9ad4df18ce2b",
      "status": "queued"
    }
  ],
  "errors": [],
  "message": "Campaign run started",
  "dryRun": false,
  "picks": 10
}
```
</Response>

### Path parameters

<ParamField path="id" param-type="string" required="true">
Campaign ID.
</ParamField>

### Body parameters

<ParamField body="accountSlug" param-type="string" required="false">
Account slug to use for the run context.
</ParamField>

<ParamField body="maxCalls" param-type="number" required="false">
Maximum number of calls to start in this run. The endpoint also accepts the alias `max_calls`.
</ParamField>

<ParamField body="dryRun" param-type="boolean" required="false">
Simulate the run without placing calls. The endpoint also accepts the alias `dry_run`.
</ParamField>

<ParamField body="noAutoComplete" param-type="boolean" required="false">
Disable automatic completion behavior for this run. The endpoint also accepts the alias `no_auto_complete`.
</ParamField>

## Common workflow

Most campaign integrations follow the same path:

<Steps>

<Step title="List outbound assistants" icon="users">

Call `GET /api/crm/outbound-assistants` and select the assistant you want to use for outbound calls.

</Step>

<Step title="Create the campaign" icon="plus">

Create a campaign with `POST /api/crm/campaigns` and provide the required `assistantId`, `companyId`, `fromNumberIds`, and `name` fields. A successful response returns `success: true` and a new `campaign.id`.

</Step>

<Step title="Add contacts" icon="upload">

Attach contacts with `POST /api/crm/campaigns/[id]/contacts`. After the request succeeds, the response includes a `contacts` array.

</Step>

<Step title="Start the run" icon="play-circle">

Send `POST /api/crm/campaigns/[id]/run` with any optional run controls you need, such as `maxCalls` or `dryRun`. The response includes `started`, `failed`, and `calls` values for the run.

</Step>

<Step title="Monitor progress" icon="bar-chart">

Poll `GET /api/crm/campaigns/[id]/dashboard` to track `total_calls`, `answered`, `failed`, and `in_progress` while the campaign runs.

</Step>

</Steps>
